# Guard v0.4 — фильтрация native-направлений

Самостоятельный патч от актуального `main`,
база `eecc3b2ff860108fbea6e4d42d59667842a50b31`.
Уже включает библиотеку v0.2 из #5, планы v0.3 из #6 и новую фильтрацию v0.4.
Предварительно интегрировать #5/#6 не требуется; они остаются историей разработки.
Guard v0.1 / PR #2 для переноса не нужен. Изображения/ярлык из #7 независимы.
Основной AIO-сервер и UI по-прежнему не подключают Guard автоматически.
В MAIN, workflows, установщики, Excel и Advanced изменения не вносятся.
Текущие README и лицензионный документ main сохранены; README дополнен только
отдельным разделом о кандидате Guard. Код v0.4 подготовлен и проверен сначала
поверх #6 @595da6eec91ee25e87ec45b61f7a968c969be83a, затем перенесён в этот
самостоятельный патч с побайтовой проверкой совпадения runtime-файлов.

## Задача

«Выбрать всё» в свободном конвертере задаёт произведение числа исходников и
форматов. Наличие DBF в общем каталоге LibreOffice не означает экспорт BMP в DBF:
для графического документа и электронной таблицы доступны разные native-фильтры.
Задача Guard — использовать эти сведения без ручной таблицы разрешённых форматов
и без запрета рабочего файла из-за ошибочного расширения.

Контроль потерь содержимого, полноценный сканер, сравнение оформления, шрифтов
и страниц отложены до завершённого базового конвертера и ADVANCED.
`qualityCompared=False` сохраняется. Успешный native-экспорт не объявляется
доказательством отсутствия потерь.

## Два уровня фильтрации

### 1. Подсказки до загрузки/запуска

`guard.capabilities(files)` / `POST /api/converter-guard/inspect` читают
TypeDetection `Types` и `Filter/Filters` из установленного LibreOffice.
Используются реальные `Extensions`, `IMPORT`, `EXPORT`, `DocumentService`.
Общая таблица GraphicFilter не считается списком экспорта документов.
Учитываются фрагменты, операции replace/remove и флаг NOTINSTALLED.

Для каждого формата возвращаются:

| Поле | Значение для интегрирующего UI |
|---|---|
| compatibleFileIds | По имени исходника найден native-импорт в модель с соответствующим экспортом |
| incompatibleFileIds | Импортные модели исходного расширения не имеют такого экспорта, либо native-тип известен, но экспорта документа нет |
| undeterminedFileIds | Данных недостаточно; не приравнивать к невозможности |
| enabled | Есть совместимый или неопределённый исходник; движок найден |
| compatibility | native_registry_hint: сведения по метаданным, не результат открытия файла |
| reasonCode | NATIVE_ROUTE_REGISTERED / NATIVE_ROUTE_UNAVAILABLE / NATIVE_ROUTE_UNDETERMINED |

Для обычного BMP DBF и DOCX не предлагаются как поддерживаемые направления.
В смешанном наборе BMP + XLSX формат DBF сохраняется для XLSX; его нельзя
отключать для всего набора. При составлении индивидуального `plan` UI использует
ID конкретных файлов, а не размножает каждый формат на весь список.

Подсказка по имени не является окончательным запретом: DOCX может называться
`.bmp`, а обычный текст — иметь неизвестное расширение. UI должен отличать
подсказку от окончательного результата и сохранять явный native-путь для
неопределённых/переименованных файлов. Backend не отвергает такой план по имени.
Нельзя изображать `undetermined` как доказанно поддерживаемый или неподдерживаемый
формат. При неполном реестре все недоказанные выводы остаются неопределёнными.

### 2. Подтверждение модели при выполнении

Первая **выбранная пользователем** конвертация выполняется обычным LibreOffice.
Guard не добавляет скрытый PDF-экспорт, не заставляет LO открывать файл как
Writer/Calc/Draw и не переписывает исходник. Успешный CLI-экспорт сообщает имя
действительно выбранного фильтра. Оно сверяется с тем же установленным реестром,
расширением запрошенного результата и флагом EXPORT.

Подтверждение сохраняется только для этого неизменяемого временного исходника
в текущем задании. Дальше Guard пропускает направления, для которых у определённой
модели нет native-экспорта. Неудача первого экспорта не создаёт подтверждения
модели и не превращается в запрет для остальных файлов или форматов.

Если первым выбран только DBF для BMP, без подтверждения модели backend сделает
одну native-попытку. Обычно UI исключает такую пару на этапе подсказок. Если
сначала выбран PDF, его успешный результат позволяет не запускать последующие
невозможные направления. Очерёдность выбранных направлений не переставляется.

Нет кэша «все BMP плохие», чёрного списка после ошибки документа, OCR, UNO bridge,
нового движка или анализа содержимого. Фильтрация опирается на модель, которую
выбрал LibreOffice, и его экспортные фильтры, а не на жёсткие семейства AIO.

## Неопределённость и защита от ложных запретов

- Реестр отсутствует/повреждён — `registryAvailable=False`, native-попытки сохраняются.
- Неизвестное расширение результата не запрещается автоматически.
- Известный native-тип без document export, например SVM в проверенной сборке,
  отличается от совершенно неизвестного расширения: механизм экспорта отсутствует.
- При нескольких импортных моделях расширения подсказка учитывает их объединение.
- Реестр изменился — меняется fingerprint; старое подтверждение не используется.
- Для shared extension с собственными TypeDetection-фильтрами базовая таблица
  недостаточна: `registryWarning=EXTERNAL_FILTER_REGISTRY`, строгая фильтрация
  отключается. Проверяются XCU в share/extensions и share/uno_packages/cache.
- Если stdout пуст, неоднозначен, усечён или имя фильтра не совпало с реестром,
  подтверждения нет; conversion остаётся native.
- Невозможность создать pipe/поток наблюдения не запрещает конвертацию.

Снимок XCD/XCU не заменяет UNO-конфигурацию во всех нестандартных дистрибутивах.
Сборки с дополнительными скрытыми слоями регистрации требуют отдельной проверки.
Поэтому не обещается квалификация всех версий и расширений LibreOffice.

## Результаты, ошибки и схема v3

При исключении пары:

```json
{
  "format": "dbf",
  "state": "skipped",
  "code": "NATIVE_ROUTE_UNAVAILABLE",
  "stage": "route",
  "libreOfficeStarted": false,
  "error": "Для определённого LibreOffice типа документа нет экспорта в DBF."
}
```

Поле `route` содержит основание: documentService, filter, registryFingerprint,
basis=native_selected_export_filter. Сырые логи и абсолютные пути в API не выдаются.
У исходника `nativeRoute` показывает полученное подтверждение.

Схема job/status, HTTP status и ZIP-отчёта повышена до **3**, поскольку появилось
новое терминальное состояние `skipped`. Существующий host должен явно его обработать.

- `total` — все запрошенные пары; `completed` включает skipped, ошибки и отмену.
- `attempted` — пары, у которых действительно запущен LibreOffice.
- `filtered` — пары skipped; их процент файла не выдаётся за ход native-конвертации.
- Успешные результаты + только skipped дают state=ready. Наличие настоящих ошибок
  даёт partial/failed по прежним правилам. Пропуски не рисуют зелёные галочки.
- skipped не попадают в retry_plan ошибок и не запускаются снова автоматически.
- После подтверждённого сохранения успешные файлы получают saved, skipped сохраняются.
- В ZIP включается отчёт с объяснениями; отдельные outputs остаются доступны.
- Revision/ETag v0.3 учитывают новые изменения. Неизменный status остаётся кратким.

Для вкладки «Ошибки»/«Проблемы» используйте code, error, stage и факт запуска LO.
Пропущенное неподдерживаемое направление следует показать как объяснение
недоступности, отдельно от повреждённого исходника или сбоя движка. Скрытые потери
текста/таблиц/изображений этот патч не выявляет и не имитирует их диагностику.

## Расход ресурсов

Реестр кэшируется, максимум два снимка. Ключ включает путь установки и метаданные
конфигурационных файлов. Проверка каталога не запускает LibreOffice, не открывает
документы, не извлекает текст и не создаёт фоновых потоков.

Только пока для данного исходника нет подтверждения, native stdout дренируется
короткоживущим потоком. В памяти остаётся максимум 64 КиБ; избыток отбрасывается,
а не записывается на диск. Поток не удерживается после завершения конвертации.
После подтверждения следующие экспорты не требуют наблюдения stdout.
Ресурсы процесса и отмена остаются у прежнего ProcessTree.

Прямой адаптер вне Guard сохраняет поведение: новый необязательный аргумент stdout
по умолчанию не включает захват. Параметры native-экспорта, исходные байты и
кодирование результатов не меняются. Новых лимитов размера/страниц/числа файлов
или времени по умолчанию нет. QA использует свой явный deadline 15 с на попытку.

100 прогретых инспекций трёх файлов/87 форматов: 0.6073 с суммарно, 6.073 мс в
среднем, traced peak Python 160717 байт, 0 потоков наблюдения. Это локальное
измерение метаданных с tracemalloc, не RAM LibreOffice и не общий benchmark AIO.

вывода Guard сохраняет неопределённость, а не блокирует документы.

## Основание реализации

- [LibreOffice FilterFactory](https://api.libreoffice.org/docs/idl/ref/servicecom_1_1sun_1_1star_1_1document_1_1FilterFactory.html):
  Type, Flags и DocumentService принадлежат конфигурации самого движка.
- [Native CLI dispatchwatcher.cxx](https://github.com/LibreOffice/core/blob/master/desktop/source/app/dispatchwatcher.cxx):
  штатный поиск экспорта использует документную модель и сообщает выбранный фильтр.
- [TypeDetection](https://api.libreoffice.org/docs/idl/ref/servicecom_1_1sun_1_1star_1_1document_1_1TypeDetection.html):
  определение типа может требовать содержимого; одно расширение не доказывает тип.

Финальные решения дополнительно проверены на установленном движке, а не только
выведены из документации. Остались ограничения прежнего Guard: crash recovery,
полноценная ОС-песочница и сканер качества не реализованы.
