## Исправленные блокеры

1. **Готовый результат не принимался интерфейсом.** Core возвращал
   `downloadUrl`, а новый bridge требовал отдельный `ticket`. Теперь оба поля
   описывают один действительный результат; скачивание не подтверждает сохранение.
2. **Широкий выбор терял рабочие направления.** При выборе более четырёх
   форматов bridge удалял пары по расширению исходника. Теперь передаёт весь
   пользовательский выбор, в исходной очередности. Guard пропускает невозможные
   пары после подтверждения модели настоящим LibreOffice. Их причины остаются
   в статусе и в JSON-отчёте архива.
3. **Неизвестные исходники блокировались сохранённым UI.** `enabled=true`
   недостаточно: старый контроллер дополнительно требовал `compatibleFileIds`.
   Добавлен отдельный контракт выбора, подсказки по имени сохранены для «Проблем».
4. **Ошибка упаковки делала несколько готовых файлов недоступными.** До
   завершённого ZIP Guard теперь хранит настоящую ссылку на первый результат.
   При `packagingError` bridge предлагает готовые копии по отдельности и
   подтверждает каждую только после сохранения. Отмена диалога сохраняет задание;
   повтор продолжает с ещё не подтверждённых копий. Задание освобождается после
   подтверждения всех копий либо явного изменения выбора/сброса.
5. Отмена после уже завершённого файла теперь дожидается завершения Guard и
   позволяет сохранить готовую часть. Запоздавшее создание задания после Reset,
   оборванная загрузка и задание без результатов освобождают временное хранилище.

## Контракт выбора и отчёта

Схема остаётся v3; новые поля добавлены без удаления старых.

| Поле `/inspect`, на уровне формата | Назначение |
| --- | --- |
| `enabled`, `compatibleFileIds`, `incompatibleFileIds`, `undeterminedFileIds` | Прежняя предварительная подсказка по имени; не доказательство содержимого |
| `nativeAttemptAvailable` | Найден движок, можно запросить native-попытку |
| `selectableFileIds` | Исходники, которые UI вправе включить в план, включая переименованные и неизвестные |

Контроллер использует `selectableFileIds` для выбора и запуска. У прямого
адаптера без новых полей сохраняется прежний контракт `compatibleFileIds`.
Вызов `/jobs` не делает повторного `/inspect` и не фильтрует выбранные пары в JS.
Только backend принимает решение `skipped`; ручной таблицы семейств нет.

Статус задания и `AIO-conversion-report.json` теперь одинаково считают:

```text
total = succeeded + failed + cancelled + filtered + pending
completed = total - pending
```

`attempted` — число направлений, в которых действительно запускался LO;
это отдельная метрика, поскольку запуск может завершиться ошибкой.
`filtered` — доказанные пропуски, а не ошибки процесса и не успешные результаты.
«Итоги» показывают эти числа отдельно. Пропуски не превращают успешно
обработанный файл в красную ошибку. Снято старое ограничение прогресс-виджета
на 100 файлов; отменённые строки корректно переживают сохранение готовых файлов.

Первая выбранная операция не переставляется и не заменяется скрытой пробой.
Поэтому один BMP → DBF до определения модели ещё требует native-попытки.
У повреждённого файла без успешного экспорта модель может остаться неизвестной:
ошибка одного направления не считается доказательством запрета остальных.

## Нагрузка

- Поллинг использует ETag/revision, уже поддержанные Guard. На `304` не
  собирается полный снимок, не читается JSON и не перерисовывается матрица UI.
- На прогрессе обрабатываются только новые состояния; повторный inspect при
  запуске удалён. Подсчёты статуса сведены в один проход по задачам.
- Открытие оболочки по-прежнему не создаёт задания, spool или worker-поток.
  Нет анализа содержимого, дополнительных движков и сканирования качества.
- Проверка на 100 исходниках × 87 форматах: полный статус с JSON — 1 432 507
  байт; неизменённая ревизия не требует этого ответа. Замеры Python с
  tracemalloc приведены в JSON ниже; это измерение метаданных, **не** скорость
  конвертации и **не** память LibreOffice.
