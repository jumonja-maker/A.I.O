## Первопричины и исправления

1. **M02: занятый каталог становился невидимым до перезапуска.** Неудачный owner-lock ранее просто пропускался, а поиск объявлялся загруженным. Теперь busy/access/read failure сохраняют конкретную причину и доступную ручную повторную попытку. Остальные каталоги восстанавливаются независимо; snapshot-поллинг не обращается к старому диску. `scandir` сообщает отказ доступа к самому хранилищу вместо ложного пустого результата. Учёт спасённого каталога включает все принадлежащие байты, включая оставшиеся исходники/метаданные; квота не освобождается при неудавшейся очистке. Существующие single-flight, аренды, лимит заданий, отложенная очистка и остановка при shutdown сохранены. Старый saved-record без independent readback не даёт права на автоматическую очистку: файл восстанавливается как несохранённый с RECOVERY_SAVE_UNVERIFIED; отдельная регрессия проверяет сохранность единственной копии.
2. **M02/M30: спасение неизвестного файла трактовалось как успешная конвертация.** Salvage-файлы доступны для сохранения в `recovered/...`, но задача имеет `error / RECOVERED_UNVERIFIED`. Сохранение байтов не меняет ошибку конвертации на успех; исходный каталог остаётся до явного удаления.
3. **M03: поздний async-ответ мог менять повторно открытое окно.** Смена поколения окна отсекает старые результаты действий/preview/snapshot; фактическая операция продолжает безопасно выполняться. Состояния поиска/ожидания доступа/очистки различимы, отмена удаления сохраняет статус. Длинные кнопки и поля переносятся в доступную ширину, диалог ограничен viewport, минимальный размер Qt-окна больше не принудительно равен 900×650 и учитывает доступный экран.
4. **M30: `/saved` доверял самому подтверждению клиента.** Теперь необходима серверная квитанция независимого чтения конечного файла. ZIP из spool или начало скачивания её не создают; неправильный saveId отклоняется. Ошибка/отмена новой проверки отзывает ещё не использованную квитанцию. Браузер без подтверждения показывает ограниченный статус и сохраняет исходные результаты.
5. **M30: явный ZIP для единственного результата возвращал исходный PDF вместо архива.** Явный запрос теперь действительно собирает ZIP, обычный single-output путь остаётся без дополнительной упаковки.
6. **M30: внешний ZIP ранее проверялся только целым SHA.** Теперь конечный путь заново проверяется существующим строгим потоковым ZIP-верификатором: точный набор без дубликатов, структура/ZIP64, CRC каждого члена, размеры, SHA-256 каждого результата и всех трёх metadata-файлов, стабильность файлового дескриптора/пути, затем SHA всего контейнера. Ожидания берутся из замороженного снимка упаковки, а не из проверяемого архива. Проверка выполняется под save/I/O-арендой, вне глобального lock; обычный preflight/конвертация дополнительного чтения не получили.

## Контракт ZIP и метаданных

- `AIO-conversion-report.json`, `AIO-results-manifest.json`, встроенный `AIO-save-status.json` описывают один immutable `archiveSnapshot` / `snapshotId` / revision. Встроенный статус честно равен `packaged`, `externalSave=not_observed`, а ошибки конвертации сохраняются.
- Нельзя встроить доказательство будущего чтения конечной копии в уже проверенный неизменяемый архив. Поэтому финальный authority — соседний файл **`<имя ZIP>.AIO-save-status.json`**. Он связывает уникальный внешний `saveId`, тот же `archiveSnapshot`, проверенный размер/SHA конечного ZIP и результаты проверки членов. `state=completed` появляется только после чтения конечного ZIP; сама квитанция также записывается с fsync и независимо читается. Ошибка её записи/проверки не подтверждает сохранение результатов.
- Это раздельные области доказательства, а не подмена статуса: встроенная упаковка никогда не называется внешним сохранением. Квитанция фиксирует наблюдение в момент проверки, не обещает вечной неизменности внешнего носителя и не сертифицирует качество конвертации.
- Согласованный folder-save snapshot/report/manifest/status и его независимый SHA-путь сохранены. Старые тесты подтверждения усилены реальным копированием и чтением внешнего файла перед `/saved`; отрицательный HTTP-тест подтверждает отказ без доказательства.
