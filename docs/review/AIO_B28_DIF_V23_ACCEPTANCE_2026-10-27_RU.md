# 00AIO / B28 — итог независимой Windows-приёмки Guard v23

**Решение:** целевой патч DIF принят по результатам NIKITA; разрешена только интеграция в рабочую QA-ветку, не в `main` и не в публичный релиз.

Исходная QA-база: `b47578a6a401fef2ae20499748926b7ce7977a6e`.

## Фактическая проверка

- [Windows NIKITA #40509991660](https://github.com/jumonja-maker/A.I.O/actions/runs/40509991660): **SUCCESS**.
- Новая точная матрица: **48/48 PASS** (32 исторически проблемных направления DIF → HTML/XHTML/XLSM/XLTX, уровни 1–8; 8 прямых CLI-контролей уровней 1 и 8; 8 положительных XLSX-контролей через UNO). Все исходные SHA совпадают с сохранённым корпусом.
- Независимые считыватели openpyxl и HTML проверили реальные непустые ячейки, строковые ID `001`, последнюю строку, тексты и числовые значения.
- Полная Windows исходная/Qt/DOM-регрессия: **1128 обнаружено; 1118 PASS; 10 Windows platform N/A; 0 FAIL/ERROR**.
- Отдельные нативные проверки Writer TXT v22, форматов v20, XLSX v21, очереди/save/CSV→DBF завершились PASS.
- Нативная базовая контрольная попытка до исправления: 8 из 8 L1/L8 преобразований были способны выдавать повреждённое содержимое; это выявила независимая последующая проверка, не прежний обязательный барьер Guard.
- Точная исходная причиной конкретного внутреннего дефекта LibreOffice не объявляется.

Машинные подтверждения: `docs/review/evidence/b28/acceptance.json`,
`windows-b28-native.json`, `windows-b28-baseline.json`, `windows-unit.json`, `source-seal.json`.
Набор `source-seal.json` фиксирует SHA-256 проверенных файлов до добавления **этого** итогового документа; повторное редактирование исходного технического отчёта не делалось.

## Исправленные технические границы

1. Защита DIF выполняется в реальной CLI-развилке, включая случаи живой UNO-сессии с неоднозначным экспортным рецептом.
2. При необходимости CLI получает нативный промежуточный FODS-снимок с проверенными значениями и отдельным профилем импорта; обычные успешные UNO-маршруты остаются прежними.
3. Проверка выходного файла теперь охватывает поддержанные ячейки с координатами, типами и значениями даже при `qualityCheckRequested=false`. Доказанное усечение становится `ENGINE_OUTPUT_CONTENT_LOSS`, а не `ready`.
4. Windows LibreOffice 26.8.1.1 может кодировать число `1.43` атрибутом HTML `sdval="1,43"` при `sdnum="1049;"`. Контракт распознаёт именно подтверждённую русскую десятичную локаль; неподтверждённые варианты дают `not_checked`, а изменённое число по-прежнему является потерей.
5. Бюджеты и неполная грамматика не приравниваются к повреждению: возвращают явную неполную проверку.

## Остаточные ограничения

Это проверка **подмножества содержимого DIF**, а не всех визуальных эффектов, формул, шрифтов, макросов и внешних объектов. Полный пользовательский FULLTEST на объединённом Guard v23 и новая Windows EXE-приёмка не проводились. Исторические результаты не изменялись и не удалялись. Другие пункты мешка (B29/B30 и UI/ADVANCED) не входят в этот патч.
