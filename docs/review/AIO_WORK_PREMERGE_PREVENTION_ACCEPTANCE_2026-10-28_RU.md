## Что поставляется в PR #78

Только продуктовые файлы WORK #67–#72/#75, повторяемые native QA/test scripts #73, отдельные A01/A02/A03/A04/A05/A06/A07/A09 защитные корректировки и тесты. **НЕ** входит тестовый гигантский PR #74 с историческими evidence и одноразовые composer/publication workflows.

1. A01: при режиме fit каждое изображение вписывается отдельно; синхронизация прокрутки не делает маленький исходник 140×105 крошечным из-за результата 3840×2160. Exact 100% сохраняет реальные пиксели.
2. A02/A05: безусловное закрытие запрещено для выполняющегося задания с нулём результатов и для сессии с повреждённым журналом восстановления даже после сохранения известных файлов. Только явное «Да» уничтожает собственные временные данные.
3. A03: «мусорка» в обработке или preflight возвращает INPUT_CLEAR_BUSY и не скрытно отменяет весь пакет.
4. A06: по умолчанию «Проблемные» показывает подтверждённые потери/ограничения и реальные ошибки конвертации; `uncertain`/`not_checked` доступны отдельными фильтрами, не выдаются за подтверждённое повреждение.
5. A07: метаданные `supportingFile` и отдельные счётчики манифестов `AIO-sheets.json`, одновременно сохраняя обязательные несохранённые артефакты в полном учёте. Никаких автоматических фальшивых подтверждений.
6. A09: длинные и Unicode имена книг не переполняют имена промежуточных FODS, оригинальное имя и bytes не меняются.
7. A04: отчёт stress3 не записывает `actualDecision = expectedDecision`, если сырой статус не известен.
8. **Дополнительно найденный реальный дефект стыковки:** в главном `index.html` отсутствовало подключение `src/guard-comparison-viewer.js`. В PR вставлено строго перед `src/guard-comparison.js`, тест проверяет реальное подключение в QtWebEngine.

## Честные остаточные ограничения

- Отдельный сценарий сырого скачивания отвергнутого/частичного файла из карантина не реализован: по умолчанию quarantined bytes не являются готовым пользовательским output.
- ORP без genuine Base ReportDefinition положительного файла не считается проверенным.
- Нет пользовательской EXE/GUI/real-GPU приёмки, исходного 680-файлового FULLTEST, прежних 186 пар анализа и независимой массовой статистики ложных решений.
- Скоростные проблемы A10 отдельно отложены.
- Hosted Linux workflows для старых проверок имеют статус failure без доступного детального лога/тестовых шагов; эта приёмка опирается на полный self-hosted Windows NIKITA набор выше, не выдаёт hosted failure за PASS.

**Политика релиза:** интеграция только в рабочую QA-ветку PR #56 после точной проверки источника и отсутствия сторонних изменений; не в main. Новая Windows EXE должна затем пройти самостоятельную пользовательскую приёмку.
