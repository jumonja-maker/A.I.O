## Результат

Патч устраняет подтверждённый механизм ложного успеха при пустом HTML,
уточняет выбор установленных фильтров LibreOffice, разделяет тайм-ауты стадий,
добавляет явную загрузку зависимостей HTML и необязательную проверку
сохранённых байтов. Включены исправления окна «Состояние», регрессии и QA-инструменты.

**Это не закрытие всех ошибок FULLTEST.** Нативный прогон: 129 задач,
126 успешных и 3 управляемых тайм-аута ODC. Все 126 сохранённых файлов
перечитаны и сверены по SHA-256. Windows/Qt/EXE и вся матрица 7 326
направлений здесь не проверялись. Новый движок, рендерер, Advanced и
сканер сравнения до/после не добавлены. Исправления v14 сохранены.

## 2. Ящик A — пустой HTML

На установленном здесь LibreOffice обычный CLI BMP → HTML воспроизвёл
оболочку 432 байта без изображения, с пустым h1. Размер отличается от
исторических 429 байт: проверка не привязана к длине.

Реальный реестр одновременно предлагает Draw-фильтры draw_html_Export
и XHTML Draw File. Старый обход требовал сначала однозначно выбрать
первый фильтр, поэтому при реальной неоднозначности не включался.
Теперь подтверждённая одностраничная native-модель Draw использует
именно установленный XHTML Draw File. Для нескольких/неизвестного
числа страниц обход не применяется.

Guard после CLI и UNO проверяет тело основного HTML:
заголовок, пустой h1, пробелы, стили и скрипты не означают содержимое.
Пустой результат получает ENGINE_OUTPUT_CONTENT_EMPTY, не ready.
Текст/графика подтверждают только наличие содержимого. Лимит инспекции,
кодировка и динамический контент дают not_checked с предупреждением.

Инспекция читает максимум 1 МиБ, ограничивает буфер незавершённого тега,
поддерживает отмену и работает в конвертерном потоке.
Она консервативна: намеренно пустой исходник тоже может получить ошибку
пустого HTML. Отличить его от потерь должен будущий сканер.

Нативно 63/63 допущенных графических исходника дали HTML с графикой.
Три APNG не получили подтверждения импорта в этой Linux-установке;
глобального запрета APNG нет. Независимо разобраны 51 растровое
вложение и 12 SVG; в 33 случаях payload побайтно совпал именно со своим
исходником. Это не сертификат анимации, пиксельной точности или верстки.

## 3. Ящик B — фильтры и скорость

Выбор учитывает основной суффикс native-типа, уникальный DEFAULT,
PreferredFilter и стандартные установленные варианты OOXML.
Случайный первый элемент множества не выбирается.
Неизвестный реестр/внешние overlays сохраняют неопределённость.
Наблюдавшийся импортирующий фильтр сохраняется при экспорте в его
основной формат.

| Направление | Изменение и граница |
|---|---|
| Writer → CSV/TAB/TSV/TXT | Text (encoded):UTF8. Обычный текст, не восстановленная таблица Calc; предупреждение о потерях структуры. |
| Calc → CSV/TAB/TSV | Сохранены отдельные параметры диалекта; импорт не подменяет экспорт. |
| Writer/Web → графика | Writer-экспорт при доказанном XTextDocument; суффикс HTML ничего не доказывает. |
| DBF/DIF | Нативные параметры UTF-8 и подсказки по содержимому. Неизвестная кодировка DBF не угадывается; запрос на потери не подтверждается автоматически. |
| Writer/Calc → SVG | Текущий filterWriterOrCalc требует SelectionOnly. Полный документ этим маршрутом недоступен с причиной NATIVE_SVG_SELECTION_ONLY. Draw/Impress SVG не отключён. |
| OOXML | Установленный стандартный фильтр вместо неопределённого CLI fallback. Сложное оформление требует проверки против прямого LibreOffice. |

Нативно: 36/36 задач CSV/DBF/DIF → ODS/XLSX/DBF/DIF;
12/12 ODT → CSV/TAB/TSV/EPUB; 15/15 автономных HTML/HTM/XHTML → DOCX/PNG/HTM.
Это не доказательство исправления всех старых 397 отказов.

В старом отчёте CLI выполнял 1 383 задачи (18,9%), но занял около 73%
суммы длительностей задач: ready — 5 778 215 мс, ошибки — 890 999 мс,
отмены — 679 407 мс. Это сумма измерений операций, не отдельный замер сеанса.

Новые рецепты дают существующему Windows UNO worker однозначный фильтр:
часть повторных запусков CLI становится не нужна.
executionReason отличает неразрешённый фильтр от недоступной UNO-сессии.
**Windows-ускорение не измерено.** Linux Calc CLI остаётся медленным:
36 задач заняли 365,452 с. Обещания «1000 файлов за N минут» нет.

## 4. Ящик C — стадии и ODC

UNO-протокол различает import/export/close.
По умолчанию импорт ограничен 60 с, закрытие — 15 с; общий дедлайн
пары остаётся настраиваемым. Повтор stage-сообщения не продлевает
время; чужой task ID и неверная последовательность отвергаются.
Измеренный медленный preflight-импорт может увеличить бюджет.

Подтверждённая native-модель Chart имеет отдельный бюджет 60 с,
включая CLI. Это политика Guard, не запрет ODC. Явный повтор с
увеличенным временем повышает этот бюджет.

Тайм-аут экспорта/закрытия больше не объявляет остальные форматы того
же исходника невозможными. Ошибка открытия/тайм-аут импорта может
отложить остальные направления этого исходника; следующий продолжает очередь.

Worker передаёт положительное подтверждение storeToURL до close.
При зависшем закрытии результат возвращается только после завершения
собственного процесса и проверки выходных путей. Предварительный файл
без положительного commit-сообщения готовым не считается.

Три ODC → ODC завершились тайм-аутами примерно по 20 с — явный QA-бюджет.
Вечного ожидания нет, но **успешный экспорт ODC не доказан**.
Standalone/embedded ODC и нативную причину зависания нужно проверить на Windows.

## 5. Ящик D — исходники без задач и HTML-ресурсы

inputsUploaded/inputsPlanned/inputsWithoutTasks сохраняют невыбранные
исходники и preflight-коды в отчёте и журнале восстановления.
Удаление из активного плана больше не стирает след диагностики.

Пользователь явно выбирает исходник HTML и папку с ним и ресурсами.
Основной HTML не становится ресурсом/второй карточкой.
Форматы автоматически не выбираются, экспорт не запускается.

Ресурсы принадлежат одному исходнику в приватной папке его задания.
API /resources и /resource использует тот же loopback/token-контракт,
потоки, квоту, отмену и I/O leases. Проверяются относительные пути,
NFC/регистровые коллизии, конфликт файл/папка, замена исходника и
Windows-несовместимые имена.

CSS/SVG/вложенный HTML проверяются относительно своего файла.
Выход за приватный корень и ссылки/reparse points не допускаются.
Буферы, число анализируемых зависимостей и очередь ссылок ограничены;
повтор одного URL не наращивает очередь. Старый постоянный порог
32 МиБ для анализа HTML удалён: чтение потоковое. Неопределённость
синтаксиса/времени видна явно; повтор дольше увеличивает бюджет.

Четыре HTML/HTM FULLTEST всё ещё ссылаются на отсутствующие PNG.
Патч не восстанавливает потерянные картинки. Новый DOM/HTTP-сценарий
подтвердил папку ресурсов, повтор проверки, одну карточку, один upload
исходника и отсутствие автозапуска/автовыбора.

Три EPUB этот LibreOffice не импортировал. Другой импортёр/движок
не добавлялся. Неподтверждённый импорт нельзя считать поддержкой EPUB-входа.
ODT → EPUB при этом прошёл 3/3.

## 6. Ящик E — сохранение, память, интерфейс

В «Состоянии» есть отключённая по умолчанию проверка сохранённых файлов.
При включении папка перечитывается целиком по манифесту до host ACK.
Ошибка, отмена и повреждение того же размера оставляют результаты
несохранёнными в Guard. Для ZIP/одиночной загрузки сравниваются все
байты скачанного файла с удерживаемым результатом.

Хеширование/копирование работают в фоновых host-потоках; Qt получает
сигналы. Копирование и readback имеют разные надписи, число файлов
не удваивается. При выключенной проверке второго чтения нет.
SHA-256 вычисляется во время существующего копирования.
ZIP содержит AIO-results-manifest.json; outputs и метаданные используют ZIP64.

Readback подтверждает байты, не качество конвертации.
Браузер без native host не получает ложного readback-подтверждения.
tools/qa/verify_saved_results.py проверяет папку/ZIP независимо от UI,
не меняя отчёты или saved-состояние.

Окно «Состояние»: крестик, Escape, клик по фону; перенос указателя
изнутри на фон окно не закрывает. Закрытие не отменяет очередь.
Исправлено всплытие событий проверки/сохранения до контроллера.
Загрузка ресурсов и повтор проверки сохраняют открытый диалог.
help теперь имеет ожидаемый UI массив из трёх записей.

Новые правила находятся в Guard и конвертерном UI.
libreoffice_engine.py, Excel, зависимости, бренд, установщик и workflows
не менялись. Новые проверки не запускаются при импорте или работе Excel.
File-ссылки ресурсов находятся в WeakMap; документы/ZIP/результаты
не копируются целиком в память.

Синтетическая очередь 1000 файлов: 1000 успехов, Python tracemalloc peak 11,11 МиБ.
UI 1000 файлов/83 000 задач: 50 DOM-строк, 100 обновлений часов за 7,31 мс,
без полного обхода задач/клонирования прогресса/forced layout.
Это не замер LibreOffice/Qt RSS и не 1000 реальных конвертаций.
Старый пик BLACK.BOX 2 468,96 МиБ по дереву процессов не доказывает утечку:
многочасовой Windows-тест обязателен.
