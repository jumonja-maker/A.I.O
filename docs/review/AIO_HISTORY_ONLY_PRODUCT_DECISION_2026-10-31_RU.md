# 00AIO — «Только журнал»: отключение автоматического legacy Recovery

Дата 31.10.2026. База QA `548e3775418f7f254cf352e9428c5bdacdb4692e`, PR #83. Повод: уточнение владельца проекта — *сохранять журнал прошлых конвертаций, а не старые файлы результата*; ранее в UI наблюдалось ложное «несохранённых результатов 3» при давно удалённых файлах.

## Подтверждённые факты
- M04 уже хранит отдельно SQLite отчёты без документов, ticket или auto-recovery: `docs/review/AIO_HISTORY_M04_2026-10-30_RU.md`.
- После PR #95/#96 штатный `start_server` автоматически выбирал `data_directory()/legacy-jobs` (либо sibling от Guard), даже если пользователь НЕ просил восстановление. `index.html` и `src/guard-queue.js` постоянно подключали Legacy Recovery UI.
- Guard M02 является **другим** механизмом: обычный снимок `recoverable(scan=False)` не сканирует старый диск; раздел «Найти предыдущие результаты» ручной; состояние recovered=true уже исключено из показателя `текущих несохранённых`. Не утверждать, что новая A06 была первопричиной старого симптома — пока нет такого доказательства.

## Минимальный безопасный продуктовый патч
1. Штатный desktop-сервер больше не вычисляет/не сканирует `legacy-jobs` автоматически; `ConverterTransport` использует временное сессионное хранилище, как до #95, с сохранением остальных валидаций и лимитов. Явный `legacy_recovery_parent` остаётся как изолированное opt-in для регрессий/миграции.
2. Удалить подключение `src/legacy-recovery.js` и монтаж его UI в обычном интерфейсе. Модуль остаётся в истории исходников, но не загружается пользовательским приложением.
3. Журнал M04, текущая конвертация Guard и выборочное сохранение M30 не меняются. Existing on-disk results **НЕ удаляются**, данные остаются доступными для отдельной безопасной ручной миграции по решению владельца.

## Приёмка
- Нулевой auto-scan, auto-import и legacy quota current count из старых файлов при первом запуске, даже если под `legacy-jobs` существует каталог.
- `История завершённых конвертаций` остаётся; `Результаты прежнего конвертера` не появляются.
- Никаких файловых удалений, GitHub MAIN/Release/installer и изменений M02 Recovery без дополнительного решения владельца.
- Полный Windows/Linux CI/строгий gate на точном source SHA; без PASS не сливать QA.

## Открытый вопрос M02
Нужно ли также убрать *ручной* пункт «Найти предыдущие результаты» и хранение аварийных результатов Guard между запусками? Он не равен автоматическому A06. Решение перед деструктивной миграцией должен подтвердить владелец проекта.
