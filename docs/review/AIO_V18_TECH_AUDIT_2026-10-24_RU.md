# A.I.O — технический осмотр и патч v18

Дата задания: 24.10.2026. Репозиторий: `jumonja-maker/A.I.O`.

## База и область ответственности

Патч подготовлен отдельно поверх рабочей QA-ветки
`feature/blackbox-deep-telemetry-v01-20261021`, точный исходный коммит
`a6b0861be1c5f9b67130627527dfbafe64fbd0f3`, дерево
`7594781ac9c0b9b3e94ceed36229fe256bb4bccc`. В эту базу уже интегрирован PR #40
с Guard v17. Исправления v14–v17 не выдаются за новую работу.

Цель: убрать доказанные лишние вычисления и удержание объектов, исправить
подтверждённые ошибки результата, восстановления, сохранения и отмены.
Новые движки, Advanced и собственный рендер не добавлены. Фильтры LibreOffice,
параметры сжатия/качества экспорта и правила допуска native-пар не ослаблены.
`main`, установщик, workflow, релизы и пользовательские результаты не изменены.

Это осмотр исходников всего приложения с целевыми исправлениями и локальными
испытаниями. Он не доказывает отсутствие любых ошибок, утечек или визуальных
потерь во всех форматах. Windows/NIKITA и повторный FULLTEST-510 входят в
последующую приёмку, а не в заявленные здесь результаты.

### Согласование протокола состояния

Старые клиенты по-прежнему получают полные `result.outputs`. Новый JS явно
запрашивает delta и обновляет outputs по стабильному ticket, включая `saved`.
Full snapshot, разрыв revision и начальное появление результата имеют полный
resync. Барьеры results_available/job_failed не позволяют потерять уже готовые
outputs при переходе от `result=null`. Дополнительные изображения/ресурсы одного
target остаются в inventory. PartialResult остаётся отдельным anchor descriptor.

Это оптимизация передачи и построения состояния. Она не меняет порядок задач,
разрешённые форматы, количество успешных native exports или байты результата.

### Что именно кэшируется

Кэш подготовки принадлежит одному batch, хранит одну текущую private import copy,
проверяет путь, device/inode, размер, mtime/ctime исходника и копии. Исходные ZIP
members проверены на равенство подготовленным версиям до/после оптимизации.
При временной блокировке старой private copy ОС её удаление откладывается до
cleanup batch workspace: она больше не используется и не мешает следующему
файлу. Пользовательские результаты этим cleanup не затрагиваются.
Живая изменяемая модель LibreOffice между target не переиспользуется: это могло
бы переносить состояние фильтра/страницы/стили на другой экспорт.

SourceEvidence хранит только ограниченные сведения существующих инспекторов
ODF table text/media profile. При смене файла или stat он очищается, изменение
во время чтения делает подтверждение невозможным. Кэш не является постоянным
доказательством совместимости и не заменяет независимую проверку каждого output.
Криптографическую защиту от противника, способного незаметно менять внутренний
private spool с сохранением всех identity-полей, этот кэш не обещает.

### Сохранение и переносимость

Обязательный readback сохранённых байтов и сохранность оригиналов Guard не
ослаблены. Файл, появившийся в целевой папке между проверкой и публикацией,
не заменяется. Если hard links не поддерживаются, используется exclusive copy
с fsync, а затем штатный независимый SHA-256 readback. При ошибке/отмене fallback
частичный файл может остаться в папке неудачного сохранения; Guard не объявляет
его сохранённым, не удаляет потенциально заменённый чужой файл и сохраняет свои
исходные результаты для повторения операции. Это намеренный выбор сохранности.

## Скорость и память: что измерено

Локальные измерения Linux/Python 3.12; абсолютные значения зависят от машины и
параллельной нагрузки. Tracemalloc измеряет Python allocations выбранного
участка, а не общий RSS процессов LibreOffice/Qt.

Status benchmark сравнивает legacy полную и negotiated выдачу на одном текущем
job и одном коде. Время отдельного checkout v17 этим замером не измеряется.
Столбцы «Было/Стало» для этой строки обозначают два протокольных режима.

## Почему полная конвертация всё ещё может быть медленной

1. На Linux экспорты используют существующий CLI-путь; startup/загрузка документа
   могут стоить существенно дороже этих metadata-проверок. Windows применяет
   существующий private UNO session, но модель открывается отдельно для target.
   Перенос результата замера Linux на Windows был бы неверен.
2. Сложный layout, формулы, шрифты, векторная графика и несколько страниц требуют
   работы самого LibreOffice. Удаление страниц/кадров/проверок ускорило бы процесс
   ценой содержимого; этот патч так не делает.
3. Multi-sheet legacy exports выполняют отдельные нативные операции для листов,
   создают companions/typed recovery там, где формат не способен вместить всё в
   один файл. В реальном локальном испытании именно DBF/DIF занимали заметную
   часть очереди даже при небольшом числе исходников.
4. ZIP, запись на медленный/сетевой диск и независимое хеширование требуют I/O.
   Потоковая запись и более лёгкий опрос уменьшают сопутствующую нагрузку,
   обязательное подтверждение байтов сохранено.

Нового универсального процента ускорения всей конвертации здесь нет. Для него
нужен A/B прогон одной фиксированной матрицы на одной машине, с одинаковым LO,
файлами, шрифтами, target filters, cold/warm режимом и независимыми проверками
содержимого. Без этих условий обещать «в несколько раз быстрее» нельзя.

## Достоверность качества и оставшиеся риски

- Checked subset контейнера не равен декодированию всех пикселей. Проверка EOI,
  размеров и пиксельных границ отсекает конкретные усечения, но не доказывает
  визуальную идентичность каждой страницы/изображения. `qualityCompared=false`
  не заменено ложным обещанием полного контроля.
- Native preflight доказывает модель/зарегистрированный маршрут установленного
  LO; он не гарантирует удачный экспорт любого повреждённого или сложного
  исходника. Причина конкретного отказа остаётся task-local и не превращается
  в глобальный blacklist расширения.
- PDF/fonts/layout, формулы и типизация таблиц требуют профильной проверки.
  Готовность пакета тестов не заменяет пользовательскую визуальную приёмку.
- Для новых файловых и QObject изменений нужны реальные Windows QtWebEngine,
  переносимые носители и отмена/закрытие приложения во время длинной очереди.
- Длительный RSS/handle soak, disk-full, принудительное завершение на разных
  стадиях и повторная полная матрица 510 исходников здесь не заявляются.
- Наблюдение о системном буфере обмена Windows (issue #27) в Linux не
  воспроизводилось; причину и исправление этого наблюдения патч не заявляет.
- Потери, присущие выбранному target (например анимация → статический формат),
  нельзя превратить в lossless преобразование оптимизацией оболочки. Программа
  должна сохранять объяснение/companion или честно отклонять неполный результат.

## Приёмка и повторение

Финальная локальная регрессия после заморозки программных файлов:
**635 tests, 635 PASS, 0 SKIP, 0 FAIL/ERROR, 52,012 с**. Сюда входят 53 новых
регрессии, исходные Excel/HTTP/JS/Qt контракты, проверка очереди на 1000 файлов,
DOM на 83000 задач, fault injection сохранения/очистки и проверки метрик.
Компиляция Python, разбор JavaScript и `git diff --check` также прошли.

Реальный Linux subset: 8 исходников, 21 выполненный export — 21 PASS; проверены
текст/порядок EPUB, кадры анимации, EMZ/WMZ, таблицы и повторно прочитанные
сохранённые байты. Запрошенный PNG→SVM не предоставляется Linux native-маршрутом
этого движка и отмечен platform_not_applicable; требуется Windows UNO-проверка.
Исходные файлы остались неизменными. Это не повтор полного FULLTEST-510.

Точные результаты финального набора и реального native subset приведены в
соседнем JSON evidence. Первичный неполный native прогон без corpus не считается
полной приёмкой: его 9 exports прошли, но harness корректно оставил INCOMPLETE
из-за отсутствующих исходных образцов. После предоставления corpus выполняется
отдельный полный целевой subset, а не подмена статуса первого прогона.

Пример запуска в собственной подготовленной среде:

```bash
QT_QPA_PLATFORM=offscreen AIO_QT_SAVE_QA=1 \
AIO_DOM_MODULE=/path/to/linkedom/esm/index.js \
python -m unittest discover -s tests -v

python tools/qa/guard_v18_native_benchmark.py \
  --baseline a6b0861be1c5f9b67130627527dfbafe64fbd0f3 --output native-benchmark.json

python tools/qa/guard_v18_status_benchmark.py --output status-benchmark.json

python tools/qa/guard_v17_native_acceptance.py \
  --executable /path/to/libreoffice/program/soffice \
  --corpus /path/to/unpacked/guard_v17_fulltest_subset \
  --output /new/private/qa/output --seconds 60
```

Offline test dependency bundle v17 используется только для испытаний и не
становится зависимостью приложения. Новый патч следует рассматривать целиком
от указанной QA-базы: Python/HTTP/JS delta-контракт меняется согласованно.
Для старых клиентов сохранена полная выдача outputs. Интеграция в рабочую
QA-ветку и подтверждённый Windows QA должны предшествовать выпуску в main.
