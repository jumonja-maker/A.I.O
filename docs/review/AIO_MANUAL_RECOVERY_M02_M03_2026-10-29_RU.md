# M02/M03 — ручной поиск предыдущих результатов без блокировки списка

База: 1646af04841e409079d1bb52150ff10670dc31f1, Draft PR #83. MAIN и базовая QA-ветка не меняются.

## Подтверждённая причина

Первый GET /recoverable синхронно вызывал _load_recovery, включая чтение журналов, SHA-256 исходников и выходов, обход папок и иногда очистку. Интерфейс вызывал его уже при mount конвертера. Пустое состояние блокировало кнопку «Состояние». Сообщение «Команда принята. Обновляем состояние…» привязывалось к revision активной очереди, который при удалении старого задания мог вообще не измениться.

## Изменения

- Интерфейс получает только GET /recoverable?mode=snapshot: сведения уже известных сессий, без поиска и хеширования старых документов. Прежний GET и прямой core-вызов остаются совместимыми и синхронными.
- Кнопка «Найти предыдущие результаты» явно запускает единственный ленивый исполнитель поиска. POST возвращает 202, не ожидая диска. Повторный запрос не создаёт параллельный поиск. Показаны состояния idle/scanning/completed/waiting_for_slot/failed и отдельный признак loaded; пустой список до поиска не называется подтверждённым отсутствием результатов.
- Уже проверенные пакеты появляются постепенно. Снимки опрашиваются только при открытом окне и незавершённом поиске/очистке; закрытие окна, уход из инструмента и pagehide прекращают опрос. Поздний ответ старого представления не заполняет новое. Ошибка транспорта видна и не стирает известные результаты.
- Проверки журналов, путей и SHA-256 не отключены. Задание публикуется после существующей проверки. Перед публикацией повторно проверяется число слотов под общей блокировкой, чтобы параллельная новая конвертация не приводила к превышению max_jobs. Ожидающие папки остаются на диске и требуют продолжения поиска после освобождения слота.
- Завершение приложения кооперативно прерывает чтение журналов и хешей. Остановка не трактуется как повреждение и не запускает salvage. Владелец папки освобождается; неизменённые байты остаются для следующего запуска. Непрерываемый системный вызов диска всё ещё может задержать shutdown; предельное время ОС не обещается.
- Быстрые снимки передают необходимую очистку отдельному существующему исполнителю; квота не освобождается раньше удаления. Ошибка очистки отображается отдельно, бесконечного автоматического повторения не добавлено.
- В текущем счётчике не смешиваются результаты этого запуска и явно найденные старые пакеты. Это не создание отдельной долговременной истории M04.
- M03: выбор пакета заменён нативным inline listbox на четыре строки, ограниченным внутри прокручиваемого модального окна. Внешний системный popup больше не открывается. Подтверждение удаления сохранено; отмена не объявляется выполненным удалением. Статус очистки показан отдельно вместо вечного «Обновляем состояние».

## Приёмка и ограничения

Новый тест на старом HTTP воспроизводит запуск дискового поиска даже с запросом snapshot. Новые проверки используют настоящие сохранённые файлы и журналы, управляемые барьеры медленного диска, повреждение равного размера, конкурентное создание задания, остановку и повтор после ошибки. DOM-проверка использует продуктовый JS и реальные DOM-узлы; HTTP, доставка мутаций и нативный dialog контролируются. Это не проверка отрисовки Windows WebEngine/DPI.

Полная приёмка точного продуктового SHA должна быть подтверждена завершённым GitHub-hosted Windows/Linux CI в PR. До этого PENDING. Одноразовый подготовительный workflow/скрипт не входят в дерево продукта. Нативная конвертация и pin LibreOffice 26.8.2.2 не изменены; дополнительных чтений при обычной конвертации не добавлено.

Открыты: независимая история M04, установленный GUI и малые окна/DPI обеих тем, полный исторический FULLTEST 200/5723, benchmark общего корпуса, удаление «До/После»/BlackBox и остальной мешок. Пользовательский установщик, Releases и Actions Artifacts не создаются; личные раннеры не используются.
