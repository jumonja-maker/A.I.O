## Предмет интеграции

Это продолжение актуальной QA после PR #59, а не самостоятельная замена прежних патчей. Весь новый код находится в одном PR #60. Сливать несколько старых веток заново не требуется. Основная и QA-ветка этим патчем не изменены.

Сильнее проверяется достоверность «До/После», полнота результатов, запись и восстановление, владение файлами между экземплярами, работа процессов и закрытие. Обычная конвертация остаётся на существующих маршрутах. Новые движки, сетевые проверки и зависимости приложения не добавлены. Pillow применялся лишь как независимый внешний проверяющий инструмент в локальном тесте TIFF.

## Изменения контрактов

- Неподдержанный Strict SpreadsheetML получает неполную инспекцию, не ложное совпадение пустых таблиц. Нативный маршрут Strict XLSX → XLSX проверен отдельно.
- Необязательные ограничения анализа (геометрия, preview, память процесса) не становятся ограничениями на импорт/экспорт документа.
- Preview может принимать `analysisId`; новый UI передаёт его. Старые вызовы без идентификатора сохраняют совместимость.
- В новых JSONL-транзакциях записан `outputCount`. Старые журналы читаются, но исчезновение целой старой строки нельзя доказать по отсутствующим сведениям.
- При удалении задания используется маленький идентифицируемый retirement-маркер рядом с каталогом. Он сохраняется до завершения удаления, чтобы другой новый экземпляр не принимал половину каталога за доступный результат. Не удалять эти маркеры вручную во время работы. Старые версии, игнорирующие этот протокол, не покрыты проверкой совместного запуска.
- Объединитель Excel очищает только временные writers собственной книги; Guard/LibreOffice ему не нужны.

## Как оценивать готовность

Linux окончательного исходника: 1038 PASS, 0 SKIP. Итог Windows и ссылки на прогон находятся в основном отчёте. После функционального SHA изменяются только QA-only диагностика дескрипторов, pinned workflows и документы/evidence; SHA текущего HEAD указан в PR.

Не принимать `checked` за обещание полного визуального равенства: он относится к перечисленным проверенным свойствам. Не переносить 900/100 синтетического теста на процент потерь пользовательского FULLTEST. Не переносить ускорение анализа на скорость LibreOffice.

Для следующей пользовательской сборки необходимы отдельная упаковка/installer и приёмка на реальном экране. Для процента потерь нужен новый неизменяемый FULLTEST с исходниками, всеми результатами и журналами. Текущий патч закрывает конкретные подтверждённые дефекты и предоставляет воспроизводимые проверки; эти будущие испытания не выдаются за уже выполненные.
