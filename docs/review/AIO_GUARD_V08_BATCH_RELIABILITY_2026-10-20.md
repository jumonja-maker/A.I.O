# Converter Guard v0.8: очередь, сохранность результатов и скорость

Дата: 20 октября 2026. Патч для отдельной проверки 00AIO, не разрешение на выпуск.

База: `feature/aio-guard-v04-on-main-20261019`, SHA `db55f6366a947ed5cdeb32cb7d6c3b35bf3bc1a4`.
Целевой PR должен смотреть в эту интеграционную ветку, оставаться Draft и не менять `main`.

## Проблема и результат

В переданном отчёте стресс-теста описаны 255 входных файлов, 83 выбранных направления,
7 710 запланированных задач, длительная подготовка, остановка на ODC и массовые диалоги
сохранения после отмены. Это разные проблемы: построение плана, импорт LibreOffice,
выполнение очереди и выдача уже готовых файлов. Их время теперь учитывается отдельно.

Патч связывает каждую попытку с `jobId`, `fileId`, `taskId` и целевым расширением.
Ошибки одного исходника не останавливают другие; отмена конвертации сохраняет готовую
часть; после перезапуска доступны подтверждённые журналом результаты. Появились пауза,
пропуск файла, поиск задач и повтор ошибок. Ни загрузка файлов, ни проверка Guard не
выбирают выходные форматы за пользователя.

Это не заявление о полном устранении потерь содержимого. Доказана сохранность выдачи
в проверенных сценариях и ограниченная эквивалентность штатному LibreOffice на созданных
образцах. Полного сканера качества в патче нет: `qualityCompared=false` сохранён.

## Исправления по участкам

| Участок | Поведение после патча |
| --- | --- |
| Текущая задача | Имя исходника, целевой формат, ID задачи, время и стадия привязаны к одному владельцу; поздний ответ UNO с чужим ID отвергается. |
| Прогресс | Отдельные счётчики успешных, ошибочных, отменённых и исключённых задач. «Обработано» не означает «успешно сконвертировано». |
| Зависание | По истечении времени текущая попытка завершается; оставшиеся направления этого исходника откладываются для явного повтора. Очередь продолжает другие файлы. |
| Невозможный импорт | Подтверждённая ошибка открытия исходника исключает бессмысленные повторные импорты этого же файла в текущем задании. Другой файл с тем же расширением не запрещается. |
| Неясная ошибка | Обычный `exit 1` не превращается в запрет формата. Сохраняется ограниченная нативная диагностика. |
| Проверка пары | На Windows основанием служит реально загруженная модель LibreOffice, её сервисы и фактический импортный фильтр; один результат определения типа не считается успешным импортом. |
| Смена LibreOffice | Устаревшее подтверждение не допускает строгий экспорт. Повторная проверка учитывает смену идентичности движка; расширенный повтор проверяет неизвестные исходники. |
| Отмена | Отмена экспортов отделена от упаковки и сохранения. Готовые результаты попадают в один `AIO_Results_Partial.zip`. |
| Ошибка ZIP | Есть повтор упаковки без конвертации и один выбор папки в desktop. Цикла диалогов по каждому артефакту больше нет. |
| Сохранение папки | Сохраняется всё дерево результатов, включая HTML и связанные выходные ресурсы; создаётся отдельная папка без перезаписи, манифест SHA-256 и отчёт. |
| Прерванное сохранение | Готовые исходные результаты остаются у Guard; отметка сохранения ставится только после завершения всей операции. |
| Служебная папка | Сохранение внутрь управляемого хранилища Guard отклоняется, чтобы последующая очистка не удалила сохранённую копию. |
| Перезапуск | Возвращаются только готовые результаты с завершёнными транзакциями журнала. Автоматической повторной конвертации нет. |

## Очередь и интерфейс обычного режима

Добавлена компактная строка под существующим конвертером. Подробности открываются
в «Очередь и результаты»: поиск, состояние, 50 задач на страницу, пакетное сохранение,
повтор ошибок, технический JSON-отчёт и удаление сохранённых у Guard результатов.
Расширенные настройки, второй движок и свой рендер не добавлены.

«Пауза» действует между нативными операциями; текущий импорт/экспорт продолжается.
«Пропустить файл» отменяет текущую операцию и оставшиеся задачи только этого исходника;
кнопка доступна также во время проверки исходника. Выбор пользователя не изменяется
из-за очередного опроса статуса. Количество запланированных пар показывается до старта.

Большой список не вставляет тысячи строк очереди в DOM одновременно. Сервер передаёт
изменённые строки по ревизии, неизменившееся состояние отвечает 304; клиент обновляет
затронутые элементы прогресса. Составление плана использует Map/Set вместо повторных
линейных поисков. Пока открыты подробности, поиск/фильтрация всё ещё обходят задачи
в памяти; полная виртуализация всего исходного интерфейса не заявляется.

## Как ускоряется работа LibreOffice

1. Реестр и его идентичность читаются один раз на фазу пакета, а не заново для каждой пары.
2. Ранее загруженные исходники и действующие подтверждения переиспользуются при изменении
   списка; увеличение времени проверки может затрагивать только неизвестные исходники.
3. На Windows с `program/python.exe` применяется один приватный Python/UNO worker и
   принадлежащий ему процесс LibreOffice. Для каждого импорта/экспорта открывается свежая
   модель; процесс переиспользуется, модель между разными экспортами не переиспользуется.
4. Сессия перезапускается после 128 операций, ошибки, отмены или тайм-аута. Все дочерние
   процессы входят в приватный Job Object; чужие процессы Office не завершаются.
5. Для однозначного нативного фильтра используется UNO `storeToURL`. При неоднозначном
   выборе фильтра сохраняется штатный CLI. Недоступность запуска UNO допускает переход
   к совместимому пути до экспорта; ошибка уже начатого экспорта не вызывает скрытый повтор.
6. stdout/stderr читаются непрерывно с ограниченным буфером. Тысячи связанных результатов
   не передаются длинным списком через управляющий канал: их собирает владелец каталога.

На Linux сохранены прежние LOK preflight + CLI. Эксперимент с прогретым CLI не показал
ускорения и не включён в поставляемый путь. Windows UNO ускорение требует измерения
на реальной установке: локальный Linux-прогон его не доказывает.

Не менялись параметры компрессии, разрешение изображений, PDF-профиль и штатные
настройки экспорта ради скорости. Во время проверки не навязывается предполагаемый
текстовый импортный фильтр: иначе неподходящий бинарный файл мог бы стать «текстом».
Для экспорта сохраняется фактический фильтр успешного импорта, если он подтверждён
установленным реестром.

## Политики, хранение и восстановление

| Параметр | Значение / назначение |
| --- | --- |
| Число/размер/страницы файлов | Новых лимитов нет; `max_files`, `max_file_bytes`, `max_spool_bytes` по умолчанию `None`. |
| Экспорт | Guard по умолчанию даёт 1 800 секунд на нативную операцию; `timeoutSeconds` позволяет явно увеличить время. Кнопка длительного повтора удваивает его, минимум 3 600 секунд. |
| Preflight | По умолчанию 120 секунд на исходник; кнопка повторной проверки увеличивает время, минимум до 600 секунд. Это неизвестный результат проверки, а не доказательство невозможности формата. |
| Библиотечный API | `GuardLimits(file_timeout=None)` по-прежнему позволяет явно отключить дедлайн. |
| Метаданные | JSON-запрос до 16 MiB для больших планов; это не лимит размера исходного документа. |
| Windows-хранилище | `%LOCALAPPDATA%/AIO/ConverterGuard/jobs`. |
| POSIX-хранилище | `$XDG_DATA_HOME/AIO/ConverterGuard/jobs` либо `~/.local/share/AIO/ConverterGuard/jobs`. |
| Перенос QA-хранилища | `AIO_GUARD_DATA_DIR` задаёт отдельный корень; сервер добавляет `jobs`. Для Windows QA использовать разрешённый владельцем каталог, например на D:. |
| Совместимый путь Windows | `AIO_GUARD_NATIVE_SESSION=0` отключает новую постоянную UNO-сессию для сравнения. |

На старте приложения каталог не создаётся и восстановление не сканируется в потоке Qt.
Чтение выполняется лениво при запросе результатов, создание — при подготовке задания.
При простое Excel дополнительные конвертации и фоновые нативные процессы не запускаются.

`job.json` записывается атомарно с контрольной суммой. `results.jsonl` содержит транзакции
начала задачи, отдельных артефактов и завершения с контрольными суммами; fsync выполняется
после задачи. Это сохраняет небольшой размер отдельных записей даже для тысяч sidecar-файлов.
Отметки сохранения и итог задания также журналируются. Токены скачивания в журнал не пишутся;
при восстановлении выдаются новые. Имя, размер и маршрут исходника в метаданных остаются
локальными пользовательскими данными.

Системная блокировка не позволяет второму экземпляру AIO присвоить активное задание.
Оборванная последняя запись не уничтожает ранее завершённые транзакции. Нечитаемый журнал
не приводит к удалению папки: UI сообщает о проблеме и предлагает диагностический отчёт.
Пути, символические ссылки, наличие и размеры выходных файлов проверяются при восстановлении.
Это не проверка смыслового содержимого файлов и не защита от изменения диска администратором.

Несохранённые готовые результаты не удаляются по старому таймеру хранения. Их освобождает
подтверждённое сохранение либо явное удаление. Это повышает сохранность, но требует места
на диске: забытые задания нужно сохранять или удалять. Прерывание процесса между записью
выходного файла и завершением транзакции может оставить неучтённый файл; Guard не объявляет
его готовым автоматически. Старые TEMP-задания v0.7 автоматически не мигрируют.
Незавершённые исходники после перезапуска нужно добавить повторно.

## Что ещё не доказано и где остаются риски

- **Windows UNO и настоящий Qt folder-save — NOT_RUN.** Не запускались NIKITA,
  установщик, сборка EXE, workflow dispatch, защищённые workflows или релизы.
- Точный зависающий ODC и EPUB из исходного стресс-прогона здесь отсутствуют.
  Ошибка фикстуры, импортного фильтра и особенность LibreOffice ещё не разделены.
  В патче нет запрета всех ODC/EPUB по расширению.
- Успешный импорт плюс зарегистрированный экспорт — свидетельство существования
  нативного маршрута, а не гарантия успешного результата для любого документа.
  Повреждение, пароль, нехватка памяти/диска и ошибки фильтра возможны во время экспорта.
- Нет доказательства отсутствия потерь сложной вёрстки, шрифтов, формул, комментариев,
  анимации и макросов. Макросы не выполняются; внешние обновления не запускаются.
  Это нужно учитывать при сравнении с интерактивным LibreOffice.
- Входные файлы по-прежнему изолированы по отдельности. Внешние относительные зависимости
  входного HTML/документа не собираются автоматически в единый пакет. Выходные ресурсы,
  созданные LibreOffice, сохраняются вместе; это не устраняет отсутствующие входные ресурсы.
- Восстановление готовых файлов проверяет журнал и размеры, но не выполняет дорогое
  повторное смысловое/визуальное сравнение. SHA-256-манифест создаётся при folder-save.
- Тысяча реальных тяжёлых документов и вся матрица 83 направлений не прогонялись.
  Один приватный worker не означает параллельный экспорт; несколько одновременных
  LibreOffice-процессов ради рекорда скорости в патч не добавлены.
- Постоянный AGR-индекс на диске и полноценный сканер до/после не реализованы.
  Отчёт диагностирует выполнение, а не присваивает результату недоказанную оценку качества.

## Приёмка 00AIO перед интеграцией

Сначала закрепить точный HEAD этого PR. Не собирать релиз по одному Linux PASS.
На разрешённой владельцем Windows-среде сравнить один и тот же набор с
`AIO_GUARD_NATIVE_SESSION=1` и `=0`, фиксируя версию LibreOffice и фазовые времена.
Использовать отдельное хранилище `AIO_GUARD_DATA_DIR`; не трогать пользовательский Office.

1. Настоящие CSV/BMP/DOCX/XLSX и переименованные/неизвестные файлы: никто не выбирает
   направления автоматически; `Выбрать всё` берёт только подтверждённые направления.
   Удаление готового исходника не вызывает повторный импорт остальных без причины.
2. Исходные ODC и EPUB из стресс-теста: записать код, нативный diagnostic и стадию.
   Пропуск/отмена должны остановить только своё дерево и продолжить другие файлы;
   увеличение времени — явное действие, а не вечное зависание.
3. Смешанная очередь с одинаковыми именами: текущая строка, задачи и выходные папки
   всегда соответствуют одному исходнику и формату. Проверить паузу между операциями,
   переход через 128 операций, исключение одной пары и повтор только ошибок.
4. Остановить очередь после нескольких успехов: один частичный ZIP. Искусственно
   сорвать упаковку: один выбор папки, все HTML-ресурсы, отмена и повтор сохранения,
   отсутствие ложной отметки «сохранено» после первого файла.
5. Перезапуск и аварийное завершение: восстановить зафиксированные результаты,
   исключить присвоение активного задания вторым AIO, проверить явное удаление.
   Восстановление не должно само запускать конвертацию.
6. Большой пакет и результаты >4 GiB: диск, ZIP64, отмена копирования и постоянство
   памяти. Сделать визуальное сравнение сложных реальных документов со штатным
   LibreOffice, включая шрифты/таблицы/многостраничность и входные внешние ресурсы.

Воспроизводимые локальные команды из корня checkout:

```text
python -m unittest discover -s tests -v
node tests/guard_bridge_contracts.mjs
node tools/qa/guard_v08_plan_benchmark.mjs
python tools/qa/guard_v08_native_acceptance.py --output <новая-папка-QA> --compare-cli
```

Для DOM-тестов нужен уже установленный linkedom и `AIO_DOM_MODULE`, указывающий на
его `worker.js`. Native QA использует локально установленный LibreOffice через
`AIO_LIBREOFFICE`; не скачивает движок, не использует сеть и не устанавливает пакеты.
Необязательный pypdf в QA отмечается отдельно, если отсутствует. Основной конвертер
его не требует. На Windows запуск этих команд остаётся решением владельца среды.

- `uno_session.py`, `office_session.py`, `native_logs.py`: приватная сессия и диагностика.
- `adapter.py`, `preflight*.py`, `routes.py`: фактический импорт и нативные маршруты.
- `app_backend/desktop.py`, `downloads.py`: одно пакетное сохранение и подтверждение.
- `src/converter-bridge.js`, `guard-queue.*`: план, опрос и интерфейс очереди.
- `tests/test_converter_guard_v08.py`, `tests/test_guard_uno_session.py`, DOM/bridge QA.

`main`, защищённые workflows, инсталлятор, брендовые исходники и состав движков этим
патчем не изменяются. Перенос на интеграционную ветку и выпуск требуют отдельной приёмки.
