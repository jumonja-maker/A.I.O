# A.I.O Guard v20 — единый патч и технический осмотр

Дата: 26 октября 2026 года. Репозиторий: jumonja-maker/A.I.O. PR: #59.

## Результат и область

Объединены v18.2.1 и v19 «до/после», исправлены конкретные дефекты FULLTEST и дефекты, обнаруженные при независимом повторном осмотре. Изменения предназначены для отдельной проверки и интеграции 00AIO. Основная ветка и релизы не изменяются.

Это не заявление «все результаты всех форматов теперь идеальны». Для части направлений ошибка находится в нативном экспортёре LibreOffice. Там исправление Guard — остановить ложный успех, сохранить точную причину и продолжить остальные задачи. Устранение ошибочного `ready` не означает восстановление отсутствующих данных и не включается в число успешных конвертаций.

Актуальные точные SHA, результаты общего Linux/Windows QA и итоговое решение записываются в `evidence/v20/acceptance.json`. Исходная интеграционная база: `eb41fd0ec9a871e239ab906cf60791abccc082b0` (PR #56). Присоединённый v19: `761991a8b00807606ad0ddd967fc9c04487a7714` (PR #54). В истории используется настоящий merge-коммит с обеими исходными ветками как родителями; прежние исправления не переносились выборочным копированием поверх старого core.

## Дополнительный разбор семи спорных источников

Проверка «LibreOffice открыл файл» оказалась недостаточной. На трёх SXW с декларацией старого StarOffice, но современным содержимым, проверенный прямой импорт не сохраняет текст; они остаются отклонёнными. Это конкретные три некорректных/неподтверждённых контейнера, не запрет всего формата SXW.

Для двух FODP alias `presentation-flat-xml` установленный явный FlatXML importer сохранил 15/36 абзацев и 3/6 слайдов. Для двух FODT alias `text-flat-xml` существующая подготовка явных колонок таблицы совместно со штатным FlatXML importer сохранила 73/105 семантических абзацев и 48/64 ячейки. Guard не переписывает исходный MIME и пользовательский файл. Нормализация обычных XML-пробелов отделена от потери значений; explicit `text:s/tab/break` в этих четырёх конкретных образцах отсутствуют.

Эти четыре alias теперь имеют узкий структурный профиль, обязательный установленный импортёр и ожидаемый сервис. Если импортёр отсутствует, возвращается `SOURCE_NATIVE_IMPORT_FILTER_REQUIRED`. Если native model не совпала, сохраняется `SOURCE_MODEL_MISMATCH`, без обхода защиты. Linux LOK автоматически выбирает неверную модель и не позволяет обещать эти направления; Windows UNO должен подтвердить явный импорт отдельно. Полные доказательства: `source-contract-seven-native.json`.

## Проверка качества: правила

### DIF

Проверка читает исходные DIF records потоково и сравнивает реальные V-числа с типизированными координатами импортированной Calc-модели. `#ERR` не очищается регулярным выражением и не преобразуется обратно в предполагаемое число. Глобальная локаль LibreOffice не меняется; применяется только описанный ниже частный профиль. Контролируемый эксперимент на том же DIF/фильтре воспроизвёл причину: `ooSetupSystemLocale=ru-RU` дал 24 строки `#ERR`, а частный `en-US` — 0 ошибок и все 72 точных числовых ячейки. Только временный профиль DIF получает `ooSetupSystemLocale`, `ooLocale`, `DefaultLocale`; при переходе к другому исходнику собственный UNO-процесс пересоздаётся с обычным профилем. Последовательные DIF используют один прогретый процесс. Неявное отображение чисел может отличаться от системного языка, что отражено предупреждением. Windows отдельно подтвердил исправление на текущем SHA.

Научная перезапись токенов не включена: эксперимент показал риск изменения числового представления.

CLI использует штатный FODS как частный снимок импортированной модели. Это дополнительная операция ради проверяемости; она может удлинить первую обработку DIF. В пределах экспортного batch повторные цели используют один снимок с проверкой идентичности исходника, временной копии, импортного рецепта и реестра. Живые изменяемые модели между целями не переиспользуются.

`checked_subset` здесь означает проверку импорта чисел. PDF после этого не становится автоматически семантически или визуально проверенным. Обычный TXT/CSV с первой строкой `TABLE` не становится DIF: worker проверяет числа только при фактически выбранном нативном фильтре DIF; CLI также требует подтверждённый импортёр, а не один префикс. Переименование настоящего DIF не снимает проверку.

Неподдержанная грамматика/бюджет инспекции одинаково даёт `not_checked` и понятное предупреждение в CLI/UNO; доказанный числовой mismatch отклоняется. Повреждённый доказательственный XML не используется как успешное доказательство.

### HTML презентаций

Проверяются активные слайды OOXML/ODF, а не произвольные файлы ZIP/media. Отсутствие всего текста при наличии только точных исходных image assets — доказательство потери текста. Отсутствие графических представлений при наличии исходных image instances — отдельная потеря изображений. Полный bundle включает companions; один файл не оценивается так, будто связанные файлы отсутствуют.

Слайд, целиком представленный растром, SVG, CSS или другим неподдержанным способом, не признаётся плохим только из-за нулевого body text. Неопределённость сохраняется явно. Нативные ошибки воспроизведены; безопасный общий экспортный параметр, восстанавливающий все свойства, не найден. Своего HTML-renderer в патче нет.

### Изображения и документы

Обычный PNG не выдаётся за анимированный APNG. GIF с непредставимой палитрой/полупрозрачностью продолжает отклоняться, вместо молчаливого квантования. JPEG остаётся форматом с потерями. Изменение представления страниц в изображение отличается от точной пиксельной конвертации изображения.

Коррекция BMP не применяется к входным пользовательским файлам и generic inspector. Она ограничена собственными завершёнными native outputs; фиксируется исходный SHA output, прежний размер, настоящий размер и четыре изменённых байта. Исходный read handle закрывается до atomic replace — необходимо для Windows. Нестандартные header/compression/offset/truncation остаются ошибками.

DOCM означает macro-enabled контейнер, но не наличие VBA и не исполнение макросов. Требование правильного экспортёра и main ContentType не заменено переименованием суффикса.

## Очередь, отмена, сохранение и изоляция инструментов

Существующая очередь не заменена новой. Один экспортный worker ограничивает число одновременно живых моделей/процессов. Неудачный файл не блокирует остальные; источник с подтверждённым import failure, включая DIF numeric mismatch, не пытается открываться для каждой цели повторно. Timeout/skip/cancel воздействуют на собственное задание и процессное дерево, а не на все soffice пользователя.

Из v18.2.1 сохранены отмена preflight, отдельный прогресс стадии routes, кооперативная отмена матрицы, pinned registry, кэш доказательств и ограниченный CSV→DBF recovery при точном UNO output missing. После объединения это повторно проверяется вместе с v19.

Сохранение использует tickets, immutable snapshots, потоковые копии, независимый readback SHA/size и защиту чужих файлов от перезаписи. Несохранённые результаты принадлежат Guard и не исчезают по таймеру ожидания пользователя. Анализ удерживает отдельный lease; discard/save не должны удалять файлы из-под живого reader. История живёт до удаления owning job, а не бессрочно после полного сброса.

Объединитель Excel и direct transport не используют очередь/кэш Guard. Общие функции ограничены существующим локальным сервером, shell и телеметрией. Обновление Guard не должно запускать LibreOffice при открытии Excel. Все прежние Excel и authenticated HTTP регрессии входят в общий набор.

## Память и вычислительная нагрузка

Проверены bounded структуры: native RPC queue, ограниченные строки протокола, LRU source proofs, trace, change history, one-source evidence/preparation, worker recycle, preview budgets. Кэш исходных признаков не является кэшем результата и не подтверждает новые output без чтения.

Исправлено реальное удержание скрытых UI rowCache/paintedRows после сброса и освобождения задания. Устаревшие HTTP-ответы не воскрешают удалённый сеанс. Preview requests прерываются при смене выбора/размонтировании. При закрытии страницы очищаются observer/timers/snapshot references.

Один worker ограничивает параллелизм, но один сложный документ всё ещё может требовать значительного объёма памяти LibreOffice. Это проверяется по RSS всего дерева процессов.

Полный отчёт и сохранение всё ещё имеют O(число задач) метаданных — это необходимые перечисления, не бесплатная операция. DOM виртуализирован, но 85 000 записей отчёта и тысячи output tickets требуют реального длительного RSS/JS paint теста. Рост renderer private bytes старого FULLTEST на 203 МиБ не объявлен доказанной утечкой; исправления известных удержаний не доказывают устранение всего роста.

## Диагностический карантин

По умолчанию выключен. В API: `GuardLimits(rejected_output_bytes=...)`; для приложения: `AIO_GUARD_REJECTED_OUTPUT_BYTES=0..8388608`. Это лимит диагностических образцов, не лимит размера конвертируемого документа. Включённый бюджет заранее учитывается в явно настроенной spool-квоте перед первым захватом. Нехватка места в диагностике не меняет исходную ошибку конвертации.

Разрешена только папка `job/work/<index>/output`. Образцы сохраняются как инертные `.capture`, с ограниченной JSON-квитанцией, SHA при фактическом копировании и `ready=false`. Большой файл не читается и не хешируется только ради диагностики. Действуют общий предел 8 МиБ, 16 задач, 16 просмотренных записей и ограничение глубины. Ссылки, reparse и hardlink не допускаются. Обычное удаление owning job удаляет карантин; дополнительная возрастная очистка выполняется при следующем захвате, фонового бесконечного сканера нет.

## Телеметрия и provenance

AIO producer сохраняет один FIFO, sequence и nonblocking admission. До 1/8 очереди (с ограниченным максимумом) резервируется от обычных событий для более важных terminal/save/cancel событий. При перегрузке важными событиями потери всё ещё возможны и отражаются sequence gaps/telemetry_dropped. Утверждения «телеметрия теперь никогда не теряется» нет.

`app_revision_source=configured` и `buildIdentity.basis=configured` означают переданный build revision, а не независимо вычисленный SHA исполняемого EXE. Scope `report_runtime` обозначает текущий запуск, включая восстановление старого задания: это не SHA первоначального экспортёра. Отсутствующая идентичность остаётся unknown. Registry fingerprint характеризует установленный реестр и его identity; не называется SHA всех бинарных файлов LibreOffice. Исходный и конечный SHA относятся к конкретным файлам и сохраняют собственную область доказательства.

CPU детей, точные PID+creation counters, WCT/ETW и гарантированная сохранность critical events на стороне BLACK.BOX требуют патча в BLACK.BOX. AIO не выдаёт появление WerFault за доказанный crash/retry. Backend heartbeat также не объявлен доказательством JS paint responsiveness.

## Что проверяется после кода

Общий Linux source suite с Qt, offline DOM и настоящим LibreOffice; независимые negative regressions; нативные экспорты и сохранение SHA; Windows source/Qt/UNO по точному SHA; сохранение старого CSV→DBF recovery; v19 PDF image pixels/CSV values; обе темы, узкое окно, recovery и пять циклов анализа/сброса. Результаты и границы каждой стадии находятся в `acceptance.json`, а не выводятся из одного зелёного CI.

В ходе осмотра исправлены собственные обнаруженные регрессии: ошибочный optional DIF probe обходил native error на отсутствующем path в прежних test adapters; закрытие status modal требовало обновления extracted-code harness; Windows BMP replacement требовал закрытия read handle; SQLite restart нуждался в проверке колонок схемы и сериализации двух запросов. Также Windows выявил удержание открытого FODS при исключении числовой проверки: генератор инспекции должен закрываться явно в finally, включая путь отказа и отмену. Проверки немедленного закрытия при сохранённом traceback добавлены; очистка не заменяется принудительным GC или подавлением ошибки. Проверки этих случаев сохранены. Неудачные промежуточные прогоны не выданы за успешные.

## Остаточные риски и критерий выпуска

1. Нужен новый полный пользовательский FULLTEST на одной версии Windows/LO с source/build SHA и сверкой всех results. Старые проценты не переносятся на новый код автоматически.
2. Требуется длительный real GUI soak: save→clear→idle, повторный batch, renderer RSS/handles и JS/paint heartbeat. Два DOM-цикла не заменяют несколько часов настоящего Chromium.
3. Для DIF полная матрица 6×21 и исторический проблемный locale/LO нужны отдельно. Проверка типизированного импорта предотвращает известную ложную сохранность, но не сертифицирует каждый итоговый формат.
4. HTML exporters LO ещё могут отвергать направления из-за реальной потери. Не следует отключать эту проверку ради большего ready-rate.
5. GIF palette, DOTM/VBA, неотображаемые fonts, layout, сложные формулы, внешние зависимости и собственные ограничения целевого формата остаются отдельными областями. Unknown не заменён глобальным «потерь нет».
6. Физическое зависание диска/fsync и зависший драйвер могут не поддаваться обычной кооперативной отмене. Shutdown с медленным I/O требует Windows fault injection; отсутствие таких отказов в unit suite не является доказательством невозможности.
7. Исследование CLI/UNO параллелизма 1/2/4, live-model reuse и новых настроек выполняется только с теми же source/target/recipe и независимым контролем качества. В этот патч не включена рискованная глобальная смена backend.

Патч передаётся как проверяемый набор конкретных исправлений и интеграции. Решение merge/release требует независимой приёмки 00AIO; `main` не изменяется самим фактом подготовки этого документа.
