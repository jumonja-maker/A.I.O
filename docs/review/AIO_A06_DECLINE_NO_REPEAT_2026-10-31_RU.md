# A06 — отказ от восстановления без повторных напоминаний

Дата: 31 октября 2026 г. База QA: `e56b9c2ee428a599bd5f803575c7834ac35cf06d`.

## Прямое требование владельца

Пользователь может отказаться от предыдущих результатов, после чего A.I.O больше **не должен повторно предлагать восстановление этих же файлов или включать их в сообщение «Есть несохранённые результаты: 3»**. Нельзя бесконечно спрашивать при каждом запуске; нельзя перекладывать проверку аварий на пользователя. M04 (журнал с отчётами) сохранить отдельно.

## Контракт реализации

1. Legacy A06 остаётся доступен только после явного открытия свёрнутой панели. При запуске старый диск не сканируется, нет всплывающего диалога и нет автоматического предложения восстановления.
2. **«Не восстанавливать»** действует на один ранее восстановленный результат либо на неисправный/непроверенный каталог из списка. **«Не восстанавливать все предыдущие результаты»** действует сразу на весь список после **одного** подтверждения. Нажатие «Нет» не делает запросов и ничего не удаляет.
3. Предупреждение чётко сообщает, что отказ означает **необратимое удаление временных файлов**; SQLite-история M04 не затрагивается. **Текущие конвертации запрещено удалять этим действием.**
4. До подтверждения отказа backend создаёт durable, fsync-подтверждённый marker `ResultStore.retire` с привязкой к идентичности каталога. Только затем удаляет каталог. Если Windows не может удалить занятые байты, маркер сохраняется: на следующем запуске эти файлы **не снова выдаются за несохранённые/восстанавливаемые**, система безопасно повторяет очистку по проверенному marker, не обходя чужие каталоги и не объявляя конвертацию успешной.
5. При невозможности записать marker backend **не выдаёт успех** и ничего не скрывает. Занятые другим экземпляром каталоги отображаются как отказ с указанием причины (нельзя считать их удалёнными). Повторные запросы не нужны для уже подтверждённых.
6. Счётчик Guard «текущих несохранённых» по-прежнему исключает `job.recovered`; старый Legacy transport не сливается с M02 Guard и не меняет M04. Для A06 применяется собственный список `restoredFromJournal`.

## Автоматическая приёмка

- Отказ одного восстановленного результата, перезапуск и повторное открытие: 0 восстановлений, 0 старых предупреждений, старые файлы удалены.
- Отказ от каталога с повреждённым journal: удаление подтверждено, каталог не показывается после перезапуска.
- Ошибка удаления после записанного marker: `cleanupPending` честно остаётся, но повторного предложения нет; затем очистка завершается.
- Массовый отказ от нескольких старых каталогов за один запрос **не затрагивает готовый результат текущего сеанса**.
- Запрос без `confirm:true` и запрос с неверным токеном не выполняется.
- DOM: без auto-scan/auto-prompt, один confirm вместо множества, отмена подтверждения не удаляет файлы, после отказа нет повторного предложения.
- Windows/Linux hosted CI + строгий QA gate на source и merged SHA. Installed Windows GUI, пользовательские диски и полный исторический FULLTEST остаются отдельной приёмкой; не считать их пройденными.

MAIN, M02, M04, релизы и пользовательский установщик не меняются. Никакие файлы не удаляются автоматически без отдельного подтверждения отказа в A06.
