# M20 — все страницы Draw/Impress → EMF/WMF и исправление BMP

База: `8dcf679072774de8400560b1bd6d2a8b0c4ffd92`, Draft PR #83.

## Подтверждённая причина

В `aio_export_graphic_pages` не было EMF/WMF. Эти направления уходили в обычный `storeToURL`, который на контрольной трёхстраничной презентации сохранял только первую страницу. Локальный опыт выполнен напрямую с LibreOffice 25.2.3.2 (Linux), без A.I.O: первый текстовый маркер присутствовал, второй и третий отсутствовали. Тот же нативный GraphicExportFilter при выборе каждого DrawPage записал правильный отдельный EMF/WMF для каждой страницы.

Второй дефект: для BMP код проверял `supportsMimeType('image/bmp')`, а проверенный нативный реестр предлагал `image/x-MS-bmp`. Проверка старого имени возвращала false. Нельзя обойти это отсутствием проверки: неподдержанное имя может приводить к неверному контейнеру. Новый исполнитель выбирает поддержанный нативный вариант; обычное image/bmp остаётся только проверяемым резервным именем.

## Изменения

- Добавлены EMF/WMF в существующий постраничный исполнитель и требования Guard для уже подтверждённых Draw/Impress-моделей. Не добавлены новые направления Writer/Calc и не ослаблен preflight.
- Только native GraphicExportFilter, исходный вектор не превращается в PNG/PDF. Один файл на страницу, прежний AIO-pages.json, единый подтверждённый счётчик страниц без повторного запроса.
- Для BMP проверяется сначала image/x-MS-bmp, затем image/bmp, только если конкретный запущенный движок его поддерживает.
- Не относящиеся к исполнителю форматы больше не вызывают getDrawPages. Одностраничный экспорт оставлен на прежнем пути.
- Недостоверный счётчик или более 4096 страниц не заменяется первой страницей.
- Пути резервируются эксклюзивно. Существующие выходы и манифест не перезаписываются. При ошибке записи/экспортёра/коллизии удаляются только созданные данным вызовом файлы. Заблокированные остатки остаются в принадлежащем заданию рабочем каталоге.
- Исправления Recovery, M05/M06, прежние маршруты и Windows LibreOffice 26.8.2.2 не меняются.

## Проверки и границы доказательств

Добавлен 21 unit-тест реального встроенного исполнителя с контролируемым UNO и настоящими временными файлами. База отдельно воспроизводит отсутствие контракта EMF/WMF и отказ канонического BMP-кодека. Новый код прошёл локальный целевой набор. Нативный локальный запуск исправленного исполнителя сохранил все три страницы EMF/WMF/BMP; уникальные текстовые метки проверены в векторных байтах, цветовые участки — в BMP. Это Linux 25.2.3.2, не приёмка Windows.

В основной Windows CI добавлен отдельный обязательный тест через штатный LibreOfficeAdapter: четыре контрольных источника FODP/FODG/PPT/PPTX, три назначения EMF/WMF/BMP — 12 преобразований и 36 страниц. Для каждого проверяются манифест, требования Guard, уникальные метки правильной страницы и неизменность исходника. Конвертация проверяется настоящим закреплённым движком, не FakeAdapter. Пиксельный анализ существует только в QA.

На момент коммита Windows/Linux CI: **PENDING**. Упаковка EXE требует также успеха нового нативного шага. Полный FULLTEST 200/5723, внешний просмотрщик EMF/WMF, точность шрифтов/всех сложных объектов, GUI и сопоставимый benchmark не выполнены. M20 целиком не закрыт. M28 (счётчики EMF), EMZ/WMZ и другие непроверенные направления здесь не объявляются исправленными.

## Дополнительная находка M19 — не закрыта

В отдельном локальном исследовании PPT→XHTML снова потерял все три текстовые метки, тогда как FODP→XHTML их сохранил. После импорта PPT текст находился в draw:custom-shape; установленный штатный XSLT содержит пустое правило для draw:custom-shape и draw:g. Изменение нумерации абзаца эту потерю не устранило. Это более узкая локализация, но не проверка всех исторических PPT и не исправление Windows-движка. Не добавлялся текст вручную в результат и не ослаблялся безопасный отказ Guard.

MAIN и базовая ветка не меняются. Только GitHub-hosted, без пользовательского установщика, Actions Artifacts, Releases и личных раннеров. Не вычитать случаи из 1079 исторических отклонений до повторного аудита исходного корпуса.
