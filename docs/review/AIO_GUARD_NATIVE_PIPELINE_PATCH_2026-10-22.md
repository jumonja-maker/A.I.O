## Результат и границы

Убрана автоматическая вторая дисковая копия результатов для сохранения в папку в настольном AIO. Снижены повторные операции UNO и объём служебных сообщений, ошибки отдельных экспортов не пересоздают исправный офис. Настроенные таймауты, отмена, проверка реальной модели и свежая модель для каждого экспорта сохранены.

**308 методов прошли, 0 FAIL / ERROR / SKIP из 308 запущенных; 310 обнаружены.** Два метода, зависящие от master PNG, явно исключены: их большие бинарные исходники недоступны локально через использованный текстовый транспорт. Удалённые blobs изображений сохранены без изменений. Нативная локальная проверка — **8/8 задач PASS** на Linux LibreOfficeDev; она не подтверждает Windows UNO, видимый Qt или полную визуальную сохранность.

Общего ускорения LibreOffice в несколько раз не заявляется. В локальном Calc-прогоне сам нативный процесс по-прежнему занимает около 10–11 секунд на маленькую таблицу. Историческая причина полного зависания интерфейса и 3,5-часового пользовательского прогона не доказана.

## Что изменено

| Область | Было | Стало |
| --- | --- | --- |
| Завершение очереди в настольном AIO | Все выходы автоматически копировались в ZIP перед итоговым состоянием | Bridge передаёт Guard `archiveMode: on_demand`; готовые выходы доступны без архива |
| Сохранение результата | Требовалось сначала дождаться ZIP, хотя папка копирует исходные артефакты | Обычное сохранение отложенного результата использует папку и все артефакты; кнопка ZIP строит архив отдельно |
| Совместимость клиентов | Один режим архивации | Старые клиенты и браузер сохраняют `auto`; значение проверяет Guard до изменения задания |
| Итог после явной сборки ZIP | Успешная/отменённая очередь превращалась в `partial` | Возвращается прежний итог конвертации; ошибка архива отражается отдельно |
| UNO preflight | Отдельный глубокий TypeDetection, иногда GraphicProvider, затем обязательная загрузка | Сразу загружается native-модель; FilterName, TypeName и services берутся из неё |
| UNO сообщения | Для каждого запроса заново составлялся и сериализовался весь список import-фильтров | Неиспользуемый список удалён из обоих UNO-запросов и одноразового manifest |
| Экспорт, требующий взаимодействия | Явный handler передавался только импорту | Экспорту передаётся собственный Silent/Abort handler; ошибка получает код `EXPORT_INTERACTION_REQUIRED` |
| Обычная ошибка экспорта | Адаптер уничтожает worker, даже если модель штатно закрылась и ответ получен | Исправный worker остаётся для следующей задачи; ошибка закрытия модели по-прежнему требует recycle |
| Неопределённый результат RPC | Возможен fallback после ошибки запуска внутри отправленного запроса | После отправки запроса скрытый повтор через CLI запрещён |
| Ожидание CLI/preflight | Завершившийся короткий процесс мог ждать полный интервал sleep | Ожидается фактический exit с ограниченным timeout, без нового watcher-потока |

В репозитории с 5000 дополнительными импортерами контракт подтверждает: сообщение экспорта не содержит весь реестр и остаётся меньше 4096 байт на этой генерируемой фикстуре. Это тест размера конкретного сообщения, не новый лимит имени или документа.

Ошибки импорта, требующего данных пользователя, не повторяются для каждого оставшегося формата того же исходника. Следующий файл продолжает обрабатываться. Ошибка отдельного экспорта не считается ошибкой импорта и сама по себе не блокирует остальные направления.

## Сохранение и восстановление

`on_demand` — политика конкретного задания. Другие инструменты AIO её не получают. Для нескольких результатов `bundleDeferred: true` и `result.folderOnly: true` обозначают отложенный архив; `packagingError` остаётся пустым. Единственный успешный артефакт по-прежнему не требует ZIP.

Явная команда `/bundle` создаёт архив из всех удерживаемых выходов. Bridge использует новый ticket архива и не выдаёт первый PDF за полный ZIP. Проверены обычный и прямой вызовы сохранения ZIP. При нехватке места все исходные результаты остаются доступны для сохранения в папку. Состояние успешной или отменённой конвертации сохраняется.

Проверены сохранение без ZIP, повтор команды сборки, отказ диска, отменённая очередь и восстановление после перезапуска с последующей сборкой полного архива. Прежние durable-транзакции, публикация готовых выходов и подтверждение сохранения не ослаблены. В `timings.archiveMs` учитывается фактическая работа архивации; отложенный ZIP не считается ошибкой.

Один и тот же новый код; сравниваются режимы `auto` и `on_demand`. Synthetic native boundary, 128 файлов по 1 МиБ, 3 чередующихся повтора, без параллельного нативного прогона.

| Метрика | auto | on_demand |

## Интеграция и оставшаяся приёмка

Переносить целиком PR #20 поверх указанной QA-основы. Производственные изменения: core/API, converter-bridge, adapter, два UNO-worker source, preflight и ожидание в libreoffice_engine. Два новых QA-скрипта не запускают runner и ничего не устанавливают.

Для повторения локально:

```text
python -m unittest discover -s tests -v
# Для трёх DOM-методов задать AIO_DOM_MODULE на существующий linkedom/esm/index.js.
python tools/qa/guard_v12_native_pipeline_acceptance.py --output <NEW_DIRECTORY> --executable <SOFFICE> --session-max-tasks 2
python tools/qa/guard_v12_archive_benchmark.py --output <NEW_DIRECTORY> --files 128 --bytes 1048576 --repeats 3
```

Windows/NIKITA, реальный Windows UNO/Job Object, видимый Qt, системные диалоги, физически медленный диск, установщик и релиз этим патчем **не запускались**. Для Windows-acceptance нужно отдельно получить разрешение владельца. В логе native QA обязательно смотреть `nativeModes`: успех CLI не засчитывать как проверку UNO.

При следующей разрешённой приёмке проверить несколько экспортов одной модели исходника с закрытием и recycle через каждые 2 операции; многолистовый Calc→CSV, DOCX→HTML/PDF и графические фильтры; требование пароля/параметров при импорте и экспорте; отмену/таймаут/потерю worker; оба сохранения и отмену диалога, повтор после отказа ZIP, отсутствие потери поздних выходов при сохранении работающей очереди. Проверить, что обычные предупреждения фильтров не создают ложных отказов под Silent/Abort handler.

Отдельно остаются полный 255-file/7326-task корпус, длительный RSS/CPU всего дерева процессов, историческое зависание GUI, качество Draw→HTML и распознавание неизвестных расширений. Полноценный сканер до/после и Advanced в этот патч не входят.
