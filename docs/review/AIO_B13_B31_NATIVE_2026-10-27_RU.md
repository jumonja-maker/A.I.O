# B13/B31 — явный DBF C9 и JPEG-алиасы Writer/Web

База QA: `e80cdb84b90f2737b492185a3eb22586570c9f8c`.
Статус: кандидат, Windows native acceptance ожидается.

DBF получает `dBase:34` только при подтверждённом заголовке dBase III,
language-driver `0xC9`, согласованных ширинах полей/длине записи, полном payload,
поддержанных типах и строгом CP1251-чтении текстовых полей. Неизвестный драйвер,
конфликт с валидным UTF-8, некорректный заголовок либо неподдержанная структура
не получают угаданной кодировки. Native abort-on-interaction сохранён.
ASCII-профиль и DIF `76` не изменены.

JPEG-алиасы JFIF/JIF/JPE получают штатный Writer JPEG-экспортёр на тех же условиях,
что JPG/JPEG: требуется установленный фильтр и подтверждённая Writer-модель либо
живой XTextDocument в Writer/Web. Проверяются JPEG magic, фактический Qt decode и
размеры. Подмена HTML переименованием не допускается. Это не утверждение полной
визуальной сохранности документа; границы JPEG остаются.

Целевой runner создаёт отдельные DBF восьми уровней, сравнивает кириллицу, числа,
ID и последнюю запись независимым openpyxl; затем выполняет 5 семейств × 8 уровней
× 3 JPEG-алиаса и JPG/JPEG/PDF-контроли. Сравниваются реальные размеры и RGBA SHA.
Проверяется неизменность исходников. Фикстуры генерируемые и не выдаются за
недоступный исторический корпус. Перед приёмкой обязательны B28/B29 и общий набор.

Дополнительные read-only probes фиксируют поведение Windows Qt на TIFF 6/7/8
страниц. Изменений TIFF-декодера в этом PR нет. ORP имеет `not_tested`: настоящая
положительная фикстура LibreOffice Base ReportDefinition отсутствует. Универсальная
конвертация обычных Office-документов в ORP не включается.

Локально: новые DBF/JPEG негативные и позитивные контракты и смежные проверки
пройдены; фактический Windows результат будет добавлен после завершения runner.
Guard-проверки презентационного HTML и GIF не ослаблены.
FULLTEST, EXE, релиз, изменение main и merge в QA не выполняются.
