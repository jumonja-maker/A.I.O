# A.I.O — «до/после» и проверенный повтор конвертации, v19

Дата: **25 октября 2026 года**.

## Основа и назначение

Единый отдельный патч подготовлен поверх QA-коммита
`3ca80cf40577372a4177f82939756247ecc95bfb`, ветка
`feature/blackbox-deep-telemetry-v01-20261021`. В ней уже находятся Guard v18 и
доработки перед интеграцией. `main` на базе задания —
`2bab2d0c31fe84a0d07404a33219dd5bdad834b7`; этот патч её не изменяет.

Реализован сквозной сценарий: конвертация → добровольный анализ → просмотр
конкретных изменений → выбор подходящих преобразований → повтор с проверенным
рецептом LibreOffice → повторный анализ кандидата. Пользователь может сохранить
первый результат сразу. Анализ не становится условием допуска к конвертации.

Подбор работает локально по конечному каталогу правил. ИИ, сетевой сервис,
загрузка моделей или новый движок конвертации для этого не требуются. Каждое
заключение относится к перечисленным проверенным свойствам; глобальная оценка
«документ полностью сохранён» не выдаётся.

## Окно пользователя

После завершения обычной конвертации доступны сохранение результата и запуск
«Сравнить до/после». Выбор файлов, подготовка маршрутов и само завершение
конвертации анализ автоматически не запускают.

Окно следует эскизу владельца:

- Слева — список конкретных пар `исходник → формат`, поиск и фильтрация. Один
  исходник, преобразованный в несколько форматов, имеет несколько отдельных
  записей. Чекбоксы задают область будущего повтора.
- Справа — предпросмотр выбранного преобразования. Двойной клик или Enter
  открывают документ. Переключатель «Исходник / Результат» сохраняет выбранную
  пару. Доступен постраничный просмотр PDF.
- Под предпросмотром — «Что изменилось»: находки, исходные/полученные значения,
  первые конкретные адреса ячеек и раскрываемые подробности. Непроверенные
  свойства отображаются отдельно.
- Внизу — «Повторить с автонастройкой» с количеством выбранных преобразований.
  Интерактивный знак предупреждает: настройка не обязательно улучшит файл,
  первый вариант сохраняется.

Красный цвет обозначает подтверждённую потерю проверяемого свойства, жёлтый —
ограничение формата. Цвет сопровождается подписью. Неопределённые и непроверенные
случаи имеют собственные состояния; они не превращаются в красную ошибку.
Для результата без обнаруженных проблем используется формулировка
«Проверенная часть сохранена».

Есть прогресс, пауза, продолжение, остановка анализа и остановка повтора. Список
выдаётся страницами по 50 записей; API ограничивает страницу 100 записями.
Закрытие окна снимает UI-таймеры, обработчики ожидания и Blob URL, не является
командой удаления результатов. Сохранение остаётся отдельным действием.
Для повторных пакетов доступны просмотр, сохранение и возврат к первому пакету.

### Фактический охват этой версии

Поддерживаются ограниченные структурные сведения ODF/OOXML и плоского ODF,
текстовые представления, CSV/TSV/TAB, PDF и распознаваемые растровые контейнеры.
Для неподдерживаемого входного представления анализ возвращает причину, сохраняя
возможность конвертации и сохранения.

- Таблицы: однозначно сопоставимые значения одной таблицы/листа. Несколько CSV
  могут подтверждать полный набор значений листов без выдуманного сопоставления
  имён и порядка. Даты, время, логические значения, локализованное отображение,
  неоднозначные формулы и текстовое представление чисел обрабатываются
  консервативно. Смысловые пробелы в ячейках не удаляются ради совпадения.
- Документы: нормализованный извлечённый текст и доступная структура. Отличие
  извлечения PDF не объявляется исчезновением видимого текста.
- Изображения: доступные размеры, кадры/страницы, прозрачность и структура
  поддерживаемого контейнера. Конкретные проверки не доказывают равенство всех
  пикселей либо точность цветопередачи.
- Побайтово одинаковые файлы получают отдельное доказательство равенства байтов.
  Это не переименовывается в выполненную проверку свойств, которые не измерялись.

Исходник проверяется по исходной SHA-256, полученной при загрузке в Guard.
Выходные файлы проверяются по зафиксированным отпечаткам результатов. Подмена
служебных байтов после конвертации отмечается отдельно: её нельзя приписывать
ошибке LibreOffice. Исходная структурная сводка используется повторно для
нескольких результатов одного файла; каждый результат исследуется независимо.

Внешний вид, шрифты, вычисление формул, смысловая эквивалентность и полнота
визуального воспроизведения остаются явными неизвестными там, где для них нет
доказательств. Никакого искусственного процента «качества» нет.

## Автонастройки LibreOffice

В v19 реализованы **два** проверенных рецепта. Произвольные параметры фильтра из
клиента не принимаются. Допуск зависит от текущего native proof, фильтра и модели
установленного LibreOffice; до создания кандидата проверяется пригодность
рецепта, затем исходник проходит свежий preflight.

| Рецепт | Применение | Параметры и ограничения |
| --- | --- | --- |
| `pdf_preserve_images` | Допустимые PDF-фильтры LibreOffice | `UseLosslessCompression=True`, `ReduceImageResolution=False`. Не восстанавливает уже утраченное качество, отсутствующий шрифт или повреждённый импорт |
| `csv_preserve_values` | Подтверждённый Calc `Text - txt - csv (StarCalc)` для CSV/TSV/TAB | UTF-8/BOM, полная точность значений вместо отображаемого округления, значения формул, отдельные файлы всех листов. Не создаёт в CSV оформление или полноценную модель книги |

Параметры реально передаются как CLI filter options/typed JSON либо UNO
`FilterData` и проверенные `FilterOptions`. Настройки относятся к конкретной
задаче, не к пользовательскому профилю LibreOffice. Живая модель документа
между target по-прежнему не переиспользуется. Qt-only/identity преобразование
не получает ложной отметки «применены настройки LibreOffice».

Каталог не содержит универсального ремонта остальных пар форматов. Отсутствие
рецепта отображается как отсутствие проверенной автонастройки. Ожидаемые
ограничения формата не объявляются исправленными изменением опций.

### Повтор и оценка кандидата

Выбираются конкретные идентификаторы преобразований текущего анализа.
Неизвестные, повторные, устаревшие и не имеющие подходящего рецепта записи
отклоняются до запуска. Для совместимых групп создаются отдельные задания,
копируются исходные байты и сопровождающие ресурсы, повторяются admission и
экспорт только выбранных пар.

Первый пакет, его байты и tickets сохраняются. История кандидата содержит
родительское задание/задачи, идентификатор рецепта и фактически применённые
параметры. Новый результат анализируется автоматически после повтора.

Оценка `checked_subset_improved` разрешена только при сопоставимом проверенном
охвате, исчезновении подтверждённых прежних потерь и отсутствии обнаруженных
новых потерь. Остальные исходы — улучшение не подтверждено или сравнение
невозможно. Эта оценка не обещает сохранность неизмеренных свойств. Автоматической
замены первого результата и бесконечного перебора опций нет; пользователь
сохраняет выбранный вариант явным действием.

## Жизненный цикл, память и восстановление

`ConverterGuard.create(..., retain_sources=False)` сохраняет прежнее поведение
для старых API-клиентов. Обычный интерфейс явно передаёт `retainSources:true`,
чтобы служебные копии оставались **на диске** после последнего target и были
доступны для кнопки анализа. Документы не удерживаются целиком в RAM.

`comparison_inputs(job_id)` выдаёт независимые записи всех terminal task pairs,
включая записи без результата. Lease удерживает `job.io` и не позволяет очистке
удалить активные исходники/результаты. Привязка lease передаётся фоновому заданию
без окна между постановкой и захватом. Paths поступают только из принадлежащих
Guard записей; source, ресурсы и outputs проверяются на расположение, размер,
обычный файл и отсутствие symlink/reparse выхода из owned tree.

Копирование повтора идёт через штатную потоковую загрузку с проверкой SHA-256.
Отмена прерывает подготовку, preflight и native-обработку без отдельного watcher
thread на каждый файл. Завершённый кандидат отсоединяется от события отмены
следующих операций. Пользовательское удаление/сохранение и ошибки работы с
диском не превращаются в успешную проверку.

Recovery хранит относительные пути retained originals, отпечатки и HTML-ресурсы.
После перезапуска исходник восстанавливается только при совпадении SHA-256.
Если он исчез или изменился, готовые outputs всё равно восстанавливаются, а
анализ честно отмечается недоступным. Произвольные исходники не импортируются и
конвертация автоматически после рестарта не возобновляется. Анализ после
перезапуска можно явно запустить заново; автоматическое продолжение прежней
аналитической сессии не заявляется.

## Фоновые вычисления и предпросмотр

Данные анализа хранятся в SQLite внутри принадлежащего Guard каталога.
На интерфейс передаются страницы отчёта, а не содержимое тысячи документов.
Объём сохранённых в менеджере завершённых метаданных ограничен. Выполняется
один аналитический worker и ограниченная очередь повтора; нет запуска 1000
нативных процессов одновременно.

Парсеры выполняются в отдельном завершаемом процессе. Ограничиваются время,
размер инспектируемых данных, XML-структура, текст и ячейки. Эти бюджеты относятся
к **анализу**, а не к допуску или размеру конвертируемых документов. Превышение
даёт `not_checked`; оно не запрещает сохранение результата.

Текущие внутренние бюджеты инспекции: 32 МиБ прочитанных данных, 16 МиБ
одного XML, 512 000 символов, 50 000 ячеек, 200 000 XML-узлов, 256 страниц
при извлечении PDF. Внутренний мягкий бюджет операции — 12 секунд; внешний
дедлайн принудительно завершает принадлежащий A.I.O процесс. Это границы
доказательства анализа, а не лимиты конвертации или сохранения.

PDF отображается постранично существующим QtPdf в отдельном процессе.
Возвращается PNG страницы с белой бумагой; в проверенном сценарии размер
не более 1400×1800. Растровые изображения тоже декодируются в отдельном
процессе Qt и возвращаются уменьшенным PNG не более 1400×1800. Исходные
сжатые байты не передаются браузерному декодеру. Ограничены заявленное
число пикселей и выделение памяти QImageReader (64 МиБ); это не жёсткий
лимит общего RSS процесса. Для анимации показан первый кадр, прозрачность
сохраняется. Небольшие изображения не увеличиваются. Для других
поддерживаемых документов доступно явно подписанное текстовое представление,
которое не притворяется визуальным воспроизведением исходной вёрстки.
Предпросмотр остальных крупных/неподдерживаемых объектов сообщает ограничение.
64 МиБ — бюджет встроенного просмотра соответствующих файлов, а не предел
конвертации. PDF имеет постраничный путь и собственный дедлайн.

Файлы не помещаются в HTML iframe и не выполняются как HTML/JavaScript.
Ослабление CSP для нового окна не требуется. Неизвестные имена, строки и
значения выводятся как текст. Временные preview directories и Blob URL
освобождаются по завершении/смене выбранного файла.

## API и программные границы

Все новые операции используют существующий authenticated loopback backend,
проверку Host/Origin и `X-AIO-Token`; произвольные локальные пути не принимаются.

| Метод и путь после `/api/converter-guard` | Назначение |
| --- | --- |
| `POST /prepare` или `/jobs`, `retainSources:true` | Явное хранение служебных исходников для последующего анализа |
| `POST /compare/start`, `jobId` | Идемпотентный запуск/получение текущего аналитического задания |
| `GET /compare?job=...&offset=...&limit=...&filter=...&q=...` | Прогресс, сводка и страница записей; поиск учитывает кириллицу без зависимости от регистра |
| `GET /compare/item?job=...&task=...` | Подробности одной пары и допустимые стороны предпросмотра |
| `GET /compare/preview?job=...&task=...&side=source|result&page=...` | Изолированный текстовый/постраничный PDF либо растровый предпросмотр |
| `POST /compare/control`, `jobId`, `action` | `pause`, `resume`, `cancel` |
| `POST /compare/retry`, `jobId`, `analysisId`, `taskIds` | Повтор выбранных подходящих пар из актуального завершённого анализа |

Основные файлы: `comparison_analysis.py`, `comparison_service.py`,
`comparison_worker.py`, lifecycle в `core.py`/`result_store.py`, рецепты в
`export_recipe.py`/`adapter.py`/`uno_session.py`, HTTP в `http_api.py`, окно
`src/guard-comparison.js` и `src/guard-comparison.css`.

Excel остаётся отдельным инструментом. Новая подсистема не запускает анализ
на открытии приложения или при работе объединителя, не меняет его данные и
ограничения. Облачный сервис/BLACK.BOX/Advanced для неё не требуются.

## Критерии интеграции и оставшаяся приёмка

1. Переносить согласованный Python/HTTP/JS патч целиком на указанную QA-базу;
   сверять SHA программных файлов с манифестом кандидата.
2. Сохранять обычное сохранение доступным, добровольность анализа и категории

### Второй Runner-прогон и исправление продуктовой границы

[Второй run #40188505773](https://github.com/jumonja-maker/A.I.O/actions/runs/40188505773)
проверял source `b6998a0`: NIKITA — 712 PASS, 1 FAIL, 7 POSIX N/A;
AIO-UBUNTU — source-only 691 PASS, 29 Qt/LibreOffice N/A, без ошибок.
[Полная компактная сводка](evidence/v19/runner-second-summary.json).

Windows fallback с настоящим junction обнаружил продуктовый дефект: выходные
артефакты фактически обходили проверку принадлежности каталогу задания.
Проверка конечного symlink на Linux недостаточно покрывала этот случай.
Теперь пути outputs проверяются перед анализом и предпросмотром. Та же общая
проверка добавлена перед скачиванием, сохранением папки и чтением для ZIP:
обычный файл, ожидаемый размер, расположение под каталогом задания и отсутствие
ссылок/reparse в предках. Непринадлежащий путь отклоняется до чтения/копирования,
включая случай полностью совпадающих байтов. Это защита границ служебных файлов,
а не заявление о полном OS sandbox против процесса с теми же правами.

Новая регрессия проверяет все три read-boundary, сохранность внешнего файла,
пустой каталог назначения, удаление незавершённого ZIP и корректное освобождение
lease. Удаление каталогов оставлено штатному механизму Python; произвольные
пользовательские папки не очищаются.

В реальном CSV на NIKITA получили `1,23`, обусловленное локалью исходного
числового формата. Прежняя диагностика оставляла UNCERTAIN, но ошибочно писала,
что значения совпадают. Теперь сообщение прямо говорит о непроверенном
соответствии типа, локали и точности. Статус неопределённости не превращён в
ложную ошибку или успех. [Проверки locale](evidence/v19/native-locale-diagnosis.json)
показывают: token 6 в испытанном CSV-экспорте не делает числовую локаль
универсальной настройкой. Производственный рецепт не меняет форматы ячеек
и пользовательский профиль. Для повторяемого контроля синтетическая ячейка
явно содержит `[$-409]0.00`; [полный реальный цикл](evidence/v19/native-explicit-locale.json)
прошёл на таком образце. Это не доказательство универсального сравнения
произвольного локализованного CSV.
