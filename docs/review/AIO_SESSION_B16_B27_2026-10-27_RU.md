# B16–B18 / B23–B24 / B26–B27: жизненный цикл сессии

База QA: `e80cdb84b90f2737b492185a3eb22586570c9f8c`. Отдельный PR; main, релизы и пользовательские результаты не затрагиваются.

## Изменения

- Три постоянных действия после конвертации: «Закрыть», «Сохранить результаты», «До/После». После сохранения результаты и исходники остаются доступны для анализа до явного закрытия.
- Счётчик выбранных/всех исходников берётся из фактической модели. Корзина отменяет текущую операцию, дожидается остановки и очищает список; готовые выходы остаются в очереди сохранения.
- Закрытие с несохранёнными основными выходами требует «Да/Нет». «Нет» не меняет данные. «Да» отменяет собственный worker и освобождает только принадлежащее сессии временное хранилище после завершения операций. Сохранение и закрытие сериализованы; завершившийся save не может одновременно потерять spool.
- Полностью сохранённая сессия закрывается без вопроса. Восстановленные сохранённые сессии доступны с нулём несохранённых выходов; счётчик предупреждений учитывает выходы, а не число сессий.
- Анализ не добавляет обязательные к сохранению артефакты. Явное сохранение из анализа создаёт отдельный необязательный ZIP с одним выбранным выходом и диагностикой. Исходник включается только по отдельному флажку. Для отказа без выходов доступна диагностика без выдуманного результата. «Сохранить всё» из анализа убрано.
- Диагностический экспорт повторно проверяет SHA и принадлежность файлов, имеет отдельный ограниченный бюджет и не подтверждает сохранение основных результатов.

## Проверки и ограничения

Локально: 36 тестов жизненного цикла, сохранения, восстановления и реального JS bridge с управляемыми HTTP/native-save границами — PASS. Отдельные DOM проверки сохраняют проверки readback и добавляют постоянные кнопки, двойное закрытие, «Нет», закрытие сохранённого результата и очистку модели.

Windows NIKITA: запланированы реальный LO import/export, частичное сохранение, restart/recovery, SHA/readback каждого файла, необязательная диагностика, анализ после сохранения и реальная отмена собственного native worker; Qt light/dark, narrow view, save/analysis journeys и полный source regression. До получения результатов это **pending**, не PASS.

Этот этап не является пользовательским FULLTEST, сборкой EXE или ручной приёмкой установленного приложения на разных DPI. Полноценный двухпанельный preview и новые анализаторы относятся к следующему PR.
