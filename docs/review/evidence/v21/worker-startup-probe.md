Это **read-only исследование**, выполненное после заморозки v21. Изменений в продукте нет. Числа ниже перенесены из фактически полученного вывода инструмента; исходный массив индивидуальных замеров не сохранялся. Новый benchmark при подготовке этих файлов не запускался.

Наблюдаемое снижение медианы времени полного пробного подпроцесса — 45,54% и 58,20% соответственно. Это эффект в данном микрозамере, не заявленное ускорение поставленного AIO. Во всех 80 подпроцессах результат был `checked`; SHA прочитанного исходника после замера совпал с SHA до него. Сам SHA в выводе не сохранялся. Qt не загружался ни в одном варианте.

## Что измеряли

Использовали `ba-venv/bin/python -B`, `PYTHONDONTWRITEBYTECODE=1`, текущую рабочую папку AIO. Для каждого из двух режимов кеша запускали 20 пар новых процессов, меняя порядок eager/lazy на каждой паре — всего 80 процессов. Часы: `time.perf_counter`. Значение p90 — элемент `sorted(values)[17]` для 20 измерений.

Дочерний процесс импортировал `comparison_worker` и `comparison_analysis`, затем один раз выполнял `analyze_pair(csv, [csv], 'csv')` на уже существующем маленьком синтетическом CSV из `state/before-after-transport-final/owned/*/work/0/output/*.csv`. Файл не создавался и не изменялся, один и тот же путь использовался как обе стороны. Поэтому замер выделяет стоимость импорта относительно простого анализа, а не имитирует полный пользовательский документ.

В режиме `simulated_lazy` перед импортами создавали **только в памяти** `types.ModuleType('app_backend.converter_guard')` с настоящим `__path__` и package `ModuleSpec`, помещали его в `sys.modules` и `app_backend.converter_guard`. Так пропускался eager `__init__.py`, а нужные подмодули загружались обычным способом. Это не готовая реализация `__getattr__` и не доказательство совместимости публичного API.

В режиме `source_only` дополнительно заменяли **только внутри измеряемого процесса** `SourceFileLoader.get_code`: для имён `app_backend` и `app_backend.*` вызывали `source_to_code(get_data(path), path)`; для остальных модулей — исходный метод. Кеш стандартной библиотеки сохранялся, файлы pyc не удалялись и не записывались. Этот режим позволяет изучить стоимость компиляции исходников проекта отдельно от обычного кеша; он не воспроизводит Windows целиком.

Минимальный код имитации для воспроизведения в новом отдельном процессе:

```python
import sys, types, importlib.machinery
import app_backend
pkg = types.ModuleType('app_backend.converter_guard')
pkg.__package__ = pkg.__name__
pkg.__path__ = [REPO + '/app_backend/converter_guard']
pkg.__spec__ = importlib.machinery.ModuleSpec(pkg.__name__, loader=None, is_package=True)
sys.modules[pkg.__name__] = pkg
app_backend.converter_guard = pkg
import app_backend.converter_guard.comparison_worker
from app_backend.converter_guard.comparison_analysis import analyze_pair
result = analyze_pair(CSV_PATH, [CSV_PATH], 'csv')
```

В eager-варианте блок подмены package пропускается. Импорт инструментальных `sys/time/json/types/importlib.machinery/Path` выполнялся до внутреннего таймера импорта одинаково в обоих вариантах. Внешнее время охватывало весь `subprocess.run`, включая старт/выход Python и stdout, но не разбор JSON в родителе. Полные min/median/p90/max сохранены в соседнем JSON; вымышленных raw samples там нет.

## Вывод для дальнейшей работы

Текущий package init загружает конвертерные `adapter`, `core`, LibreOffice, маршруты и хранилище даже для одноразового CSV-анализатора. Их исключение из этого пути — обоснованный кандидат следующего небольшого патча. Можно исследовать ленивые публичные экспорты через `__getattr__` с кешированием классов, сохранив `__all__`.

До внедрения нужны проверки публичных импортов и идентичности классов, импорта worker в чистом процессе, разных порядков и параллельных импортов, frozen/PyInstaller и повторный Windows benchmark на том же наборе. **Сейчас это не реализовано.**

Windows scale-приёмка v21 отдельно показала 296,719 с анализа 1000 файлов. Этот Linux-пробник не доказывает причину разницы между хостами и не даёт права обещать такое же ускорение Windows. Он также ничего не утверждает о производительности LibreOffice или отсутствии утечек памяти/дескрипторов.
