# A.I.O — Guard v17: завершение маршрутов большого патча PR #40

Ветка: `patch/aio-master-bugbag-v16-20261024`. База продолжения: `2c97fa73070ad52b4474fa7824cf3e93eb6aeabf`. Изменения остаются в PR #40 относительно QA-ветки PR #15. Main и прежние workflows не изменяются.

## Исправленные пути

| Проблема | Реальное исправление | Проверка |
|---|---|---|
| ODF теряет столбцы | Во временной импортируемой копии явно объявляются столбцы только однозначных прямоугольных Writer-таблиц. Исходные XML, ресурсы и файл сохраняются. Проверка содержимого продолжает сравнивать с оригиналом. | Исходный проблемный ODT: 48/48 маркеров в DOCX, TXT и PDF. Подписи, объединения и неоднозначные таблицы не переписываются. |
| EMZ/WMZ теряют блоки | LibreOffice экспортирует обычный EMF/WMF. Guard проверяет все границы записей и EOF, создаёт GZIP и независимо сверяет SHA распакованных байтов. Повреждённый старый GZIP не ремонтируется. | Исторические потери блоков выявлены; новый путь проверен на реальных экспортах размером несколько МБ. |
| Межформатная анимация | Уже входящий в приложение Qt декодирует кадры, а потоковые контейнеры сохраняют последовательность, композицию, прозрачность, задержки и повторы. APNG, GIF, lossless WebP, TIFF; одинаковые контейнеры сохраняются побайтово. | 18 реальных преобразований: независимый хеш декодированных RGBA-кадров совпадает. Непредставимый профиль даёт конкретную ошибку. |

CLI сначала получает полный native FODS, затем потоковые снимки каждого листа. Кеши формул и отображаемые ошибки сохраняются. | Реальный ODS с двумя листами и отдельный контроль с тремя листами; повторный native CSV-import проверяет маркеры и числовые итоги. |

Обычный CLI-документный фильтр не выдаётся за графический экспортёр. | Контракты worker и отдельная обязательная Windows-проверка. Linux без UNO capability не объявляется поддерживающим этот маршрут. |

Новых зависимостей и внешних движков преобразования нет. HTML/ODC/очередь/сохранение/окно состояния из v16 сохранены. Прежние workflows не перенаправляются на другие машины.

## Приёмка через собственные Runner'ы

Добавлен отдельный одноразовый workflow `aio-pr40-v17-selfhosted-qa.yml` для PR #40. Он запускает сначала NIKITA, затем AIO-UBUNTU, проверяет непривилегированную учётную запись, свободное место, исходный Git tree и точный source SHA. Зависимости используются из существующей тестовой среды; установка пакетов, приложения и загрузка Actions artifacts не выполняются. Результат и JSON сохраняются в логах и локальной отдельной QA-папке. Это не расходует hosted runner minutes или заполненное artifact-хранилище.

В исходниках приложен неизменённый поднабор 20 реальных файлов FULLTEST с SHA256-манифестом. Полные 510 файлов в исходную ветку не копируются. Драйвер предпочитает явно известную локальную FULLTEST-папку и никогда не сканирует весь пользовательский диск.

Локальные результаты записаны в `AIO_GUARD_V17_SOURCE_VALIDATION.json`, `AIO_GUARD_V17_NATIVE_EVIDENCE.json`, `AIO_GUARD_V17_MEDIA_NATIVE_EVIDENCE.json`, `AIO_GUARD_V17_EPUB_NATIVE_EVIDENCE.json`. Windows/Linux runner verdict добавляется после реального выполнения, отдельно от локальных проверок.

## Границы форматов

ORP без установленного native exporter остаётся недоступным форматом. DBF ограничивает имена и типы полей; mixed-type столбцы в UNO сохраняются как Memo с сопровождающими исходными значениями и явным предупреждением. EPUB с шифрованием, активным содержимым, фиксированной вёрсткой и неподдерживаемыми интерактивными ресурсами отклоняется с причиной. GIF не принимает полупрозрачность, более 256 точных цветов или непредставимую длительность без потерь: такие случаи не получают ложный ready. Qt-бюджеты памяти и ограничения контейнеров дают конкретную ошибку.

Полный FULLTEST-510, визуальная GUI-приёмка и установочный EXE не подменяются этими точечными проверками. Массовое закрытие issues и готовность релиза без соответствующих данных не заявляются.
