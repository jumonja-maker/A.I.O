# B33 / B14: честная доступность HTML и отчётов Base

База QA: `e80cdb84b90f2737b492185a3eb22586570c9f8c`.

Строгие проверки пустого HTML, текста презентаций, изображений и локальных ресурсов сохранены. Установка NIKITA уже подтверждает рабочий `impress_html_Export` для текстовой презентации (v20 control); запрещать все презентации было бы ложным отказом.

Нативный preflight теперь без экспорта ограниченно обходит реальные shapes страниц. Текстовый HTML Impress предлагается для полностью инспектированной текстовой структуры. Графические/встроенные/неизвестные shape types требуют PDF либо отдельно проверяемого XHTML: обычный Impress HTML даёт текстовый outline и не сохраняет эти объекты. Для неподтверждённого профиля причина обозначена отдельно. Известный проблемный `draw_html_Export` не предлагается как рабочий HTML-маршрут Draw; XHTML не запрещён. Проверка не основана на расширении исходника. Конвертация повторно проверяет причину до запуска экспорта.

ORP явно описан как ReportDefinition LibreOffice Base. Writer/Calc/Impress не предлагаются как универсальные источники ORP. Настоящего положительного Base report fixture нет: **not_tested**, а не PASS.

Локально проходят профильные и соседние unit tests. NIKITA pending: 16 реальных текстовых HTML/HTM экспортов для 1–8 страниц, 32 обоснованные upfront exclusions презентаций с графикой и Draw, 3 строгих отрицательных проверки пустого HTML/утраты графики/отсутствующего ресурса, native v20 и соседние регрессии. Это синтетические контроли, а не отсутствующий исторический корпус. Полная визуальная эквивалентность HTML не заявляется.
