# A05 — Excel merge gate release-before-response, 30.10.2026

База: QA PR #83, 06fdb70fb10da3245137dc39301ea62cbd5b9041. Отдельный Draft PR, MAIN не изменяется.

## Причина
В `server.py` `merge_gate.release()` выполнялся только в `finally` после `return self._send(200, ...)`. Клиент мог уже получить HTTP 200 и послать следующий запрос, пока предыдущий поток ещё не дошёл до finally. Существующий Windows тест `test_idle_upload_fails_and_next_complete_merge_succeeds` зафиксировал такой отказ на CI #41090413225. Это не доказательство потери данных, но ложный конфликт 409 при быстром повторе.

## Изменение
После завершения `merge_xlsx` / обработки ошибки семафор освобождается **до отправки** HTTP 200/400/408/500. При исключении до ответа исходный `finally` освобождает его ровно один раз. Длинное объединение по-прежнему эксклюзивно до готовности результата, чужая работа не отменяется. Никаких изменений форматов, длительности обработки, данных, auth/host защиты или контроля полноты загрузки.

## Проверки
Сохранён исходный тест тайм-аута. Добавлены два последовательных HTTP 200 с немедленным проверяемым освобождением gate и повторной загрузкой без паузы. Точный Windows/Linux hosted CI — отдельный критерий, отсутствие полного PASS не считать приёмкой.
