# A.I.O — M02/M03: поиск Recovery без ожидания HTTP и ограничение списка

База: `1646af04841e409079d1bb52150ff10670dc31f1`, PR #83. Windows LibreOffice pin не меняется.

## Изменения

- Интерфейс явно запрашивает фоновый поиск через `GET /recoverable?background=1`. Обычный endpoint и прямой `recoverable()` сохраняют синхронный контракт совместимости.
- Один лениво запускаемый исполнитель проверяет прежние журналы и хеши. Повторные запросы не создают повторных сканирований; очередь LibreOffice не используется. Непроверенные результаты не публикуются как готовые. Уже проверенные сессии доступны при продолжающемся поиске.
- Ответ содержит `recoveryScan`: pending/scanning/complete/waiting_for_slot/error/closed. Ошибка диска не маскируется пустым списком; повтор после ошибки запускается только явной командой пользователя.
- При публикации проверяется текущая вместимость Guard: новая конвертация, занявшая последний слот во время чтения диска, не приводит к превышению лимита. Старая папка остаётся на диске и ожидает свободного слота.
- Завершение Guard прерывает потоковую проверку хеша и не принимает отмену за повреждение/основание спасения. Уже существующие проверки владельца, ссылок, пути, размеров и SHA-256 не ослабляются. Другие синхронные файловые операции при завершении всё ещё могут ждать текущего системного вызова.
- Прореживание сохранённых сессий для нового HTTP-пути использует существующую отложенную очистку, сохраняя квоту до физического удаления.
- Состояние показывает незавершённый поиск и кнопку повтора при ошибке. Опрос идёт одним таймером только пока окно открыто и поиск выполняется; закрытие, unmount и pagehide останавливают опрос и отбрасывают устаревшие ответы.
- Для M03 список пакетов получает уменьшаемую flex-ширину; полное имя остаётся в title. Это не новая история M04 и не полная переработка интерфейса.

## Проверки

Добавлены управляемые конкурентные тесты: медленное чтение, один исполнитель при частых запросах, независимый допуск новой очереди, гонка последнего слота, повреждение тех же размеров, отмена при завершении, сохранность файлов, прежний API и очистка. Отдельный тест настоящего production JS в DOM проверяет pending, polling, retry, коалесцирование запросов, закрытие и устаревшие ответы.

Подготовка сначала воспроизводит ожидание HTTP на неизменённом базовом core. Кандидат создаётся только после целевых тестов, без перемещения refs; подготовительные workflow/скрипт не входят в конечное дерево или историю QA-ветки.

## Границы

Проверки хешей не убраны и объём чтения не уменьшен: ускорен отклик списка, не заявлено ускорение самой проверки диска. Полный исторический FULLTEST 200/5723 и сопоставимый benchmark не выполнены. DOM-тест не проверяет пиксельную геометрию реального установленного GUI; M03 требует визуальной приёмки в обеих темах. M04, удаление До/После/BlackBox и остальной мешок остаются открытыми. MAIN, пользовательская установка и личные раннеры не меняются; пользовательский установщик и Releases/Actions Artifacts не создаются.
