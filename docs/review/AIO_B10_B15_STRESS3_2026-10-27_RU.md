# B10 / B15: отдельный remaining-bag stress3

Новый ограниченный runner объединяет только целевые проверки оставшегося мешка. Это не пользовательский FULLTEST 680×85, не сборка, не релиз и не перенос в main. Он требует совместного source candidate PR #67–#72, поэтому нативная проверка runner выполняется на отдельной интеграционной ветке.

Запуск разрешён только в новом каталоге; существующий корпус никогда не удаляется/перезаписывается. Сначала сохраняются фиксированные expected decisions. Далее создаются 24 нативных положительных OOXML (docx/xlsx/pptx, уровни 1–8), проверяются ZIP/source contracts, повторный настоящий native import и PDF с ещё одним native import. Макросов в этих контролях нет; их сохранение не сертифицируется.

Отдельные подкорпуса: все листы, DBF CP1251, JPEG aliases, TIFF 6/7/8, текстовый/графический HTML, session save/recovery/cancel, 4K/alpha/frame viewer в обеих темах и при 100/150% DPI. Их положительные/отрицательные/недоступные решения проверяются по точным числам и категориям; exit code 0 недостаточен. Источники и генераторы фиксируются по SHA256, размерам и относительным путям. Файл, изменившийся относительно отчёта, останавливает принятие корпуса.

Перед нативной матрицей создаются 12 дополнительных контролей реальных инертных парсеров и отдельного preview worker: оборванные ZIP/XML, DTD/entity без раскрытия содержимого, отсутствующий HTML resource, hidden/dynamic HTML, несовпадение текста, пустой результат, конфликт MIME, корректный Writer с чужим расширением, бюджет инспекции и SOURCE_CHANGED/RESULT_CHANGED. Их scope явно ограничен parser/identity, это не заявление о нативном отказе импортёра для каждого байта. Для неопределённых случаев фиксируется not_checked/uncertain; ложного checked нет.

Итоговые falseRejections/silentSuccesses равны нулю только при PASS всех заранее определённых контролей. При остановке они остаются null, а неполное доказательство не объявляется успехом. Подсчёт относится только к этому новому корпусу.

Для каждого завершённого контроля создаётся отдельная строка decisionIndex и pair-decisions.csv: ожидаемое/фактическое решение, scope, SHA исходника/выхода (если применим), SHA и точный JSON pointer первичного доказательства. Неопределённости и ожидаемые отказы сохраняются отдельными строками. При FAIL CSV содержит лишь завершённые проверки и не превращает неполный корпус в PASS.

Локальные контракты runner: 6 PASS. NIKITA интеграция pending. Исторический 680-file корпус, настоящая Base ReportDefinition, macro-bearing positives и ручная приёмка установленного EXE остаются not_tested. Они явно включены в coverageExceptions.
