# FULLTEST: M26 и M30, узкие исправления без дополнительных Guard-сканов

## M26 — PBM / PGM / PPM
- Только эти три исходных расширения запускают дешёвый PNM-зонд: первые 3 байта + Qt ImageReader.canRead/size; расширение само по себе ничего не доказывает.
- Qt создаёт пиксельный растр напрямую вместо рендеринга белого листа LibreOffice. Для остальных форматов исходного корпуса маршрут не меняется.
- Встроенная проверка медиа дополнена сравнением размеров первичного PNM и результата. Изменение холста больше не принимается.
- Нативный Windows-тест проверяет три исходных растра, точные пиксели и размеры PNG и отсутствие смены исходника.
- D11 всего 176 случаев, но новый механизм покрывает **только PBM/PGM/PPM**. Остальные PCD/PCX/RAS/XBM/XPM не считаются исправленными без тестов.

## M30 — точный коммит в отчёте
- В Windows EXE bundle включён `build-info/aio-source-revision.txt` с SHA из `AIO_QA_SOURCE_SHA` сборочного workflow.
- Отчёт Guard читает его один раз из `sys._MEIPASS`, когда приложение упаковано; старый явный `AIO_BUILD_REVISION` для тестов сохранён.
- Если подтверждённого SHA нет, отчёт честно оставляет `sourceRevision=null` и `basis=unknown`.
- Git/сеть не вызываются приложением в рантайме. MAIN и local runners не меняются.

**Границы:** текущий hosted native QA не равен 200×5723 исходному FULLTEST; сравним скорость/качество после повторной пользовательской приемки.

## CI-регрессии
- Native Windows тест PBM выявил неверное предположение о глубине: PBM исходно 1-битный, PNG может оставаться 1-битным без потери. Профиль теперь учитывает 1 бит, а для PGM/PPM глубина определяется только по ограниченному заголовку (8/16 бит).
- Windows выявил ранее плавающий тест EMF/EMZ: при изменении байтов без изменения размера метаданные NTFS могут остаться прежними. Теперь хеш исходного метафайла вычисляется в уже обязательном структурном обходе и сравнивается с хешем сжимаемых байтов. Тест делает мутацию после валидации детерминированно, а не по количеству вызовов отмены.
