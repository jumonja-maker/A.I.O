# A06 — восстановление без пользовательского FULLTEST, 31.10.2026

## Продуктовое решение

Владелец **повторно разрешил оставить и доработать A06** и запретил возлагать на него ручное тестирование аварийного восстановления. Код M02 (Guard Recovery) и M04 (SQLite-история отчётов) не переделываются. Это решение **заменяет** недавнее решение о штатном отключении A06 из PR #97; PR #97 не переписывается и не откатывается целиком, поверх него накладывается узкий QA-патч.

Главное UX-ограничение: **никакого автоматического появления старых файлов в текущей очереди** и никакого увеличения счётчика текущих несохранённых файлов. A06 имеет отдельную свёрнутую панель, доступную только при явном открытии в «Состоянии». M04 сохраняет только отчёты, без документов.

## Изменения QA

1. Штатный сервер снова использует `legacy-jobs` как постоянное хранилище A06. **При запуске не обходит и не хеширует прошлые каталоги:** только открытие A06 панели / явный запрос восстановления запускает полноценную проверку.
2. Новый авторизованный `POST /api/converter/rescan` повторяет поиск после разблокировки или исправления неполного журнала, не удаляя файлы и не публикуя невалидные результаты. Подтверждённые существующие билеты не отзываются или не импортируются повторно.
3. Непроверенные каталоги доступны по ручной кнопке извлечения уцелевших файлов. Новый `POST /api/converter/salvage` создаёт **отдельный ZIP с отчётом `RECOVERED_UNVERIFIED`**, без объявления успешной конвертации. ZIP независимо читается и проверяется по CRC/SHA; исходный каталог не меняется и не удаляется. Нет доступа к upload/original, следуем только известному `native/<index>/<index>/output`.
4. Повреждённые, занятые, удалённые или уже явно отбракованные каталоги не становятся `ready`; нельзя спасать каталог с подтверждённым retirement-marker. Лимит корневых каталогов учитывает физически оставшиеся каталоги даже до ручного сканирования; контролируется byte-budget.
5. API, сохранение и удаление по тикету остаются раздельными; уже сохранённые каталоги могут быть удалены только явной командой. Находки после аварии не изменяют M04/Guard.

## Что доказывает hosted CI

Автоматические регрессии проверяют restart/crash, два конкурирующих процесса, повторный scan, неполный журнал, отдельное извлечение ZIP, отсутствие ложного success, неизменность исходных байтов, ограничения пространства, два OS job, UI lifecycle и отсутствие автосканирования при первом открытии программы. Полный Windows/Linux hosted QA gate на точном source и merge SHA должен пройти **до** интеграции в QA. Пользовательский installed Windows GUI, USB/network/disk-full физически, исторический FULLTEST не являются частью приёмки A06; не заявлять, что они пройдены.

## Ограничения

Неизвестные файлы могут оставаться на диске до явного решения пользователя, а byte quota является кооперативной, не OS filesystem hard cap. Слишком большой аварийный набор нельзя безопасно упаковать, если квота не позволяет временную копию. A06 не заменяет основной Guard, не гарантирует визуальную идентичность результата и не является автоматическим резервным копированием. Ошибки и предупреждения A06 не считать несохранёнными файлами текущей сессии.
