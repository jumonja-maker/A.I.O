# B29 — строковые ID CSV/TAB/TSV → Excel

База QA: `e627c0fe3b8165ff6a5dd24d89845d8949ffb1b4`, с уже принятым B28.
Патч B29 отдельный: B30, UI, DBF, «До/После», сборка и релиз сюда не входят.

## Подтверждённая исходная проблема

Аудит стресс-теста №2 зафиксировал 96 ready-результатов: CSV/TAB/TSV, уровни 1–8,
в XLSX/XLSM/XLTX/XLTM. Исходное поле `001` импортировалось как числовая ячейка `1`
с General. Это не потеря при копировании файлов и не ограничение Excel.

## Изменение

1. Для содержательно подтверждённого импортёра `Text - txt - csv (StarCalc)`
   колонка с найденными значениями вида `001`/`+001`/`-001` получает документированный
   код Text (2), токен 5 FilterOptions. Остальные колонки не переводятся в текст.
   Возможность маршрута по-прежнему подтверждает загруженная нативная модель.
2. `legacy_import.validate_options` разрешает только ограниченную последовательность
   колонка/2; не добавляет разрешений на другие фильтры или произвольные параметры.
3. После экспорта в четыре целевых Excel-контейнера обязательная проверка сравнивает
   исходную строку и тип реальной ячейки по координатам, независимо от опциональной
   quality-проверки. Число 1, форматированное как 000, не считается строкой `001`.
4. Доказанное изменение/исчезновение ID даёт `ENGINE_OUTPUT_CONTENT_LOSS`.
   Неполная проверка даёт `CSV_TEXT_IDS_NOT_CHECKED` с причиной, не зелёный вердикт.
   Оригинальные файлы и готовые исторические результаты не переписываются.

## Границы (важно)

Это политика сохранения буквальной записи ведущих нулей, а не угадывание бизнес-схемы.
Вся выбранная колонка импортируется текстовой, включая её смешанные числовые строки;
только остальные колонки сохраняют прежнее нативное автоопределение.

Импортная подсказка использует максимум исходного 64-КиБ префикса и 256 записей.
Она не объявляется полным обследованием файла. Поздние ID проверяются независимо
после экспорта: их доказанную утрату нельзя пропустить как ready, однако этот патч
не обещает автоматически восстановить колонку, не попавшую в образец импорта.

Полный контроль ограничен UTF-8, однозначными разделителями, прямоугольной таблицей,
256 колонками, 100 000 строк, 50 000 ID и заданными байтовыми/временными бюджетами.
Это лимиты доказательства, не глобальные лимиты конвертации. Несопоставимые формы,
другие кодировки, сложные пакеты, превышение бюджета остаются явно непроверенными.
Полная визуальная идентичность, формулы, все прочие типы данных не сертифицируются.
