## Что подключено поверх PR #8

- `app_backend/server.py`: `ConverterGuard` и `GuardAPI` работают на том же проверенном loopback server и токене сессии, что A.I.O. Ветка сохраняет старые прямые /api/converter маршруты как контрольный путь, но новый UI направляет конвертацию в `/api/converter-guard`. Сервер закрывает процесс Guard при закрытии оболочки.
- `app_backend/converter_guard/http_api.py`: точное чтение частичных HTTP JSON тел через уже исправленный Windows-сервер; потоковый upload с прерыванием через событие, не через опасный Windows `SHUT_RD` (из прежней QA-регрессии).
- `src/converter-bridge.js`: inspect → индивидуальный план по fileId → отдельные потоковые upload исходников → /start → /jobs status v3 → native save → /saved → /release. Глобальное «выбрать всё» не размножает несовместимые маршруты каждого файла. До четырёх явно выбранных форматов native-попытки сохраняются даже при несовпадении расширения; подозрение по имени не является backend-отказом.
- `addons/file-converter/aio-converter-issues.js`: `skipped`/NATIVE_ROUTE_UNAVAILABLE отдельно от ошибок процесса; `undetermined` не объявляется недоступным.
- `app_backend/downloads.py`, `src/bridge.js`: разрешена только локальная и верифицированная форма Guard download URL с nonce `aioSave`; окончательное `saved` возможно только после подтверждения штатного Qt диалога/записи.
- `tests/test_guard_aio_integration.py`: дополнительные будущие регрессии схемы v3, токена/origin, частичных TCP фрагментов JSON, per-file plan, save-фильтра и привязки UI.

## Важные границы

1. **Это не scanner/quality-checker**. В PR #8 `qualityCompared=false`; Guard определяет native-модель и фильтрует направления, не сравнивает страницы, изображения и шрифты.
2. Если реестр неполон, native stdout/выбранный фильтр недоступен или формат неоднозначен, результат остаётся `undetermined` и обычный LO не блокируется.
3. Первоначальные подсказки не равны проверке реального содержимого. Выбор до четырёх форматов сохраняет возможность обхода подсказки по расширению; для широкого выбора применяется предварительная фильтрация. Полноценный явный UI override для переименованных файлов при выборе десятков форматов ещё не добавлен.
4. В `src/converter-bridge.js` метрика `filtered` из v3 относится к парам, зарегистрированным и затем пропущенным Guard во время выполнения. Маршруты, исключённые при составлении исходного индивидуального плана, не входят в `total`, поэтому метрика не сравнима напрямую с полным декартовым произведением.
5. Доступность фильтров зависит от установленной Windows-версии LibreOffice; авторские Linux числа 261→81 не являются обещанием для сборки NIKITA.
6. Ранее собранный NIKITA EXE был построен **без** нового Guard и **без** восстановленного ICO; для тестов нужен новый закреплённый Windows QA build. Существующий `aio-lo-direct-owner-windows-build.yml` закреплён за старым исходником — запускать его как A.I.O+Guard нельзя.
7. Старые сценарии `tests/native_ui_dom_smoke.mjs` предназначены для прямой ветки /api/converter и требуют адаптации/отдельного Guard DOM QA. Новые DOM/native Windows тесты **ещё не выполнялись**.
8. Обычные файлы пользователя не меняются: Guard обрабатывает временные копии. Excel остался независимым.
