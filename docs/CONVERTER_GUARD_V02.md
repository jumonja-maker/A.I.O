# Converter Guard v0.2 — отдельный модуль для интеграции 00AIO

Основа: рабочая ветка feature/libreoffice-direct-and-ui-geometry-20261019,

## Статус и совместимость с предыдущими патчами

Этот патч продолжает работу Guard из PR #2 на актуальной основе после интеграции
UI-патча #4. Он добавляет только библиотеку, необязательный HTTP-порт, тесты и QA.
Сервер AIO, интерфейс, Excel, прямой адаптер LibreOffice, установщик и workflows
не изменяются. Приложение продолжает работать через существующий ConverterTransport.
Новый Guard не импортируется приложением и не подключает свои маршруты автоматически.
ADVANCE и собственный рендерер отсутствуют.

Новый модуль является самостоятельным кандидатом вместо первой реализации Guard
из PR #2. Для него не нужен merge #2: старые UI/server/bridge-правки #2 не надо
переносить вместе с новым модулем. Ссылку на #2 можно передать как историю и контекст.
Это не готовый интегрированный Windows-релиз.

## Что делает Guard

Порт управления: загрузить неизменённый исходник на диск → последовательно
выполнить выбранные пары «файл / формат» через существующий native convert_path →
предоставить результаты по билетам → удерживать их до явного освобождения.

Для каждого исходника вызываются все заданные форматы. Разрешения по семействам
Writer/Calc/Impress отсутствуют. Вход BMP, PDF, неизвестное расширение и файл без
расширения не отклоняются до LibreOffice. Любое структурно корректное расширение
результата можно передать движку, даже если его нет в каталоге установленного LO.
Каталог экспортов — подсказка, не обещание совместимости каждой пары.

| Ситуация | Поведение |
|---|---|
| Один файл или формат не обработан | Ошибка только этой пары; остальные выполняются |
| Требуется пропустить зависший/долгий файл | cancel_file останавливает его собственный процесс и пропускает оставшиеся форматы этого файла; очередь продолжается |
| Отмена всего задания | Останавливается текущий процесс, оставшиеся пары отменяются; готовые результаты доступны |
| Отмена задания, ещё стоящего в очереди | Future отменяется сразу, без ожидания предыдущего LibreOffice |
| Несколько native-файлов результата, например HTML и картинки | Сохраняется исходная иерархия вспомогательных файлов в общем ZIP |
| Нет квоты на общий ZIP | Отдельные готовые файлы остаются доступны; packagingError = BUNDLE_QUOTA |
| Диалог сохранения отменён/скачивание оборвано | Результат и ticket остаются для повторной попытки |
| Host подтвердил завершённую запись на диск | confirm_saved меняет соответствующие ready на saved |
| release во время скачивания | Новые скачивания запрещены, открытый поток удерживает файлы до закрытия |
| Не удалось удалить временную папку | Владелец и квота сохраняются; следующая очистка повторяет удаление |

Сохранение одной картинки из HTML не означает сохранение всего HTML-результата.
Подтверждение сохранения общего ZIP помечает все входящие успешные результаты.
Скачивание, HTTP 200, открытие диалога и запуск download сами по себе не являются
подтверждением сохранения. Физическую запись должен подтвердить интегрирующий host,
например успешный Qt download; Guard не может доказать её по сообщению браузера.

Промежуточный процент LibreOffice не выдумывается: у выполняемой пары percent=null.
Процент задания означает долю завершённых пар, включая ошибки/отмену.
Во время сборки архива состояние packaging, finished=false, даже если все пары уже завершены.

## Ресурсы и стоимость работы

- Нет лимита МБ, страниц, числа файлов или времени конвертации по умолчанию.
  max_files, max_file_bytes, max_spool_bytes, file_timeout по умолчанию None.
  Явные ограничения задаются только через GuardLimits, не через UI.
- По умолчанию до 16 владельцев заданий. Это ограничение очереди и удерживаемых
  результатов, а не размер документа. Метаданные HTTP ограничены 1 МиБ,
  простой загрузки — 30 секунд без завершения очередного чтения; эти параметры
  также принадлежат GuardLimits и не являются дедлайном конвертации.
- Один рабочий поток и один процесс LO в активной паре. Параллельные задания
  не запускают несколько офисных процессов и не умножают их RAM.
- Загрузка, выдача и ZIP идут блоками до 64 КиБ. Нет document-sized bytes/Blob,
  распаковки Office, извлечения текста, превью и анализа шрифтов в основном пути.
  ZIP_STORED не пересжимает файлы; потоковые записи используют force_zip64=True.
- Временный исходник остаётся до последнего выбранного для него формата и затем
  удаляется, освобождая свою квоту. Единственный успешный physical output не
  копируется в дополнительный ZIP. При нескольких выходах ZIP занимает
  дополнительное место; отдельные outputs сохраняются для повторных скачиваний.
- Поиск исходника и билета выполняется через словари; дедупликация форматов
  линейная. Нет обхода всех исходных файлов при каждом upload/download.
- Журнал ограничен 512 событиями и не включает содержание или абсолютные пути.
  Обычный status не передаёт журнал; он включается только include_trace/trace=1.
- Import, создание Guard и инспекция не стартуют worker/LO/таймер. Политики
  времени/размера проверяются в существующем цикле ожидания native-процесса.
  Обход растущего output выполняется только при явно заданной byte-квоте,
  максимум два раза в секунду. При квоте None такого обхода нет.
- Рекурсивное удаление не держит общий lock метаданных. Освобождение может
  выполнять файловую операцию; GUI должен вызывать операции библиотеки через
  свой backend, а не синхронно в UI-потоке.
- Несохранённые результаты не удаляются по TTL. TTL 1800 секунд относится
  только к заброшенным заданиям без outputs и применяется при обращении.
  Фонового сканера чужих временных каталогов нет.

Квота — учёт зарезервированных входов, удерживаемых outputs, ZIP и известных
остатков неудачной очистки. Это НЕ жёсткая квота файловой системы или RAM LO:
профили, внутренние временные файлы LO, быстрый рост между проверками и внешние
ресурсы требуют дополнительного места. Без настроенной квоты OS disk-full
обрабатывается как ошибка хранения. Настройка file_timeout=None допускает долгий
документ, но без вмешательства пользователя зависший native-вызов может занять
очередь: для этого предусмотрены cancel_file и явно настраиваемый дедлайн.
Автоматического «документ завис» по отсутствию выдуманного прогресса нет.

Guard хранит задания только в памяти текущего процесса. Восстановление очереди
после аварии ОС, долговременное хранилище и очистка после crash не реализованы.
Закрытие/сброс в штатном режиме освобождает только собственные каталоги.

## API библиотеки

    from app_backend.converter_guard import ConverterGuard, GuardLimits

    guard = ConverterGuard(limits=GuardLimits())
    metadata = [{"id": "f1", "name": "image.bmp", "size": source_size}]
    snapshot = guard.create(metadata, ["pdf", "png"])
    job_id = snapshot["jobId"]
    with source_path.open("rb") as stream:
        guard.upload(job_id, "f1", stream, source_size)
    guard.start(job_id)
    # Опрос backend-ом: guard.status(job_id); готовность: finished.
    # При необходимости: guard.cancel_file(job_id, "f1") или guard.cancel(job_id).
    # Скачать: with guard.open_result(ticket) as (stream, name, size): ...
    # Только после подтверждённой записи: guard.confirm_saved(job_id, ticket).
    # После осознанного освобождения результатов: guard.release(job_id).
    # При завершении приложения: guard.close().

upload требует точный размер и читает ограниченными блоками. Для собственного
блокирующего stream интегратор обязан передать interrupt=callable, который
разбудит read при отмене. Сам Guard не может прервать произвольный пользовательский
read. Необязательный HTTP-порт уже передаёт shutdown(SHUT_RD) для такого случая.

Нативный адаптер использует существующие libreoffice_engine.py/native_process.py.
Отдельный собственный конвертер, UNO-сервис или новый движок не добавляется.
LibreOffice получает оригинальные байты и выбранное расширение; параметры
экспорта, текст, страницы, изображения и поля не реконструируются Guard.
В свежем профиле отключены макросы. DisableActiveContent не применяется,
поскольку ранее такая настройка скрывала формулы. Это не ОС-песочница.

Качество/потери остаются свойствами native-экспорта. PDF-профиль без потерь,
CSV dialect/encoding, диапазоны листов/страниц и пользовательские options
этим патчем не реализованы. options отклоняются явно, не игнорируются.
Готовый output не объявляется «без потерь» по сигнатуре/извлечённому тексту;
qualityCompared=false в отчёте. Например, экспорт таблицы в CSV в QA сохранял
только первый лист, а BMP в PNG использует native-полотно Draw. Продуктовые
предупреждения и параметры надо сохранить при будущей интеграции интерфейса.

## Необязательный HTTP-порт

GuardAPI(guard, origin="http://127.0.0.1:PORT", token=session_token) не создаёт
сервер сам. Его можно смонтировать на текущий loopback server при отдельной
интеграции. Методы get(handler, path)/post(handler, path) используют обычный
BaseHTTPRequestHandler и host._json(status, object). Нужен точный Host/Origin,
X-AIO-Token; скачивание разрешено только по случайному ticket владельца.
Неоднозначный Content-Length/Transfer-Encoding не принимается.

| Метод и путь /api/converter-guard | Назначение |
|---|---|
| GET /status | Версия, доступность, политики и счётчики; без запуска движка |
| POST /inspect {files} | Метаданные и native-каталог, без чтения документа |
| POST /jobs {files, formats} | Создать; formats по умолчанию ["pdf"]; допустим одиночный formatId |
| POST /input?job=ID&file=FILE | application/octet-stream с точным Content-Length |
| POST /start {jobId} | Запустить очередь |
| GET /jobs?job=ID[&trace=1] | schemaVersion=2, файлы/targets, outputs, state, finished |
| POST /cancel-file {jobId,fileId} | Пропустить один исходник и продолжить очередь |
| POST /cancel {jobId} | Отменить задание с сохранением прежних outputs |
| GET /result?ticket=T | Поток файла; не подтверждает сохранение |
| POST /saved {jobId,ticket} | Подтверждение записи от host; допускает повтор |
| POST /release {jobId} | Запретить новые скачивания, освободить после I/O |

При завершении сначала api.close(), затем guard.close(): сокеты надо разбудить
до ожидания аренды файлов. Готовые файлы доступны по отдельным ticket даже во
время следующих конвертаций. Для использования текущего native-диалога Qt новый
путь /api/converter-guard/result должен быть явно добавлен в download-allowance;
данный патч не расширяет разрешения существующего UI/Qt автоматически.

## Как 00AIO подключать этот модуль

1. Перенести новый модуль и тесты поверх актуальной direct-ветки. Не сливать
   старые UI/bridge/server-изменения PR #2 как обязательную зависимость.
2. Создать один Guard на время жизни backend и смонтировать API на существующий
   origin/token. Не запускать ConverterTransport и Guard на одном задании.
3. Адаптировать bridge к асинхронным create/upload/start/status и вложенным targets.
   Общие formats применяются ко всем файлам задания; разные наборы цветных групп
   нужно оформить отдельными заданиями или отдельным последующим контрактом.
4. Сопоставить состояния ready/saved/cancelled/packaging с уже принятым дизайном,
   связать saved с подтверждением Qt, сохранить отмену диалога и повтор.
5. Провести Windows/Job Object/native-save/installer приёмку по точному SHA
   отдельным согласованным запуском. Этот PR сам NIKITA не запускает.

## Проверки

Обычный Python-набор включает Guard и исходные Excel/HTTP/UI-контракты:

    python -m unittest discover -s tests -v
    python -m compileall -q app_backend tools/qa
    node --check src/converter-bridge.js

Для DOM включить AIO_DOM_MODULE с уже установленным QA-пакетом linkedom.
Реальный синтетический прогон:

    python tools/qa/guard_v02_native_acceptance.py --work /new/empty/directory

Он проверяет обычные и неизвестные входные расширения, несколько экспортов,
ошибку первого файла, пропуск реально запущенного native-файла, HTML companions,
DOCX >20 МиБ / набор >50 МиБ, исходные байты на каждом запуске, ZIP-содержимое,
реальный HTTP→файл→saved→release. Контрольный двухстраничный PDF сравнивается
с прямым CLI-экспортом по тексту, страницам, встроенным изображениям и, при
наличии Poppler, пикселям обеих страниц. Это синтетическая проверка нескольких
документов, не гарантия полноты произвольного пользовательского документа.

Численные результаты: docs/review/GUARD_V02_VALIDATION_2026-10-19.json и
docs/review/GUARD_V02_NATIVE_EVIDENCE_2026-10-19.json.
Контролируемые CLI-тесты deadline/quota проверяют процессы фикстуры, а не
настоящий LibreOffice. Native QA отдельно использует установленный LibreOfficeDev.
Windows, установленный EXE, NIKITA, GUI-интеграция и полный корпус — NOT_RUN.
Проверка всех возможных пар всех расширений каталога также не заявляется.

Существующий source workflow запускает только Excel/clean-foundation;
Guard/DOM/native наборы автоматически в него не добавлены. Workflows защищены
и не меняются; зелёный старый CI не означает выполнение всего списка выше.
