# Восстановление значка и Эльвы — передача 00AIO

Основа патча: `feature/libreoffice-direct-and-ui-geometry-20261019`,
`af1065687ff2ac25c57037f03106c7bc1dc7392b`. Это независимое исправление ресурсов:
оно не требует интеграции Guard, изменения движка, workflows или Advanced.

## Причина и исправление

В новый репозиторий попала только миниатюра Эльвы размером 3176 байт. Она
использовалась в интерфейсе и в QIcon; PyInstaller не получал значок EXE.
Поэтому изображение в окне было размытым, а Windows не получал нужный ресурс
приложения и ярлыков.

Восстановлены оба точных оригинала из старого `jumonja-maker/All-in-One-`,
commit `7856c110b0898c578530bc0c72ae5e065b4f2cfd`, каталог `assets/brand`:

| Файл | Оригинал | SHA-256 |
|---|---|---|
| aio-new-brand-source.png | 1254×1254 RGBA, значок приложения | 34b6491b56bae5f5eb7c014e0bcd7ede3151c0daff11d6732904ed225a5e0f37 |
| elva-v13-happy-source.png | 1254×1254 RGBA, персонаж Эльва | 87e2b8dc069bee52ec796ea03d31e618789b64ffeb9c8a66ea50f09f49db42c5 |

Байты и Git blob IDs совпадают с архивом. Персонаж, эмблема и цвета не
перерисованы; увеличения старой миниатюры нет. Источник и хэши производных:
`assets/brand/BRAND_PROVENANCE.json`.

- В шапке — прозрачные PNG 64/128/256/512 с `srcset` по ширине и `sizes`,
  соответствующим CSS. Браузер выбирает разрешение по физической плотности
  и масштабу, не загружая оригинал 1254 px для маленькой плашки.
- `src/branding.js` использует отдельный значок приложения для favicon и
  контракта native host; изображение персонажа не подменяется favicon.
- Для окна/QApplication и Windows создан настоящий ICO с 32-битным alpha:
  16/20/24/32/48/64/128/256 px.
- `AllInOne.spec` включает ICO в EXE и проверяет его наличие до сборки.
  Существующее включение assets сохраняет все необходимые ресурсы в `_internal`.
- Оба Inno Setup-скрипта используют ICO для Setup, удаления и двух ярлыков:
  рабочего стола и меню «Пуск». Пути указывают на упакованный ресурс.

Ресурсы уже подготовлены и включены в git. `python tools/build_brand_icons.py`
пересоздаёт их локально из проверенных оригиналов. Используется Qt, который
уже входит в зависимости приложения. Новых runtime-библиотек, обработки
изображений при запуске и сетевых запросов не добавлено.
Оригиналы занимают около 3.45 МБ на диске; обычный интерфейс их не декодирует.
Для используемой в QA картинки 128 px требуется 64 КиБ декодированных пикселей,
для 256 px — 256 КиБ, вместо 6.3 МБ для полного RGBA-оригинала.

## Приёмка

| Проверка | Результат |
|---|---|

| Оба SHA-256, PNG alpha, все размеры ICO | PASS |
| Реальная раздача PNG/ICO через сервер | PASS, правильные байты и MIME |
| Подключение ресурсов в spec и обоих .iss | PASS, статическая/изолированная проверка |
| QIcon в настоящем Qt | 8 размеров, 256 px пиксельно совпал с исходным app mark |
| WebEngine, светлая/тёмная темы, масштаб | PASS при devicePixelRatio 2/3/4 |
| Окно Windows, упакованный EXE, установленные ярлыки | NOT_RUN |

Native QA выполняется `tools/qa/brand_native_acceptance.py` при явном запуске.
В `AIO_BRAND_QA_OUTPUT` укажите новый пустой каталог. Для проверки плотности
использовался `QT_SCALE_FACTOR=2` и zoom 1/1.5/2. Метаданные сохраняются без
случайного порта: [Qt evidence](review/BRAND_NATIVE_2026-10-19.json).
При изменении масштаба проверка ждёт загрузки подходящего физического размера,
а не считает успешным один лишь HTTP 200.

Windows-сборка и проверка установленного ярлыка остаются отдельным шагом для
00AIO. Статическая проверка spec/.iss и Linux QIcon не доказывает работу
установщика Windows. NIKITA и owner-only workflows не запускались.
Существующая установленная версия не меняется от добавления патча: для неё
потребуется новая проверенная сборка.
