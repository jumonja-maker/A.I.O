## Что считается проверенным результатом

Поддержанный маршрут должен сохранить исходник, выполнить преобразование с отменой и контролем места, проверить применимые свойства результата, сохранить необходимые файлы-компаньоны и проверить сохранённую копию. Подтверждённая потеря обязательных данных не должна превращаться в «Готово». Успешное создание файла, проверка его структуры, успешное чтение и визуальная эквивалентность — разные уровни проверки.

Ошибка адаптера AIO исправляется в коде AIO. Ограничение формата показывается как ожидаемая потеря. Неподтверждённая совместимость импортёра LibreOffice остаётся явно неподтверждённой. Печатное обрезание таблицы не называется потерей исходных значений; безопасный отказ не называется успешной конвертацией. Полная совместимость макросов, произвольной вёрстки, шрифтов и всех встроенных объектов не сертифицируется.

## Изменения патча

### C01. Один бюджет импорта для одиночной и массовой подготовки

При 32 и более источниках прежний код молча сокращал native import до 15 секунд вместо настроенных 120. Специальный предел удалён; явный пользовательский бюджет, отмена, прогресс и блокировка конфликтующих действий сохранены. Регрессия с корректным 20-секундным импортом падает на основе и проходит с исправлением.

Два точных XHTML из диагностики проверяются через API и реальный массовый Qt-интерфейс: 32 файла проходят native PDF, сохранение папки и независимое чтение. Маркеры включают уровень, `00123`, `12345678901234567` и `Москва`. Этот отдельный UI-контроль не выдаётся за прогон всего корпуса 178 файлов; текущий корпус имеет собственный драйвер и протокол.

### C02. Маршруты ODM/OTM/ORP требуют реального подтверждения модели

Обобщённый LOK TEXT объединяет Writer, Writer/Web и GlobalDocument. Одного такого объединения либо расширения недостаточно для master/report-экспорта. Нужны подтверждённая native-модель, применимый фильтр и актуальный registry fingerprint.

Добавлено узкое распознавание успешно загруженного LOK OTHER вместе с проверенным ODF master MIME/body. Оно разрешает содержательно подтверждённый GlobalDocument, сохраняя отказ для обычного Writer, неоднозначного объединения сервисов и устаревшего доказательства. Минимальные корректные master-контроли реально загружаются в Linux LOK и дают PDF с маркером. Четыре пользовательских ODM/OTM проходят структурный контракт, но локальный native load по-прежнему возвращает null; положительный минимальный контроль не подменяет их совместимость.

Отдельный настоящий Base ReportDefinition и storage-путь описаны в C12. Прежнее утверждение «настоящего положительного ORP нет» устарело: реальный образец и native API-доказательство получены. Продуктовый Windows worker уже подтверждён отдельным rare-прогоном на `2421713`; итоговая матрица повторяет этот обязательный контроль на окончательном SHA.

### C03. PCX DPI и геометрия PCD/PCT/TGA

PCX с заголовком 100 DPI превращался в PNG около 96 DPI. Теперь оба DPI сохраняются в QImage и независимо проверяются у поддержанных PNG/APNG/TIFF/BMP/JPEG с учётом округления самого формата. Для выходов без подтверждённого физического масштаба ограничение перечисляется явно.

Содержательно подтверждённый TGA получает растровый маршрут без A4-холста Draw. PhotoCD использует ограниченный Pillow Base decoder: **768×512 либо поворот 90/270°**. Высшие слои 4Base/16Base и выше не объявлены поддержанными; неизвестная ориентация или усечённый Base не принимаются как корректный результат. `MEDIA_PHOTOCD_BASE_ONLY` показывается в обычном интерфейсе даже без quality-summary и технических resultChecks.

Для PCT native GraphicExportFilter ограничен подтверждённой единственной графической фигурой: известный QuickDraw frame, без обрезания/вращения/деформации. Текущие пользовательские PCT выявили реальную потерю RGB: в Windows `42544055441` четыре PCT→PNG/TIFF случая имели правильный canvas, но изменённые пиксели. Старый uniform-black 37×19 контроль этого не обнаруживал. Java UNO показал импорт VECTOR/XGraphic с SizePixel 0×0: native renderer ресэмплирует bitmap. Его PrefSize соответствует **641×401 / 1101×761 при 72 DPI** вместо frame 640×400 / 1100×760. Это согласуется с inclusive extent **+1** в [официальном ipict.cxx установленного commit](https://github.com/LibreOffice/core/blob/2c87e51eeaa2b413ff4ae097b2705eea1995d8e5/vcl/source/filter/ipict/ipict.cxx#L1268) и последующим [SetPrefSize](https://github.com/LibreOffice/core/blob/2c87e51eeaa2b413ff4ae097b2705eea1995d8e5/vcl/source/filter/ipict/ipict.cxx#L2013). Отдельный Bugzilla ID не выдумывался. Antialias on/off не восстановил исходные байты.

Исправление — узкий содержательный decoder только для self-contained PICT v2, одного DirectBitsRect, 3×8 RGB, planar PackBits, полного прямоугольного clip и без дополнительных drawing opcodes/transforms/ICC comments. Проверяется весь поток; ≤32 MiB, ≤16M pixels, bounded построчная обработка с отменой. Extended header и PixMap 16.16 DPI должны согласоваться. Qt writer получает исходные RGB, а Pillow независимо проверяет результат по RGB hash и непрозрачности до ready. Другие/vector/mixed PICT сохраняют native защищённый путь; это не общий PICT renderer.

Семь hand-authored тестов покрывают literal/repeat/NOP PackBits, разные форматы, DPI72×100, неизвестные opcodes/clips/transforms/comments, повреждённые/переполненные строки, canvas/cancel, corruption/alpha и renamed content. Все четыре настоящих PCT PNG/TIFF теперь совпадают по RGB с независимым PCX reader; **72 DPI** сохранён. Полный локальный 32-case fidelity: 30 успешных конвертаций, 2 явных Linux PPT safe refusals, 0 FAIL, исходники неизменны. Windows `42547471560` на `2421713`, затем `42550237123` на `3fb5c56346b66aaa25a17d01181897af5decbe97` подтвердили **32/32 текущих fidelity-контроля**, включая все четыре PCT pixel/canvas/DPI случая; исходные SHA неизменны. Это фактический результат исправленного bitmap-пути, отдельный от прежнего Windows FAIL. Полная матрица финального SHA повторяет эти обязательные проверки.

### C04. Единая политика GIF

Ранее Qt-путь запрещал молчаливое уменьшение палитры, а native GIF мог превратить сотни цветов в 256. Теперь native-страницы сначала экспортируются в PNG, затем проходят тот же точный GIF encoder. Более 256 цветов, частичная прозрачность и неподтверждённый профиль не превращаются в скрытую потерю.

Проверяется весь набор страниц до публикации, манифест обновляется на фактические GIF. Подтверждение относится к кодированию native PNG, а не к полной правильности предшествующего рендера LibreOffice. Допустимая потеря страниц при static JPEG/BMP и DPI представленной страницы проверяются отдельно. Текущие GIF имеют собственный независимый контроль кадров/значений; это не сертификат произвольной анимации.

### C05. DBF: кодировка, Memo, заголовки и EOF

Строгая представимость CP1251 проверяется по фактическим текстам, заголовкам и отображаемым значениям целиком, а не только по первым строкам или locale. Для подтверждённого немемо-листа используется native Windows-1251, LDID C9 и matching CPG; остальные Unicode/Memo-сценарии сохраняют UTF-8 с CPG и предупреждением о выборе кодировки. Байты значений после LibreOffice не перекодируются; изменяется только подтверждённый байт метаданных до окончательного манифеста.

Кириллица вне CP1251 не заменяется вопросами. Проверяются поздние строки, формулы/ошибки, смешанные столбцы, Memo, mapping-файлы и ZIP/Folder-save. Windows CRT мог удалить DBF EOF `0x1A` при текстовом `os.open`; оба пути теперь используют `O_BINARY`. Регрессия допускает изменение только LDID, сохраняя строгую проверку остальных байтов.

Native auto detection LibreOffice в проверенных средах игнорировал CPG/LDID. Патч не обещает исправить чужой импортёр одними метаданными. Независимое чтение DBF/DBT и повторный native import с явной кодировкой записываются отдельно от default LO. На Windows в `42544055441` все 10 прежних DBF-контролей, включая Memo/schema/сохранение, прошли; GDAL/OGR на этом runner отсутствовал и не засчитывается как выполненный внешний потребитель.

### C06. Неподвижная компоновка и видимые ограничения качества

Убраны принудительные 640px минимальной высоты панелей и рост всего конвертера. Рабочая область использует доступную высоту; длинные списки имеют ограниченную внутреннюю прокрутку. Слот кнопки конвертации не перемещается после сохранения или отмены диалога.

Счётчик, фильтр, добавление файлов и корзина находятся **в одной строке с общим вертикальным центром**. Добавление видно и в пустом списке. Резерв счётчика выдерживает `4096/4096` и `10000/10000`, не выталкивая кнопки вниз. В узкой панели остаются доступные подписанные иконки, на desktop — полные подписи. Внешний document не получает прокрутку; `overflow: clip` также устраняет программный скачок при Tab/scrollIntoView, а доступ к содержимому остаётся внутри рабочей области.

Выявленная на Windows разница шрифтов резерва `ch` и счётчика устранена: число и слот используют одну family/17px/700/tabular-nums, кнопки — явный 13px шрифт. Проверка полной ширины не заменена обрезанием текста. Проверяются пересечения, реальные hit targets, фильтр, Tab, темы, zoom, narrow viewport и отдельный Qt scale 150%; это не проверка всех физических мониторов/DPI.

Обычная строка результата показывает применимые факты, readback сохранённой копии, ожидаемые потери и непроверенные свойства. Объект quality не скрывает предупреждения. «Готово» не означает полной эквивалентности расположения, шрифтов, анимаций и макросов.

### C07. Свежие обходы места без прежнего замедления Windows

Полные свежие обходы перед допуском, native-экспортом, упаковкой и публикацией сохранены; TTL-кеша размеров нет. Файлы суммируются при scandir, в стеке остаются каталоги. Их тип повторно проверяется перед спуском; бюджеты глубины/числа записей, отмена и учёт чужих файлов остаются.

Повторный полный `lstat` каждого отложенного каталога давал заметное замедление Windows. Для этой узкой повторной проверки применяется свежий `GetFileAttributesW`: отклоняются reparse и смена типа, пропавшие пути пропускаются, прочие I/O-ошибки не скрываются. Метаданные файлов и байты не кешируются; корень и размеры файлов сохраняют соответствующие проверки. Реальный Windows junction-контроль выполнен, POSIX сохраняет `lstat`.

Windows A/B `42542072466`, HEAD `acc0e33`, 4 000 чужих файлов и пять чередующихся пар: synthetic transport **4731,992 → 4695,791 мс**, одинаковые 406 обходов и хеши содержимого. Прежнее ухудшение около 26% на этом контроле устранено. Плоский обход: **4,961 → 4,005 мс**, Python traced peak **1 567 170 → 2 472 байт**. Отдельный directory-heavy обход всё ещё медленнее базы на 5,74% без token и 11,89% с token; универсальное ускорение обходов не заявляется.

Настоящий CLI batch: медиана **30,366 → 29,488 с**, три пары, семантические хеши совпадают. Разница около 2,9% может включать вариацию native engine; ускорение самого LibreOffice не доказано. Холодный диск, SMB, native peak RSS и многопроцессное соперничество этим A/B не проверялись. FT4-07/G05 нельзя закрыть одним быстрым плоским scandir.

### C08. Обычный упакованный desktop

Portable frozen driver запускает обычный EXE, использует локальный Qt DevTools, загружает RTF через интерфейс, получает PDF и независимо читает маркер. Внешние engine overrides удалены, требуется bundled LibreOffice. Сохраняются screenshot, обычный WM_CLOSE и проверка завершения принадлежащих приложению процессов до принудительной уборки.

Этот контроль успешно выполнялся в прежнем полном Windows CI `42538020271` на `6e2ac614`; он остаётся историческим доказательством этого SHA. Он не означает прохождения нового финального кода, установки через installer или работы системного Save-диалога. Для установки добавлен отдельный C15.

### C09. Работающая конвертация отрицательных Decimal в DBF

CSV `000123,-12.750` прежде давал native width/export failure. Теперь на приватной UNO/FODS-копии вычисляются ширина, знак, десятичный разделитель и scale по всем числовым строкам; Date/Logical/Currency/Percent не подменяются числовой схемой. Целевые поля задаются явно, а до публикации независимо сравниваются схема и точные Decimal каждого числового значения. Оригинальные заголовки/байты исходника не переписываются; побочный mapping сообщает выбранные поля.

Эмпирическая граница native dBase — ширина **до 19**, scale **до 15**; случай N20 не объявляется поддержанным, поскольку native exporter его сжимал. Неоднозначность/выход за границу даёт явный отказ. Проверки имеют бюджеты, адаптивные chunks и отмену, включая повторённые FODS-строки.

В `42544055441` все четыре новых Windows native-контроля прошли: 132 строки с поздним `-999.990`, ведущие нули, Date/Logical/Memo, оба оригинальных CSV из текущего корпуса и готовый ZIP с точными `-12.750/0.125`. Физический DBF reader и native повторный импорт подтвердили значения. Прежнее описание этого случая как единственного безопасного отказа устарело: в проверенной границе конвертация теперь работает. Новая итоговая матрица должна повторить это на окончательном SHA.

### C10. PSD как проверенное сводное RGB-изображение

Два текущих PSD независимо читаются Pillow как 640×400 и 1100×760, но bare native LibreOffice в локальной сборке не открывал их. Добавлен ограниченный содержательный путь для 8-битного трёхканального RGB merged composite: проверяются размеры, структура, бюджеты и применимые ICC-метаданные. CMYK, 16-bit, alpha и неподтверждённые профили не получают молчаливого допуска.

PNG/TIFF независимо совпадают с исходным RGB по размерам и всем пикселям, в том числе с парными PCX/TGA из корпуса. Четыре PSD-контроля на Windows `42544055441` прошли. Это экспорт объединённого изображения, а не сохранение редактируемых слоёв, масок и эффектов; явное предупреждение остаётся видимым. PSD→PDF не объявляется поддержанным только потому, что исправлен PSD→PNG/TIFF.

### C11. Освобождение native LOK-документа после проверки

На повторной проверке одного пути HTML/CSV/DIF/TAB/TSV/DOCX/FODT старый worker оставлял собственный `.~lock`, после чего следующий native load мог вернуть null. ### C14. Текущий корпус, честный PDF-readback и печатные ограничения

Первичный драйвер проверяет каждый из 178 исходников, route/model proof, SHA до/после, факт завершения всего набора и применимое независимое чтение PDF. При этом PDF визуально корректен, а стандартные BDC/EMC `/ActualText` строки UTF-16 явно задают «и»/«й». PyMuPDF и Poppler независимо читают все исходные параграфы правильно. pypdf6.10/6.21 и частично Qt PDFium не учитывали replacement semantics. Четыре точных PDF восстановлены из bounded Base64 chunks с проверкой SHA; их данные и native PDF filter settings не изменялись.

QA-only fix учитывает **ActualText как замену всей marked sequence**, без эвристической подмены «й» на «и» или удаления управляющих символов. Поддержаны UTF-16/PDFDocEncoding, пустой replacement (discretionary hyphen), balanced nested BMC/BDC/EMC и named properties; malformed/unbalanced/invisible/неподтверждённые spans дают UNCERTAIN. Подавленный текст нельзя вернуть обычным raw extractor как fallback. Пятнадцать регрессий проходят на обеих версиях pypdf; **все четыре Windows PDF теперь проходят прежнее строгое сравнение всех уникальных исходных параграфов**, что независимо подтверждено PyMuPDF/Poppler. L1 содержит13 ActualText spans, L2 —77/16/68 по страницам. Некоторые consumers без ActualText могут по-прежнему извлекать эти glyph sequences неверно; универсальная совместимость readers не заявляется.

Повторное чтение **151 ранее созданного Linux PDF** после добавления HTML source parser: **34 PASS**, **6 подтверждённых печатных пропусков**, **111 NOT_CHECKED** без независимого parser исходника. Это подтверждено PyMuPDF, Poppler и координатами PDF. `57.0 → 57` — формат отображения, не потеря числа. Нужны явные ширина/перенос и проверка диапазона печати/предпросмотра в исходной таблице; автоматическое изменение макета не добавлялось. ### C16. Совместимость корректного prefixed OOXML через приватную CT-копию

На десяти актуальных DOCM/DOTM/PPTM/POTM/PPSX двух уровней оригинальный native import не определял модель. В `[Content_Types].xml` namespace OPC корректен, но элементы записаны с `ns0:`. Production сначала пытается открыть оригинал. Только после подходящего фактического native import failure и распознанного OOXML-контракта создаётся ограниченная приватная копия; она заново проходит native model/filter/registry/source-contract gate. При conversion эта копия воспроизводится с проверкой original SHA и prepared SHA из preflight. Postconditions и VBA-контракт читают оригинал. Обычный интерфейс показывает `OOXML_PRIVATE_CONTENT_TYPES_NAMESPACE`; сообщение не обещает качество всех объектов документа.

Подписанные/зашифрованные/двусмысленные пакеты, неизвестные namespace/атрибуты/элементы/ZIP extra, DTD/PI/comments, дубли/case/URI aliases и external relationships не переписываются. Бюджеты: 128 MiB ZIP, 256 MiB expanded, 8192 members, 1 MiB на CT/relationship part, 4 MiB metadata суммарно. Отмена действует между chunks. Явная spool quota контролирует приватную ZIP при записи, затем её фактический размер вычитается из допуска native output. Copy не добавляет новые маршруты и не обходит исходные проверки модели.

Тринадцать unit-тестов проходят; DOM показывает предупреждение без technical/quality summary. Local product-native proof: **12 PASS** — десять текущих originals, подлинный licensed POI Word VBA с prefixed CT и равными потоками, отказ для signature-marker package. Ещё один реальный quota-контроль при 1 байте дал SPOOL_QUOTA **до запуска native exporter**, исходник неизменен. Windows driver объединяет все **13 обязательных сценариев** и требует настоящие UNO positives. В `42550237123` на `3fb5c56346b66aaa25a17d01181897af5decbe97` **все 13 прошли**: десять оригиналов, подлинный Word VBA, signature-marker refusal и quota guard. Прежние четыре Word QA-ошибки исчезли после поддержки стандартного ActualText; native PDF settings и исходные документы для этого не менялись. Маркер подписи проверяет отказ от переписывания, а не криптографическую валидность подписи. Источники и все проверенные части сохраняются; визуальный layout и работа VBA не сертифицируются.

После восстановления этих десяти остаются восемь ODF-family source gaps. На четырёх ODM/OTM проведены восемь свежих Java UNO probes: auto-load вызывает **BrokenPackageRequest**, ремонт отклонён, модель не создана; явный зарегистрированный writerglobal8(_template) также возвращает null. MIME/manifest/body согласованы, но это не доказательство полной package/schema validity; безопасного filter-hint исправления не найдено. OTH объявляет незарегистрированный `text-web-template` вместо native `text-web`. ODF содержит office-wrapper вокруг MathML вместо обычного native MathML root; полная схема не проверена. Автоматическое исправление/ремонт этих восьми источников не добавлялось. Точные SHA и результаты: `odf-gap-package-review.json`, `routes/master-java-native/evidence.json`.

## Передача и применение

Накопительный standalone patch формируется как `git diff --binary b7216d1210489a5fd1eadb21daf2e3b3849e30f4..patch/converter-completion-20261109`. Точные commit endpoints и SHA самого diff указаны в завершающем протоколе. Это единый diff для указанной чистой основы; он не применяется поверх уже содержащего его коммита и не переносится на историческую MAIN без зависимостей. Применимость проверяется на отдельном чистом checkout, а содержимое ZIP — по manifest/SHA и повторному чтению.

В передаваемый архив входят DOCX/MD/PDF, diff, README с точной основой/головой, исходные provenance, итоговый и промежуточные CI/native JSON, существенные журналы и ограниченный набор screenshots. Точный final head и окончательный Windows/Ubuntu статус фиксируются в завершающем протоколе после заморозки кода; успешные тесты одного SHA не переносятся на последующие изменения молча.

Следующему чату сначала следует открыть PR #104/точный SHA и прочитать итоговые machine reports. Не начинать повторно с исторической MAIN, retired-модулей или уже исправленных D01–D09. Для оставшегося дефекта фиксируются конкретный original SHA, target, recipe/версия engine, фактический результат и независимый критерий: значения/типы, страницы, пиксели/размеры, literal occurrences или визуальный эталон. Ошибка reader/QA, native import incompatibility, ожидаемая потеря формата и ошибка AIO разбираются отдельно.
