# A.I.O — отдельный патч завершения конвертера

9 ноября 2026 года, московская дата. Основа: `b7216d1210489a5fd1eadb21daf2e3b3849e30f4`, актуальная накопительная ветка PR #83. Ветка нового патча: `patch/converter-completion-20261109`. Предыдущий PR #103 уже включён в основу; его изменения повторно не применялись. MAIN и Release не изменяются.

Этот документ описывает новый слой исправлений. Точный финальный commit, Windows/Ubuntu CI, итоговые количества тестов и хеши артефактов фиксируются в прилагаемом завершающем протоколе. Успех source-тестов или наличие выходного файла не означает полной визуальной эквивалентности всех форматов.

## Проверяемая граница готовности

Рабочий поддержанный маршрут должен: сохранить исходник; явно сообщить о доступности и ограничениях; выполнить преобразование с отменой и контролем места; проверить применимые свойства результата; сохранить все необходимые файлы-компаньоны; подтвердить чтение сохранённой копии. При подтверждённой потере не должен выдавать неверный результат как готовый.

Нативные несовместимости LibreOffice и неподтверждённые модели не объявляются исправленными добавлением расширения в список. Полноценное совпадение всех шрифтов, расположения объектов, формул и макросов не сертифицировано.

## Изменения этого патча

### C01. Одинаковый бюджет импорта в одиночной и массовой подготовке

При 32 и более источниках код молча сокращал обычный тайм-аут каждого native import до 15 секунд вместо настроенных 120. Удалён этот специальный предел; отмена, прогресс, явный пользовательский бюджет и блокировка конфликтующих действий сохранены. Регрессия моделирует корректный 20-секундный импорт и падает на базе.

Два точных XHTML из прежней Windows-диагностики сохранены без изменения байтов. Нативный API-контроль использует 32 копии этих источников с разными именами, затем независимо читает два PDF. Отдельный Qt/WebEngine-контроль проводит все 32 файла через настоящий массовый интерфейс, native PDF, сохранение папки и чтение всех PDF. Содержимое проверяется по маркерам уровней, `00123`, `12345678901234567` и `Москва`. Это не полный исторический корпус 178/200 файлов.

### C02. Специализированные ODM/OTM/ORP требуют подтверждённой модели

Обобщённый LOK TEXT объединяет обычный Writer, Writer/Web и GlobalDocument. Ранее такая группа могла ошибочно разрешить master-экспорт обычному HTML. Теперь недостаточно расширения или объединения типов: специализированному экспортёру нужна реально загруженная UNO-модель либо ранее подтверждённый native exporter. Подтверждённые native GlobalDocument-маршруты сохраняются.

Четыре исходных ODM/OTM из диагностического ZIP не стали положительными примерами master-документов: на локальной сборке их импорт не подтверждён. Реальная положительная ORP/Base ReportDefinition по-прежнему нужна для закрытия M14.

### C03. Физический масштаб PCX и контроль геометрии старых растров

PCX с заголовком 100 DPI превращался в PNG около 96 DPI; mandatory-проверка не имела исходного профиля и принимала результат. Теперь оба DPI поля сохраняются в QImage, а масштаб независимо проверяется у поддержанных PNG/APNG/TIFF/BMP/JPEG. Учитывается представительное округление плотности самого формата. Для форматов без подтверждённого физического масштаба потеря явно перечисляется.

TGA с подтверждённой бинарной структурой и согласующимся Qt-декодером получает растровый маршрут без A4-холста Draw. PhotoCD читается ограниченным штатным Pillow Base decoder: **768×512 либо поворот 90/270 градусов**. Это не поддержка всех уровней 4Base/16Base и выше. Неизвестная ориентация и усечённый Base не объявляются корректными.

Предупреждение `MEDIA_PHOTOCD_BASE_ONLY` видно пользователю даже при скрытом technical resultChecks/отсутствии quality-summary. Оно сообщает границы декодирования; наличие и потеря более высокого слоя не выдумываются.

Для actual importer `PCT - Mac Pict` добавлен узкий native GraphicExportFilter-путь по подтверждённой фигуре: известный QuickDraw frame, ровно одна страница и один не обрезанный/не повёрнутый/не деформированный graphic. Обычный Draw сохраняет страничную семантику. Windows-проверка этого пути обязательна; Linux CLI без loaded-model receipt не получает обход прежней защиты всех страниц.

### C04. Единая политика качества GIF

Прямой Qt-путь отказывался молча уменьшать палитру, а native GIF мог незаметно превратить сотни цветов в 256. Native-страницы теперь сначала экспортируются в PNG, после чего применяется тот же точный GIF encoder. Более 256 цветов, частичная прозрачность и неподтверждённый профиль не превращаются в незаметную потерю.

Обрабатываются все страницы до публикации набора; манифест страниц обновляется на фактические GIF. Receipt относится к кодированию **native PNG raster**, а не доказывает правильность предшествующего импорта/рендера LibreOffice. Отдельная регрессия сохраняет допустимую потерю страниц при static JPEG/BMP и проверяет DPI именно представленной страницы.

### C05. DBF: честная кодировка, заголовки, Memo и внешнее чтение

Проверяется полная строгая представимость фактических текстов, заголовков и отображаемых значений, а не только первые строки или locale машины. Для подтверждённого немемо-листа используется native Windows-1251, явно объявленный LDID C9 и matching CPG; остальные Unicode/Memo-сценарии сохраняют UTF-8 с CPG. Байты значений не перекодируются после LibreOffice; изменяется только подтверждённый байт объявления кодировки до построения окончательного манифеста.

Unicode за пределами CP1251 не заменяется вопросами. Контроль охватывает строки после первого chunk, формулы/ошибки, mixed columns, Memo, названия и mapping-побочные файлы, ZIP/Folder-save. Неподдержанная неоднозначность даёт явный отказ, а не фиктивное подтверждение схемы.

Первый Windows CI выявил новый побочный эффект LDID writer: Windows CRT мог удалить завершающий байт DBF `0x1A` уже при открытии через `os.open` в текстовом режиме. Оба native пути теперь явно используют `O_BINARY`. Исходная строгая проверка EOF сохранена; отдельный тест сравнивает все байты, разрешая изменение только LDID. Это исправление runtime, а не ослабление теста.

**Ограничение движка:** на локальной LibreOfficeDev 26.8 автоматическое открытие игнорировало и UTF-8 CPG, и CP1251 LDID. Одними метаданными это не исправить. Проверяются независимые физические DBF/DBT, explicit-encoding LibreOffice и доступный внешний GDAL/OGR; default-LO результат записывается отдельно. Предупреждение пользователю требует явного выбора кодировки там, где auto detection её игнорирует. Windows-прогон обязан реально выполнить UNO schema/Memo cases (`--require-uno`).

Дополнительный отрицательный контроль: CSV с отрицательным десятичным значением выявил native DBF width/export failure. В сохранённом прогоне задача закончилась явным `ENGINE_FAILED`, без результата/выходов, исходник не изменился. Это **безопасный отказ, а не успешная конвертация и не исправленный exporter**. В архиве сохранены `negative-decimal.csv`, статус и исходная диагностика; положительные кодировочные CSV-контроли не используются как доказательство этого случая.

### C06. Компоновка интерфейса и фактическая область проверки качества

Убрана принудительная минимальная высота 640px каждой панели с автоматическим ростом всего конвертера. Desktop-компоновка использует доступную высоту, списки имеют собственную прокрутку; компактная компоновка оставляет достаточно места кнопкам. Фильтр, добавление и корзина проверяются на пересечение/выход за панель, кликабельность и контраст состояний. Слот кнопки конвертации не сдвигается после сохранения или отмены диалога.

По уточнённому требованию владельца счётчик, фильтр, добавление файлов и корзина располагаются в **одной строке**, с общим центром по вертикали. Добавление видно и при пустом списке, счётчик имеет резерв ширины; изменение числа файлов не переносит кнопки вниз. В узкой панели используются доступные подписанные иконки. Устранено отдельное mobile-правило, растягивавшее всю страницу: внешний document не должен получать прокрутку; в физически маленьком viewport доступ к длинным спискам остаётся через ограниченную рабочую область.

Windows дополнительно выявил несовпадение шрифта родителя, в котором вычислялся резерв `ch`, и шрифта числа: `10000/10000` имело ширину 105,328 px при слоте 88,938 px. Резерв и число теперь используют одинаковые family/17px/700/tabular-nums; кнопки имеют свой явный шрифт 13px. Проверка полного счётчика не удалена и не заменена обрезанием. Во всех размерах сохраняются проверки полных desktop-подписей, центра строки и отсутствия внешней прокрутки.

В «Состоянии» видны подтверждённые свойства и проверки, статус сохранённой копии/readback, ограничения формата и непроверенные свойства. Предупреждения не скрываются quality-summary. «Готово» не становится сертификатом расположения, шрифтов и визуального совпадения.

Используются реальный Qt/WebEngine, светлая/тёмная тема, desktop/narrow viewport, browser zoom и отдельный Qt scale 150%. Масштаб Qt не выдаётся за проверку всех физических мониторов и Windows DPI-конфигураций.

### C07. Снижение накладных расходов измерения места

Свежие полные обходы перед допуском, native-экспортом, упаковкой и публикацией сохранены. TTL-кеша размеров нет. Обычные файлы суммируются при scandir, в стеке остаются только каталоги; перед спуском повторно проверяется их тип. Сохранены бюджеты глубины/числа записей, отмена, отказ от симлинков/reparse и учёт чужих файлов.

Сопоставимый локальный контроль: 4 000 существующих файлов, 5 чередующихся A/B-пар. Пик Python-аллокаций обхода 1 259 198 → 2 341 байт; тёплый обход 5,750 → 5,132 мс; синтетический batch 3 221,538 → 3 087,789 мс. В обоих вариантах 406 полных обходов с admission. Это не native RSS и не холодный диск/SMB.

100 настоящих CLI-задач сохранили одинаковые проверенные PDF/TXT и исходные хеши. Медиана 2 945,482 → 2 933,380 мс различается примерно на 0,4% при перекрывающихся диапазонах: **ускорение LibreOffice не заявляется; FT4-07 не закрыт**. CLI-маршруты с доказанными sheet/page safeguards не заменялись ради цифры скорости.

### C08. Проверка обычного упакованного desktop

Прежний frozen smoke проверял структурные workers и отсутствие удалённых модулей, но не GUI/native conversion. Новый QA driver запускает обычный EXE без нового product QA switch, подключается к локальному Qt DevTools, загружает контрольный RTF через интерфейс, преобразует его в PDF и независимо читает маркер. В frozen-режиме внешние engine overrides удалены, наличие bundled LibreOffice обязательно. Сохраняется screenshot; Windows получает обычный WM_CLOSE и проверку завершения.

Это portable packaged desktop, **не установка пользовательского installer**, не реальные действия в системном диалоге и не тест внешнего диска. Source control не выдаётся за frozen evidence. Новые native/GUI-проверки обязательны для Windows gate; пропущенный/упавший шаг не позволяет зелёному aggregate скрыть отсутствие проверки. Сохранён прежний контракт без upload-artifact/cache: отчёты находятся в журнале CI, ключевые screenshots — в ограниченных Base64 chunks с SHA-256 для восстановления в архив передачи. EXE и Release не публикуются.

## Исходная регрессия и воспроизводимость

На чистой основе `b7216d1`: полный локальный source suite — **1668 обнаружено, 1663 PASS, 5 Windows-only skips, 0 ошибок/падений**, 76,16 с. Отдельные новые регрессии воспроизводятся на базе и проходят после исправления. Полный итоговый suite/Windows evidence прилагаются отдельно после фиксации финального кода.

Локальный suite первого кандидата: **1701 обнаружено, 1696 PASS, 5 Windows-only skips, 0 ошибок/падений**, 74,35 с. В нём добавлены **33 новых метода**, без суммирования повторных targeted suites. Первый общий прогон обнаружил устаревшую положительную DBF-заглушку без валидного заголовка и нарушение прежнего CI no-artifact-контракта. Заглушка заменена минимальным корректным DBF с прежними quota assertions; upload-artifact удалён. Runtime validation и прежний dependency/CI контракт не ослаблены.

Первый CI `42534118291`, commit `fd86ffe13d705a0953c2ca818e2c6e49f194c93c`: Ubuntu PASS; Windows обнаружил неверный canvas PCT при прежней сериализации GraphicProvider и потерю EOF из-за Windows CRT O_TEXT. Новые проверки сработали и заблокировали package/frozen stage. Исправления используют shape GraphicExportFilter с typed pixel dimensions и двоичный файловый дескриптор. Этот неуспешный запуск сохранён отдельно; финальный статус относится только к последующему проверенному SHA из завершающего протокола.

После этих исправлений и уточнения единого ряда кнопок: **1702 обнаружено, 1697 PASS, 5 Windows-only skips, 0 ошибок/падений**, 76,40 с. Всего **34 новых метода** относительно основы. Хеши исходников не менялись во время этого полного прогона. Обновлённый Qt GUI: 31 проверенный сценарий, включая 32/32 XHTML→PDF/Folder-save, и 27 сценариев при фактическом Qt DPR 1,5. Проверены центры строки, резерв счётчика 4096/4096 и 10000/10000, стабильность состояния, клики фильтра, реальный переход Tab и отсутствие программного сдвига body. Старые UI-протоколы с двухрядной шапкой являются историей; актуальны `ui-header-row-report` и завершающий Windows-протокол.

Во втором Windows CI `42536458547` PICT, DBF с обязательной UNO-схемой и bulk routes прошли; source suite Windows: 1695 PASS + 7 N/A, Ubuntu: 1697 PASS + 5 N/A. Новый UI driver остановился именно на переполнении резерва шрифта счётчика. После точечной коррекции шрифта полный локальный suite снова прошёл: **1702/1697 PASS +5 N/A, 77,50 с**. Дополнительно выполнены 27 real-Qt сценариев при обычном DPR и 27 при Qt DPR 1,5, с native PNG/save. Полный 32-file local native batch повторно не суммируется и не выдаётся за новый прогон: свежий Windows CI проверяет его на окончательном SHA. Baseline с новым font-инвариантом падает, коррекция проходит; исходники между freeze и итогом suite не менялись.

Локальный native DBF: 9 PASS, один явный NOT_RUN для Windows UNO literal/mixed mapping; свои CP1251 DBF и UTF-8 DBT прошли обратное преобразование в A.I.O. Local media: 10 PASS, один PASS_SAFE_REFUSAL, 4 BLOCKED без Linux PyUNO; обязательный Windows driver не принимает BLOCKED как успех. Source Qt bulk: 32/32 native PDF и Folder-save; отдельный Qt scale 150%: 17 проверенных сценариев.

Нативная Linux-среда: LibreOfficeDev 26.8.0.0.alpha0, Python 3.12, Qt offscreen. Windows CI использует pinned LibreOffice 26.8.2.2 и Python 3.11 с hash-locked dependencies/SBOM/SCA. Результаты платформ и readback scopes не смешиваются.

Google Docs из приложенного списка вернул HTTP 401; доступ к полной закрытой истории не выдумывался. Использованы предоставленный текст и доступные диагностические ветки. Точные 22 источника имеют отдельный provenance/SHA; 10 namespace-only OOXML pairs исследованы как прежняя диагностика, а не разрешение переписывать исходники в production.

Открыть новый PR/ветку поверх указанной накопительной основы. Патч не применять поверх уже содержащего его коммита и не переносить на историческую MAIN без зависимостей.
