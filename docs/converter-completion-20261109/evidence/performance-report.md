# Производительность: новый completion-патч

Изолированно исправлен измеренный bottleneck `legacy_storage_budget.measured_bytes`: обычные файлы теперь суммируются непосредственно при обходе. В памяти откладываются только каталоги; каждый каталог повторно проверяется через `lstat` перед спуском. Полные свежие обходы перед admission, native-экспортом, после него, при упаковке и перед публикацией сохранены. TTL-кеша размеров и сокращения числа проверок нет.

Для 4000 существующих маленьких чужих/непроверенных файлов, 5 чередующихся A/B-пар, сравнение с компонентом из `b7216d1210489a5fd1eadb21daf2e3b3849e30f4`:

| Измерение | Baseline, медиана | Патч, медиана | Вывод |
| --- | ---: | ---: | --- |
| Полный тёплый обход 4000 файлов | 5,750 мс | 5,132 мс | Время ниже на 10,7% |
| Пик Python-аллокаций одного обхода (`tracemalloc`) | 1 259 198 байт | 2 341 байт | Ниже на 99,8%; это не native RSS |
| 100 входов × 2 target, синтетическая запись + ZIP + проверки | 3 221,538 мс | 3 087,789 мс | Время ниже на 4,2%; 406 полных обходов с обеих сторон |
| 5 входов × 2 target, настоящий CLI LO | 2 945,482 мс | 2 933,380 мс | Разница 0,4% внутри шума; ускорение native не заявляется |

Настоящая часть: 5 A/B-пар, 100 успешных CLI-задач суммарно, в каждом запуске 32 полных обхода. Исходники неизменны. Каждый PDF имеет ровно одну страницу, все 12 контрольных строк присутствуют; TXT и извлечённый PDF-текст совпадают с исходными строками. Нормализованные результаты всех A/B-запусков одинаковы. Синтетические ZIP payload digests одинаковы во всех 10 запусках. Прежние 405 обходов не стали 406 из-за патча: новый benchmark включает admission `begin()`, старый замер начинался после него.

Нативные диапазоны полных batch-времён перекрываются: baseline 2812,982–3108,289 мс; патч 2837,947–3015,095 мс. Медиана `cliProcessMs` на 10 задач: 2614 против 2623 мс. Следовательно, FT4-07 (165 исторических CLI-задач / 55,6% времени) **не закрыт** этим исправлением. Смена native backend или переиспользование CLI-профиля не выполнялись: имеющиеся CLI-пути включают проверенные all-sheet snapshot/export/recovery контракты; перенос требует отдельного сопоставимого native качества, а не подмены маршрута ради скорости.

Ограничения G05: Linux, LibreOfficeDev 26.8.0.0.alpha0, тёплые filesystem metadata и новый приватный профиль для каждого native вызова. Старая копия меняется только для scanner-компонента, оставшийся checkout одинаков с обеих сторон. Не измерены установленный Windows GUI, холодный диск/SMB, historical FULLTEST 200/5723, конкурентные экземпляры и native peak RSS. `nativeBoundaryMs`, `cliProcessMs`, `fullScanMs` частично перекрываются из-за quota-monitoring во время native-вызова; их нельзя складывать.

Регрессии: 62/62 PASS, без skips: legacy quota, archive readback, durable recovery, capacity и direct engine. Новые проверки покрывают точную границу количества/глубины, рост существующего файла и новый чужой каталог, отмену посреди плоского каталога, замену каталога симлинком перед спуском. Существующие real-process quota-growth/cancellation и symlink/reparse-отказы проходят.

Воспроизведение:

```bash
/workspace/scratch/aio-inspection-20261108/venv/bin/python tools/qa/completion_performance_native.py \
  --output /new/empty/performance-directory \
  --executable /opt/codex/runtimes/codex-primary-runtime/dependencies/bin/override/soffice \
  --repeats 5 --fixture-inputs 100 --native-repeats 5 --native-inputs 5
```

Первичные данные: `matched-final/evidence.json`. Лог: `regression-tests.log`. Хеши: `manifest.json`. Предварительные `matched-scan-v1`/`matched-native-v1` сохранены отдельно; основной вывод использует чистый последовательный `matched-final`.
