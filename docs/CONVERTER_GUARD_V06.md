# Converter Guard v0.6 — отбор до конвертации

Патч для интеграционной ветки PR #9 `feature/aio-guard-v04-on-main-20261019`.
База: `fc0a673edbb06b79728c4b61c2becf3399b4f486`, tree
`cdf784856048a7aa20b643a73fa3131ca001908f`. Guard v0.5 уже включён в эту базу.
Отдельные старые PR Guard повторно переносить не нужно. MAIN, workflows,
установщики и графические ресурсы этим патчем не меняются.

## Что исправлено

В v0.5 тип определялся по первому удачному экспорту. Поэтому первый BMP → DBF
мог зря запустить LibreOffice, а «Выбрать всё» ещё не имело доказательств для
отбора. Теперь сначала проверяются исходники, затем формируется автоматический
план. Все исключения отмечаются до постановки экспортов в очередь, даже если
недоступный формат стоит первым.

1. После добавления исходники один раз потоково сохраняются в Guard.
2. Guard открывает каждый файл через API установленного LibreOffice, узнаёт
   тип native-документа и сопоставляет его с реестром экспорта этой установки.
   Выходные документы при этом не создаются.
3. «Выбрать всё» выбирает объединение подтверждённых форматов для выбранных
   файлов. При запуске Guard отдельно оставляет только подтверждённые пары
   каждого файла: выбранный для таблицы DBF не запускается для соседнего BMP.
4. Неопределённый тип, недоступное API или тайм-аут проверки не означают
   «LibreOffice не поддерживает файл». Такие направления не добавляются
   автоматически, но сохраняют возможность явной ручной попытки.

При выборе одного BMP DBF не предлагается. При выборе BMP и XLSX DBF доступен
для XLSX; BMP → DBF будет пропущен до экспорта. Подтверждение означает наличие
native-механизма, а не гарантию успешного преобразования любого содержимого.

## Native-граница

Используется LibreOfficeKit C API из **того же установленного LibreOffice**:
`libreofficekit_hook_2` → `documentLoadWithOptions` → `getDocumentType`.
Никаких `saveAs`, рендеринга страниц или скрытых пробных преобразований в этом
пути нет. Никакого другого конвертера, pyuno, своего парсера документов или
новой зависимости для пользователя не добавлено.

Библиотека загружается через ctypes только в собственном дочернем процессе.
В UI/HTTP-процесс она не загружается. Frozen launcher обрабатывает служебный
аргумент до импорта Qt. Проверяются размеры используемых префиксов C ABI.
Импорт получает отдельный профиль с запрещёнными макросами, оригинал открывается
для чтения. Родитель владеет деревом процесса, отменяет его и удаляет профиль.
Результат ребёнка — небольшой атомарно записанный JSON. После него ребёнок
выходит через `os._exit`: глобальное завершение LibreOfficeKit может ждать
собственный цикл событий, а все native-ресурсы здесь принадлежат только ребёнку.

Native-kind TEXT сопоставляется с объединением Text/Web/Global Document:
укрупнённый API не позволяет надёжно различить эти модели. Это консервативное
расширение может допустить дополнительную попытку; оно не даёт права объявлять
неподдерживаемым Web/Master-документ. Другие поддержанные виды: Calc, Impress,
Draw. Прочие виды остаются `undetermined`, а не блокируются.
Это небольшой мост от native-вида к UNO service, **не таблица расширений**.

Источник ABI: [официальные заголовки LibreOfficeKit](https://github.com/LibreOffice/core/tree/master/include/LibreOfficeKit).

## HTTP/JS контракт

Схема остаётся v3, старый прямой `/jobs` API сохранён для совместимости.
Актуальная оболочка использует новый путь:

| Операция | Результат |
| --- | --- |
| `POST /prepare {files}` | Задание загрузки без форматов и экспортов |
| `POST /input?job=…&file=…` | Исходные байты, потоковая запись |
| `POST /preflight {jobId}` | Завершённая проверка и per-file матрица форматов |
| `POST /prepare-update {jobId,files}` | Сохраняет неизменённые исходники и доказательства, добавляет новые |
| `POST /start {jobId,fileIds,formats,onlyVerified}` | Выбор ранее подготовленных файлов и предварительное исключение пар |

`/inspect` остаётся дешёвой подсказкой по метаданным. Его одного недостаточно
для подтверждённого «Выбрать всё». В новом ответе `verifiedFileIds` содержит
только подтверждённые файлы; `selectableFileIds` также допускает неопределённые
для ручной попытки. Доказательства никогда не принимаются из metadata браузера.
Изменение native-реестра инвалидирует доказательство по fingerprint.

| Метрика/состояние | Значение |
| --- | --- |
| `preflightChecks` | Число native-проверок исходников, отдельно от экспортов |
| `attempted` | Число фактически запущенных экспортов |
| `skipped`, stage `preflight` | Пара исключена до экспорта, `libreOfficeStarted=false` |
| `PREFLIGHT_ROUTE_UNDETERMINED` | Автоматический план не включает неизвестную пару; ручная попытка доступна |
| `prepared` | Проверка закончена; экспорт ещё не поставлен в очередь |

Счётчик `libreOfficeStarted` у цели относится к **экспорту**, а не к импорту
проверки. UI теперь пишет «Экспортов LibreOffice», не скрывая проверку в этом
счётчике. Весь отчёт с пропусками остаётся в «Проблемах» и JSON внутри ZIP.
Чистый пропуск не превращается в зелёную галочку сохранённого результата.

## Нагрузка и жизненный цикл

- Один последовательный preflight на Guard; массового параллельного открытия
  документов нет. Оболочка без файлов не запускает native-проверку.
- Один исходник импортируется один раз на подготовленную сессию. Смена форматов
  и отметок выбора повторно не загружает байты и не запускает импорт. При
  добавлении/удалении файлов сохраняются доказательства оставшихся исходников.
- Импорт может быть дорогим для сложного документа. Это осознанная цена отбора
  **до** экспорта; ускорение одиночной конвертации не заявляется. При массовом
  выборе избегаются запуски для невозможных пар.
- `preflight_timeout=15` секунд — мягкий предел одной проверки. Его превышение
  даёт неизвестный результат, а не запрет и не обрезку документа. Время самой
  конвертации, размер файла и число файлов по умолчанию по-прежнему не ограничены.
- Установленное приложение/CLI, недостающая C API библиотека и несовместимая
  разрядность могут оставить проверку неопределённой. Ручной путь сохраняется.
- Сброс прогресса сохраняет подготовленные исходники; закрытие модуля, отмена
  проверки, ошибка загрузки/обновления, подтверждённое сохранение освобождают
  принадлежащее задание. Действуют прежние TTL и учёт занятого диска.
- Подтверждённая preflight-модель не запускает дополнительный stdout observer
  при экспорте. Для старого API/неизвестной модели сохранено наблюдение v0.5.
- ETag/304, ZIP64, частичные результаты и повтор сохранения сохранены.

Native-сценарий использует настоящий HTTP, настоящий JS bridge, установленный
LibreOffice и три синтетических исходника: BMP, DOCX с расширением BMP, XLSX.
Проверяет отсутствие экспортов до preflight, кэш, исключение неподходящего
первого формата, ZIP, отмену сохранения, очистку и неизменность исходников.
PDF дополнительно сравнивается с прямым LibreOffice: число страниц, извлечённый
текст и байты встроенных изображений. Это узкая регрессия, не сканер качества.
Прямые контрольные попытки исключений с тайм-аутом помечаются
`inconclusive`; они не выдаются за доказательство невозможности конвертации.

Два неизменённых master PNG >1 MiB недоступны в локальном checkout через
использованный файловый коннектор. Две связанные проверки бренда локально
помечены NOT_RUN; сами тесты не ослаблены, исходные Git blobs и производные
иконки не меняются. Полный checkout у интегратора должен пройти эти проверки.

Windows/NIKITA, библиотека C API в штатном Windows LibreOffice, frozen EXE,
настоящий Qt Save и Setup — **NOT_RUN**. Старый owner workflow закреплён на
