## Особенно проверено

- PDF: существующий private `registrymodifications.xcu` сохраняется; новый профиль получает security и PDF defaults. В обычном экспортном рецепте и embedded UNO helper используются одинаковые два boolean-параметра. UNO сохраняет тип `[]com.sun.star.beans.PropertyValue` внутри `Any`, отвергает произвольные свойства и целочисленные подмены boolean. Не-PDF рецепты остаются прежними.
- Текст: общий allocator сохраняет ограниченный точный поиск. Неудача жадного выбора не считается потерей. Превышение бюджета остаётся incomplete. Host сохраняет нормализацию границ слов, а UNO — существующую нормализацию без пробелов; это различие не замаскировано как проверка вёрстки.
- Legacy: учёт листов опирается на распознанный контейнер, связи OPC/namespace, прямые таблицы ODF, включая скрытые и пустые листы. Вложенные sidecars не заменяют верхнеуровневые результаты. Неизвестные/бинарные inventories явно не проверены. Storage-control exceptions не должны проглатываться XML/source-contract парсерами; целевой regression PASS.
- Upload/quotas: эксклюзивная коллизия и подмена stage не дают публикации/удаления чужого файла; незавершённый scan не публикует частичный byte total как точный.

## Границы этого review

Полный suite, LibreOffice/native-прогоны и Windows не запускались этим reviewer. Их результаты должен приложить основной агент. Qt ICC/DPI-пути просмотрены статически; их отдельные conversion-тесты здесь повторно не запускались.

PDF defaults предотвращают дополнительное JPEG-сжатие/downsampling, но не подтверждают эквивалентность исходного документа. CSV-контракт относится к явно распознаваемым чувствительным литералам и поддерживаемым Excel targets. Legacy receipt подтверждает количество листов, не их значения/вёрстку. HTML visitor проверяет контейнеры распознаваемых растров; существование шрифтов и прочих неизвестных ресурсов не доказывает их декодируемость.
