# Converter Guard v0.1 — первый интеграционный патч

Основа: `migration/ui-excel-clean-foundation-20261019` @ `74adcde69c5430e29fcccf9aa9eaa8efad7b9cd0`.
Этот патч предназначен для отдельного review поверх переноса UI/Excel. Он не меняет `main`, установщик, workflows или исходный All-in-One-. ADVANCE не подключается.

## Подключённый сценарий

Существующий интерфейс A.I.O передаёт задание в Guard. Guard сохраняет оригинальные байты во временный файл, запускает отдельный процесс LibreOffice с отдельным профилем, получает PDF и предоставляет результат для сохранения. Excel не импортирует Guard и сохраняет свой прежний механизм объединения.

| Семейство LibreOffice | Входы первой версии | Выход |
|---|---|---|
| Writer | DOCX, DOC, ODT, RTF | PDF / `writer_pdf_Export` |
| Calc | XLSX, XLS, ODS | PDF / `calc_pdf_Export` |
| Impress | PPTX, PPT, ODP | PDF / `impress_pdf_Export` |

Это покрытие нового адаптера, а не список всех возможностей LibreOffice. HTML, TXT, CSV, картинки, PDF как вход и остальные выходы пока имеют явный статус `INPUT_NOT_CONNECTED` / `OUTPUT_NOT_CONNECTED`. Нет промежуточной реконструкции документа, собственного рендера или обязательного извлечения текста. Доступность маршрута в UI описывает реализованный адаптер; успешный импорт конкретного документа определяет LibreOffice.

PDF использует `UseLosslessCompression=true`, `ReduceImageResolution=false`. Это сохраняет пиксели встроенных изображений в квалифицированных примерах, но может увеличивать размер PDF. Полное сохранение разметки любого документа и одинаковые шрифты на разных машинах не гарантируются.

## Жизненный цикл и нагрузка

- Один рабочий поток, один процесс LibreOffice одновременно. Ошибка/тайм-аут одного файла не прерывает следующие. Отмена останавливает текущий файл и помечает оставшиеся отменёнными; уже готовые результаты можно сохранить.
- Загрузка и выдача результатов идут блоками 64 КиБ. PDF не возвращается в Python `bytes` или браузерный Blob целиком. Для нескольких успехов создаётся ZIP_STORED; повторное сжатие PDF не выполняется. При нехватке квоты для архива остаются отдельные PDF.
- Осмотр списка читает только метаданные и не запускает LibreOffice. Нет анализа содержимого на каждый клик, рендера превью или фонового обхода документов. Проценты задания — число завершённых файлов; промежуточный процент отдельного экспорта LibreOffice неизвестен и остаётся `null`.
- Журнал ограничен 512 событиями. Обычный опрос активного задания не передаёт журнал заново; он доступен при завершении или с `trace=1`. В журнале нет содержимого, имён исходных файлов и абсолютных путей.
- До 100 файлов в задании, до 16 владельцев заданий; отдельный результат не расходует дополнительный слот задания. По умолчанию: вход до 512 МиБ, квота документов/результатов 2 ГиБ, тайм-аут файла 1800 секунд. Настройки находятся в `GuardLimits`, не изменяют качество и не ограничивают число страниц.
- Учёт квоты охватывает зарезервированные входы, готовые PDF и архив. Это не жёсткая ОС-квота: профиль LibreOffice, его служебные файлы и кратковременный рост вывода требуют дополнительного места. Рост ожидаемого PDF проверяется во время работы процесса.
- Готовые результаты сохраняются до явного release/reset/закрытия приложения. TTL 1800 секунд относится к заброшенным заданиям без результата и применяется при следующем обращении, без постоянного таймера. Нельзя удалять несохранённый результат только потому, что пользователь долго не нажимал «Сохранить».
- Сброс и закрытие освобождают только принадлежащие Guard каталоги. Скачивание удерживает файловую аренду до конца потока; отмена диалога сохранения не удаляет результат. При закрытии HTTP-передачи прерываются до ожидания освобождения файлов. Ошибка удаления сохраняет владельца/квоту для повторной очистки.

## Процесс и безопасность

Путь берётся из явного `AIO_LIBREOFFICE`, затем из PATH/типичных расположений. Явный неверный путь не подменяется другой копией. Автоскачивания LibreOffice нет; Python/Qt/UNO-конвертеры и новые движки не добавлены. Обнаружение не выполняет пробную конвертацию при запуске A.I.O.

Команда передаётся списком аргументов с `shell=False`. Guard назначает временный каталог; исходное имя проверяется как один компонент и сохраняется, если файловая система допускает его. Пользователь не задаёт CLI-фильтр или профиль. Макросы отключены через `DisableMacrosExecution=true`; профиль пользователя LibreOffice не используется. POSIX отменяет собственную process group, Windows использует Job Object с kill-on-close. Глобальный `taskkill /IM soffice*` отсутствует. Windows-ветка реализации требует проверки на Windows перед релизом.

Свежий профиль и отключение макросов **не являются ОС-песочницей** и не гарантируют запрет всех файловых/сетевых обращений LibreOffice. Поддерживается `BlockUntrustedReferrerLinks`, но полная изоляция враждебного активного содержимого остаётся отдельным условием продуктового релиза. Проверки безопасности должны учитывать сохранность документа: blanket `DisableActiveContent=true` в квалифицированном LibreOffice скрывал OMML-формулу. Эта настройка удалена до публикации, а формула включена в нативную регрессионную проверку.

Loopback API проверяет точный Host/Origin и токен сеанса. Ссылка результата содержит случайный bearer ticket, привязанный к владельцу, и не принимает файловый путь. Она используется для обычного download, который не умеет добавлять X-AIO-Token. Native-save допускает только текущий origin/порт, Excel Blob и Guard PDF/ZIP tickets. HTTP-загрузка сама по себе не означает успешное сохранение на диск; требуется подтверждение Qt или File System Access API.

Проверка `%PDF-`/`%%EOF` — ограниченная проверка созданного результата, не полный анализ PDF и не подтверждение качества. «Проверить подробнее» в базовой версии честно сообщает, что глубокое сравнение не выполнялось, и показывает журнал этапов.

## HTTP-контракт

Все операции, кроме скачивания по случайному ticket, требуют `X-AIO-Token`. JSON не более 256 КиБ. Токены и содержимое документов не записываются в журналы.

| Операция | Запрос | Ответ/назначение |
|---|---|---|
| Состояние движка | GET `/api/converter/status` | Доступность, покрытие, лимиты, счётчики хранилища |
| Метаданные | POST `/api/converter/inspect` `{files:[{id,name,size}]}` | Возможности интерфейса, без чтения документа |
| Создать | POST `/api/converter/jobs` `{files:[...],formatId:"pdf"}` | `jobId`, состояния `awaiting_upload` |
| Загрузить | POST `/api/converter/input?job=ID&file=FILE_ID` | Исходные байты, `application/octet-stream`, точный Content-Length |
| Запустить | POST `/api/converter/start` `{jobId}` | 202; обработка в рабочем потоке |
| Опросить | GET `/api/converter/jobs?job=ID[&trace=1]` | Файлы, `finished`, результат, коды, факт запуска LibreOffice |
| Отменить | POST `/api/converter/cancel` `{jobId}` | Отмена своего процесса/очереди |
| Скачать | GET `/api/converter/result?ticket=...` | Поток PDF/ZIP; результат удерживается для повторного сохранения |
| Освободить | POST `/api/converter/release` `{jobId}` | Отмена при необходимости, удаление после завершения I/O |

Состояния файла: `awaiting_upload`, `queued`, `converting`, `ready`, `error`, `cancelled`. Ошибка содержит `code`, `error`, `stage`; отчёт файла и журнал фиксируют `libreOfficeStarted`. Нет объявления файла повреждённым только потому, что движок отсутствует или маршрут ещё не подключён.

## Проверки и воспроизведение

Обычные проверки требуют только существующего `openpyxl` и Node:

```bash
python -m unittest discover -s tests -v
node --test tests/test_converter_guard_bridge.cjs
python -m compileall -q app_backend tools/qa
node --check src/converter-bridge.js
```

Opt-in DOM + реальный HTTP (пакет linkedom используется только в QA):

```bash
AIO_DOM_MODULE=/absolute/path/to/existing/linkedom python -m unittest discover -s tests -p 'test_converter_guard_dom.py' -v
```

Нативный синтетический smoke (только QA: python-docx, python-pptx, Pillow, pypdf; `openpyxl` уже используется приложением):

```bash
AIO_LIBREOFFICE=/absolute/path/to/soffice python tools/qa/guard_native_smoke.py --work /absolute/path/to/new-qa-directory
```

Создаются собственные синтетические документы, пользовательский корпус не используется. Проверяются все десять расширений, два листа/слайда, OMML-формула, сноска, поле FILENAME, таблица, точные пиксели встроенного PNG, неизменность исходников и реальный DOCX 23 103 397 байт. Пустой первый файл не мешает остальным. Контрольный DOCX экспортируется также прямой CLI-командой, вне владельца заданий Guard.

Локальная проверка: 58 Python tests PASS (включая opt-in DOM/HTTP), 10 Node tests PASS. Сводка: `CONVERTER_GUARD_VALIDATION_2026-10-19.json`; нативные результаты: `CONVERTER_GUARD_NATIVE_EVIDENCE_2026-10-19.json`. Среда — Linux, LibreOfficeDev 26.8.0.0.alpha0, Python 3.12; это не обещание скорости на другом ПК. Представительные PDF Writer/Calc/Impress и большой DOCX дополнительно просмотрены через Poppler. Эталонный корпус всех документов, Windows Job Object/Qt-диалог, установленный Windows GUI, сборка и упаковка — **NOT_RUN**. NIKITA не использовался.

Существующий source CI запускает Excel и shell contracts. Выделенные Guard/Node/native команды выше необходимо учитывать отдельно; зелёный старый CI не означает, что выполнена вся квалификация этого патча. Workflows в этом патче не изменяются.

Имена: допустимые длинные кириллические имена не отклоняются по UTF-8-байтам. Исходное имя временной копии сохраняется для полей FILENAME; если имя недопустимо для ОС хоста, используется алиас с предупреждением SOURCE_NAME_NORMALIZED.
